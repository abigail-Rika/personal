# ROI 弹性建模必须先锁定同口径分子分母

## 原则

**先锁口径，再算杠杆。**

任何 ROI / CPL / 析出率弹性模型，本质都在回答：

```text
新单 leads 成本 = 投放成本 / (现状 leads + 新增 leads)
```

这里最容易错的不是公式，而是口径：

- 投放成本是直投单渠道，还是全公司获客成本？
- 现状 leads 是否只包含新投放，还是也包含召回？
- 新增 leads 作用的用户池是否和现状 leads 同渠道、同人群？
- 用户池是否已经扣掉已析出的用户？
- 月度池、周活池、当日触达池是否混在一起？

只要任一口径不一致，杠杆比就会被高估或低估。

## 建模 Checklist

1. **先定成本口径**：这笔成本来自哪个渠道、哪个周期、是否包含其他获客方式。
2. **再定 L0 口径**：现状 leads 分母必须和成本口径一致，也要和 AI 新增 leads 的作用范围一致。
3. **拆出真实可影响池**：  
   `真实可影响池 = 名义用户池 - 已析出用户 - 当期不可触达 / 不活跃用户`
4. **区分漏斗环节指标**：触达率、加微率、首诊率、体验课购买率、leads 析出率不能互相替代。
5. **最后才算杠杆比**：  
   `杠杆比 = 真实可影响池 / L0`

## 反模式

| 反模式 | 为什么错 |
|--------|---------|
| 用全量用户池直接除以现有 leads | 没扣掉已析出和不活跃用户，会高估 AI 可影响空间 |
| 新增池包含召回，L0 只算新投放 leads | 分子分母人群不一致，会高估杠杆 |
| 把加微率叫成 leads 析出率 | 加微只是过程环节，不一定能进入财务 leads 分母 |
| 月度 ROI 模型里塞周活率但不说明 | 时间周期不一致，结论无法解释 |
| 已有 ROI 计算器时重复手算 ROI | 应先计算前置变量变化，再输入公司口径的计算器 |

## 什么时候需要回溯经验

当分析 AI 销售、CC 召回、端内捞量、投放成本摊薄、ROI 计算器输入项时，回读原始经验，尤其关注这次从“5.9w 名义池”修正到“约 1.5w 真实可影响池”的过程。
