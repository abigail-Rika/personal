# 首次用增长 PRD 规范对现有 PRD 做对照评审

日期: 2026-04-03
角色: 增长策略

## 背景

团队有一份「增长产品 PRD 规范」，核心要求是"五个必须说清楚"：问题和现状、假设、假设支撑、方案（用户视角）、实验方案。用这套规范对已有的「售卖落地页前置弹窗」PRD 做了逐项对照评审，看实际 PRD 和规范之间有多大差距。

## 经过

1. 先扫描 `prd/` 目录下的所有 PRD，发现 3 篇中只有「售卖落地页前置弹窗」是增长实验型需求，适合用这套规范评审（另外两篇分别是 bug 修复和教学示例）
2. 用五项逐条对照，产出一份结构化评审文档（通过 / 建议修改 / 必须修改三级分类）
3. 直接将改进建议应用到 PRD 原文

## 关键收获

1. **实战中最容易缺的两个要素是"一句话假设"和"用户视角描述"**。问题描述和假设支撑通常不会漏（因为写 PRD 时自然会交代背景和数据），但假设往往散落在多处没收敛、用户视角直接跳过进了功能配置。

2. **这两个要素恰恰是增长 PRD 和普通 PRD 的本质差异**：
   - 普通 PRD：问题 → 方案 → 开发
   - 增长 PRD：问题 → **假设（一句话）** → 假设支撑 → **方案（先用户视角再功能视角）** → 实验（含成败标准和止损）
   - 如果缺了假设和用户视角，写出来的本质上还是"需求文档"而不是"实验方案"

3. **修复成本很低**。识别出差距后，补一句话假设 + 几段用户视角描述 + 展开实验方案，15 分钟能搞定。说明不是能力问题而是习惯问题——写的时候没有对照清单检查。
