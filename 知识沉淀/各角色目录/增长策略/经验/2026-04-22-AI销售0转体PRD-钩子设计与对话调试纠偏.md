# AI 销售 0 转体验课 PRD：钩子设计与对话调试的两次纠偏

日期: 2026-04-22
角色: 增长策略 / 产品设计

## 背景

写「AI 销售 0 转体验课」的 PRD，目标是把月均 5w+ 端内未被析出的用户用 AI 销售捞起来转化体验课。PRD 主体写完后做了两件事：① 生成"理想转化链路"的 HTML demo（3 个 case：新客有数据 / 新客无数据 / 断课）；② 用户在过程中提了两次关键纠偏。

## 经过

### 纠偏 1：钩子设计（"知识清单吸引力可能不够"）

PRD 里对「无 APP 数据用户」（典型冷启动场景）我设计的加微钩子是 **"五年级数学白皮书"+"3 题迷你自测"**。结构是：白皮书是主钩子，自测是附加项。

PM 一句话点穿了问题：

> "对于没有很多信息的用户，知识清单会不会吸引力没那么足，已经这个知识清单的形式也不太确定。"

我反思后承认，"五年级白皮书"这种钩子确实有 3 个硬伤：
1. **同质化**：网上免费的"年级考点汇总"很多，无信息差
2. **单向给予**：家长收下 PDF 就完了，没有任何动作 → 漏斗会断在加微即结束
3. **没有"为我"感**：通用 = 不针对我家孩子，警戒值不会降

提出更上层的判断标准：**好钩子应该是双向的** —— 我给你 X，你顺手给我 Y（一段信息 / 一个动作），动作完成时家长就已经进入了下一阶段。

按这个标准重新设计：把"5 分钟 1v1 AI 学情诊断"作为主钩子，白皮书降级为成交后的赠品。改完后整个 Case C 的链路通顺了很多——加微即进入诊断，家长 5 分钟内亲自体验了产品力。

### 纠偏 2：对话 demo "悬浮"

我把 PRD 思路做成了 1466 行的 HTML demo（带微信对话样式、3 个 case 的 tab 切换）。给 PM 看后她的反馈是：

> "我觉得这个里面的对话还是有点悬浮，你可以专门建一个对话模拟的 md 文档吗？我们先用文档调整文案，然后再生成 demo。"

我事后捋了一下，HTML demo 里的对话确实有 5 类典型悬浮病：
1. **AI 太懂事**：每句反馈都太得体（"您观察得真准""嗯嗯明白了"）
2. **家长太配合**：现实中家长经常打断、敷衍、不回复，demo 里成了完美陪练
3. **推销转折太硬**：从聊天到推体验课的衔接（"我们的体验课刚好……"）
4. **价格成交太顺**：家长一问价、AI 一报价、家长就买了，没博弈
5. **专业术语用得太顺**："单位 1""分数除法应用题"家长不一定接得住

更关键的是工作流上的反思——**在 HTML/可视化原型里改文案，会因为"视觉看着挺像那么回事"而把内容糊弄过去**。建立独立的纯文档脚本（`对话模拟.md`），用 `// 待调：` 标注疑点，逐句调整后再生成 demo——这样话术调试和呈现调试解耦，每一层都更聚焦。

## 关键收获

1. **「单向钩子 vs 双向钩子」是漏斗起点设计的核心判断标准**：所有"加微/留资/留电话"等漏斗第一环节，都该用这个框架自检。详见 → `各角色目录/增长策略/洞察/2026-04-22-单向钩子vs双向钩子-漏斗起点设计.md`
2. **AI 生成的销售/服务对话有 5 类反复出现的悬浮病**：review 时应该有标准化 checklist。详见 → `各角色目录/产品设计/技能/2026-05-08-AI对话脚本-主流程极简加阻塞分支模板.md`
3. **对话/话术调试必须先用纯文档、再生成可视化 demo**：可视化呈现会掩盖话术问题，分层迭代更聚焦。详见 → `各角色目录/产品设计/技能/2026-05-08-AI对话脚本-主流程极简加阻塞分支模板.md`
4. **PM 一句话质疑能戳穿一个看起来"完整"的方案**：我自己也对白皮书钩子心虚但没主动暴露——这种"自己心虚但糊弄过去"的方案应该主动标 `// 待调：` 给 PM 看。
