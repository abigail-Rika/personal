# keyfrom 规范优化

> 来源：[Confluence - 251218 keyfrom 规范优化](https://confluence.zhenguanyu.com/pages/viewpage.action?pageId=1003991941)
> 空间：Aries
> 归档时间：2026-03-27

## 背景

keyfrom 携带了从订单维度记录的用户信息，用于分析用户行为及区分用户属性。但由于没有固定命名规范，存在两个问题：

1. **命名混乱**：不同业务、使用者、时期对同一场景命名不一致，看数时历史包袱大
2. **维护成本高**：keyfrom 独立维护在商分侧，和业务、数仓分离，准确性难以校准

目标：梳理可沿用的 keyfrom 规范，统一命名 + 降低维护成本。

## 新规则

完整规则：[用户增长新规则-25.10](https://shimo.zhenguanyu.com/sheets/3al78EpYadjgIgDm/CgxGA/)

### 层级定义

保持前 3 级不变（历史依赖），6～12 级新增：

| 层级 | 定义 | 私域 | 端内 | 转介绍 | 导流 | 品牌 |
|------|------|------|------|--------|------|------|
| 1-5 | 维持不变 | | | | | |
| 6 | 业务线 | siyu | app | ref | daoliu | pinpai |
| 7 | 一级渠道 | qw/kefu/pintuan/... | tab页 | zzfx/yqyl/.../业务形式 | yfd/ybc/.../导流业务 | 具体品牌名称 |
| 8 | 二级渠道 | chuchuang... | 点位 | | | |
| 9 | 三级渠道 | kefu_name/群名... | 更深点位 | | | |
| 10 | 标的物（价格+钩子品） | 0yuan/1yuan/9yuan/29wulihe/x | 同左 | 同左 | 同左 | 同左 |
| 11 | 用户身份 | newUser/trailOverdue/vipOverdue | 同左 | 同左 | 同左 | 同左 |
| 12 | 用户来源（端内） | x | nature/zt | | | |

空值用 `x` 占位。

### 产出流程

- **1-9 级**：
  - 端内：研发填（产品新增点位时提供）
  - 私域/转介绍/导流：业务手动填写
- **10-12 级**：数仓映射时判断填写，部分需反向查询用户订单价格后补充到第 10 级

示例：6 级之后 = `ref-yqyl-app-homeBanner-1yuan-newUser`

## 需求拆分

### 1. 新数据增加层级（服务端）

按上述规则，新增订单在 keyfrom 中追加 6-12 级。

### 2. 历史数据增加层级（数仓）

常用表：
- `aries.dwd_aries_leads_conversion_ha`
- `aries.dwd_aries_leads_conversion_with_proc_ha`
- `aries.dwa_aries_leads_behavior_for_cc_detail_ha`

映射关系：[用户增长历史keyfrom映射-25.10](https://shimo.zhenguanyu.com/sheets/3Dzy5blGa7z1iBxg/bY2fN/)

### 3. keyfrom 后台支持配置到第 11 级（服务端）

后台：https://gaffey.zhenguanyu.com/web/biz/#/put-management/put-management-keyfrom

现只支持到第 4 级，需扩展到 11 级，同一层级新增需校验重复值。
