# AI 销售钩子分类——v2 case 库 15 用户跑通

日期: 2026-05-25
角色: 增长策略

## 背景

AI 销售 0 转体 v1 方案 §3.4.2.1 综述表里，CC 真实 case 那一行的"钩子类型"字段写的是「多样——首通直转 / 加微首诊 / SOP 群发」——用户当场指出这行太笼统：「CC 真实通话这里，钩子类型多样，我可以再给你几个 case，你帮我按照钩子类型展开分类下嘛？」

用户给了 15 个 user_id，按"成单/未成单 × 人工电话/AI 外呼"4 组分类：
- 人工成单 5 个：176885884 / 196876516 / 243046606 / 250837926 / 252636748
- AI 外呼成单 2 个：491625312 / 539450952
- 人工未成单 3 个：154212734 / 152544830 / 159456558
- AI 外呼未成单 5 个：1071946315 / 1086803045 / 865552368 / 845694726 / 764376453

目标：用一手 case 验证 §3.4.2.4 的钩子分类是不是真的能区分成败。

## 经过

### 端到端流程跑通

用更新后的 crm-user-query skill（含 bigdata-mcp-server）：

1. **批量拉通话录音**：`tutor_call_record` SQL → 拿到 73 通历史通话 → 筛 ≥60s + 有 ASR 转写 → 37 通有效长通话
2. **批量下载 ASR 转写**：写了一个 thread pool 并发下载脚本（`/tmp/cc_hooks_analysis/download_and_extract.py`），抽出每通的销售首 8 句话术
3. **拉关键 case 的微信原文**：491625312 / 539450952 两个"AI 外呼成单"case 走 Chrome osascript + single-chat API（base64 chunk 方案，复用 AI工程已有经验），分别拉到 350 / 255 条去重消息
4. **按首接钩子分类**：人工对照每个 case 的开场话术 + 兑现物 + 追问深度 + data note，归出 12 类钩子（A~L）

最终产出在 `v1-初步方案.md §3.4.2.4` 的"v2 case 库扩展"小节。

### 踩到 2 个数据坑

**坑 1：用户标的"AI 外呼成单"实际不是 AI 外呼成单**

把 491625312 / 539450952 的 `tutor_call_record.note` 字段调出来看，入口分别是 APP 自然流（banner）和召回 SOP，转化全部发生在**人工销售微信促单**，不是 AI 外呼。结论：用户给的"AI 外呼成单"标签不能直接对照"AI 外呼未成单"——入口性质完全不同。

写进 §3.4.2.4 的"重要数据修正"提示框，避免后续团队继续按错的对照分析。

**坑 2：把 9 元课错塞到 CC 模式**

为了对照斑马 0 转体，画了一个三方对照表（v1 软硬钩子 / 斑马硬转 / CC 利益型），第一版把 CC 那列的"标的物"写成"9 元课"。用户立刻指出：「CC 有让用户买过 9 元课么？为什么这里标的物会有 9 元课」——查了 CC 经办的实际成单流水，CC 体验链路是「0 元送课 + 直接转正价课」，根本没有 9 元中间档。改回去。

这两个坑的共同根因：**"用户已经告诉我的口语标签" 和 "数据里实际的 note / 流水" 不能等同**。前者是产品口径的概念，后者才是用户做了什么。

### 钩子分类的关键发现

12 类钩子（A 学情挖掘 / B 班主任承接 / C 免费送课 / D 抢购倒计时 / F 价格直推 / F' 保障促单 / G 0 元激活 / H 见面会邀约 / I 老用户升级 / J 退费挽留 / K 学情反馈 / L 领课提醒）按"软硬属性"二次归类后：

| 强度 | 发现 |
|---|---|
| 强 | **7/7 成单 case 全部含软钩子或特殊触发钩子**，没有任何纯硬钩子成单 |
| 强 | **硬钩子单独使用 0/4 成单**（G/L/C/F 全军覆没）——印证 CC 综述行的 "1.4-5% 意向率天花板" |
| 强 | **A 钩子（学情挖掘）成败的差异不在话术、在执行深度**——176885884 ✅ vs 152544830 ❌ vs 154212734 ❌，第一句话术高度同质，差异在追问是否完成 5 轮 + 是否避开价格触发点 |
| 中 | **流量入口决定了适用的钩子组合**——AI 外呼 0 元入口的钩子在 5 个失败 case 里 0 成单，落地页直投 / 自然流 5/5 高 |

### 用户追问引出的新假设

当我说"5min 是钩子核心目标"时，用户追问：「如果用 AI 电话的话，也要服务于这个中间目标吗」——这个问题没有现成数据可答，5min 假设是从人工 case 推出的硬门槛，AI 场景下：
- AI 不会疲惫，可以问更多轮，但用户可能更快失去耐心
- AI 推动用户做"测一道题/留个学情"等动作的能力比人工弱
- 中间目标可能要换成"用户给出 3 条以上信息 / 完成 1 次互动动作"

挂到 §3.4.6 待讨论 + 待验证问题里，没在文档里改掉。

## 关键收获

1. **"按钩子类型展开分类"不是数据需求，是概念拆解需求**——12 类钩子能跑出来的前提是先承认"首接钩子"是个独立维度（独立于流量入口、独立于兑现物）。在 v1 里把这三者笼统说"多样"，等于回避了真正的分析。
2. **15 user 这种小样本，定性分类比定量统计更有价值**——4 条结论里没有一条是"显著性 p<0.05"，全部是"成败 case 在某个执行点完全分叉"。小样本的价值是看反差而不是看比例。
3. **"软硬钩子"二元归类是这次跑出来的最有价值的中间产物**——12 类太细，2 类太粗，但 12 类 → 2 类的映射揭示了"硬钩子单独 0 成单 / 软钩子是底色"这条主结论。这个二元划分后来反向倒推 §3.4.4 整个"两层结构：软硬组合"小节的成立。
4. **用户给的"成单/未成单 × 人工/AI" 4 组分类是错的，但分类本身是对的**——错在 AI 外呼成单组实际不是 AI 外呼成单；对在用这种"反差对"找规律的思路。下次类似分析可以一开始就检查 data note 而不是相信用户的口头标签。
