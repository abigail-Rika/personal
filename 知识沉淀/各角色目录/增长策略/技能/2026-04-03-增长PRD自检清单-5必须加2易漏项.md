# 增长 PRD 自检清单：5 必须 + 2 高漏项

## 适用场景

写任何**增长实验型 PRD**（投放优化、转化漏斗、落地页迭代、AB 实验等）提交前对照过一遍。
约 15 分钟，能把"需求文档"升级为真正的"实验方案"。

> 不适用于：纯 bug 修复、教学示例、UI 重构等非增长实验类需求。

## 核心 checklist：5 必须说清楚

按以下顺序写，每项写完打勾：

- [ ] **1. 问题和现状**
  - 业务现状是什么？数据来源在哪？
  - 在哪个漏斗环节、影响了什么核心指标？
  - 写 PRD 时自然会交代——通常不会漏。

- [ ] **2. 一句话假设** ⚠️ 高漏项
  - 一句话能说出"如果做了 X，会带来 Y"的因果假设吗？
  - 假设是否散落在多个段落里、没有收敛成一句？
  - 自检：能不能把这一句**单独抽出来**贴在 PRD 顶部？

- [ ] **3. 假设支撑**
  - 这个因果假设的依据是什么？数据 / 用研 / 竞品 / 类比项目？
  - 是否区分了"硬支撑"（有数据）和"软支撑"（合理推测）？

- [ ] **4. 方案 · 用户视角** ⚠️ 高漏项
  - 是否**先写用户视角**（用户看到什么、做了什么、感受是什么）再写功能配置？
  - 还是直接跳到了"前端加一个弹窗 / 后端加一个字段"？
  - 自检：拿掉所有功能描述，剩下的用户故事是否仍然完整？

- [ ] **5. 实验方案**
  - 实验组对照组分流逻辑？
  - 成败的判断标准是什么？（核心指标、判定阈值）
  - 止损条件是什么？（什么情况下立即停掉）
  - 实验周期 / 样本量估算？

## 高漏项强调

实战中最容易缺的就是 **第 2 项（一句话假设）** 和 **第 4 项（用户视角描述）**。
原因不是能力问题，是**写作惯性**——
- 不写假设，是因为脑子里"觉得"理所当然，没主动收敛
- 不写用户视角，是因为思维容易从"问题"直接跳到"功能实现"

**修复成本很低**：补一句话假设 + 几段用户视角描述 + 展开实验方案，**15 分钟能搞定**。
但不主动 checklist 自检，就会反复漏。

## 增长 PRD vs 普通 PRD 的本质差异

```
普通 PRD：问题 → 方案 → 开发

增长 PRD：问题 → 【一句话假设】 → 假设支撑 → 【先用户视角再功能视角】 → 实验（含成败标准和止损）
```

**如果缺了一句话假设和用户视角，写出来的本质上还是"需求文档"而不是"实验方案"**。

## 使用方式

1. PRD 初稿写完后，**先停 5 分钟**，对照本清单逐项打勾
2. 任何一项打不出勾，标 `// TODO: 补 XX`，不要硬着头皮提交
3. 易漏项（第 2、4 项）打勾时要更严格——确认能在 PRD 顶部抽出"一句话假设"，再勾上

## 反模式

| 反模式 | 表现 | 修复 |
|--------|------|------|
| 假设散落 | 假设依据写了一大段，但找不出一句完整因果命题 | 把它**提到 PRD 第二节顶部**，加粗 |
| 跳过用户视角 | 直接进"前端 / 后端 / 数据" | 在功能描述前加一节"用户故事"，从用户视角写 |
| 没有止损条件 | 只写"如果转化率 +X% 则推全量"，没写"如果 -Y% 则停" | 实验方案要双向标准 |
| 把这套用在非实验需求 | 给 bug 修复硬套五项 | 区分需求类型，bug / UI 重构走另一套 |
