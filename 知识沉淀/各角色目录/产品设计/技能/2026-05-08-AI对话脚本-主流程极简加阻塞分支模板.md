# AI 对话脚本设计流程：文档调试 + 主流程极简 + 阻塞分支

## 核心思路

写 AI 销售/客服对话脚本时，先解决三个问题：

1. **在哪里调**：先在纯 Markdown 文档里调话术，不要直接在 HTML/原型/微信样式 demo 里改。
2. **怎么拆结构**：不要把所有可能的家长反应都塞进主流程，把脚本拆成两层。
3. **怎么 review**：用悬浮病症清单检查真实感，不要只看话术漂不漂亮。

脚本结构拆成两层：

- **主流程**：假设家长以"最低配合度"回应（陌生电话场景下 1-3 字），AI 一气呵成把核心信息推完
- **阻塞分支**：单独一张表格列出"如果家长突然说 XXX，AI 怎么应对"，覆盖典型疑问/拒绝/质疑

主流程展示"理想顺利情况"——节奏紧、不啰嗦；阻塞分支展示"AI 应急能力"——证明 AI 能接住意外。两层分开，对协作方（PM 评审、研发实现、销售培训）都更友好。

## 完整工作流

```markdown
1. 建对话脚本文档（纯 Markdown）
   - 角色 + 消息分行
   - 用 // 设计意图：xxx 标注关键设计
   - 用 // 待调：xxx 标注疑点
2. 文档里逐句调话术
   - 评审只看内容，不看视觉呈现
3. 按「主流程极简 + 阻塞分支」整理结构
   - 主流程只放最低配合度路径
   - 疑问/拒绝/质疑放阻塞分支表
4. 用悬浮病症清单 review
   - 命中任何一条都重写或加一轮博弈
5. 话术冻结后再生成可视化 demo
   - demo 只负责呈现，不再承载话术调试
```

可视化呈现会掩盖话术问题：微信气泡、头像、时间戳会制造"挺像那么回事"的错觉；在 HTML 里改一句话成本高，也会让评审者把注意力转向卡片、样式、tab，而不是话术本身。

## 文档格式建议

```markdown
**[电话] 19:32 · AI 拨出**

**AI**：您好，请问是李明妈妈吗？……
<!-- 设计意图：钩子是服务承诺而不是物料 -->
<!-- 待调：现实里家长大概率会先问"你怎么知道我电话"，需要应对话术 -->

**妈**：嗯。
<!-- 待调：这里按最低配合度写，经典疑问放阻塞分支 -->
```

一句话独立成行，调起来直接；`// 设计意图` 保留给最终 demo 注解用；`// 待调` 标记 AI 自己心虚的地方，方便 PM 快速纠偏。

## 为什么不直接把疑问写进主流程

写脚本最容易踩的坑是想让对话"既理想又真实"——结果让家长在主流程里既配合又质疑，比如：

> AI：您好，我是 XXX
> 家长：你怎么有我电话？  ❌
> AI：嗯，孩子之前注册过……我是来给您反馈学习情况的，不是推销
> 家长：哦那你说  ❌
> AI：……

这种"配合式质疑"反而更悬浮：

1. **场景失真**：陌生电话里家长真实状态是想尽快挂掉，主动追问长句的概率很低
2. **AI 自言自语感**：AI 自己制造一个疑问然后自己回答，看起来像在练习话术
3. **协作方误读**：研发会以为"必须先答完疑问才能继续"，把分支硬编进主流程
4. **触发"AI 太懂事"病症**：AI 每次都得体回应每个挑衅，反而暴露脚本感

## 主流程的写法

### 原则

| 原则 | 说明 |
|------|------|
| 家长字数极简 | 陌生电话主流程里，家长每次回复控制在 1-3 字（"嗯""行""你加我吧"） |
| AI 不等家长追问 | 不要让 AI 等家长问"是什么"才往下讲，AI 应主动一句话讲完核心钩子 |
| 时长压缩 | 整个电话主流程 ≤ 35 秒，AI 累计说话不超过 3-4 句 |
| 一句一意 | AI 每句话只承担一个动作（身份确认 / 信息来源 / 钩子 / 行动），不要一句话塞 3 件事 |
| 不重复"不是推销" | 主动声明"不是推销"在阻塞分支里用一次就够，主流程里说一次反而欲盖弥彰 |

### 模板

```markdown
### 阶段 ① · AI 电话外呼

> ⚠️ 现实约束：陌生电话里家长通常话很少，主流程假设极简配合即可走完，
>    "经典疑问"放到下面的「阻塞分支」单独展示，作为 AI 应急能力。

`[电话] 19:32 · AI 拨出，接通约 XX 秒`

**AI**：您好，请问是 XX 妈妈吗？我是 XXX 的 X 老师          ← 身份确认

**妈**：嗯                                                ← 极简

**AI**：[一句话讲完信息来源 + 具体钩子 + 行动]              ← 信息来源 + 钩子 + 行动

**妈**：行，你加吧                                         ← 极简

`[系统] 电话时长 XX s · 已发送加微短信`
```

## 阻塞分支的写法

### 原则

| 原则 | 说明 |
|------|------|
| 用表格不用对话 | 阻塞分支是"应急话术库"不是"分支剧本"，用 markdown 表格更清晰 |
| 列高频反应 | 4-6 条覆盖 80% 真实反应即可，不追求穷举 |
| 一行一类 | 同类反应（如各种"不需要"）合并一行，不要展开成多个变体 |
| 应对话术给完整成句 | 每条应对必须能直接被销售/AI 念出来，不是设计意图 |
| 跨场景反应统一指向 | 所有 case 都会出现的反应（如"你是真人吗"）指向文末统一待讨论项 |

### 模板

```markdown
#### 🔀 阻塞分支（按需触发，主流程不展示）

| 家长反应 | AI 应对 |
|---------|---------|
| 「你怎么有我电话？」 | [给信息来源 + 主动声明不是推销，1-2 句完成] |
| 「不需要 / 直接挂」 | [记录 + 后续二次触达策略说明] |
| 「孩子早不学了 / 不上了」 | [给一个低门槛兜底物，让用户带走价值即使不加微] |
| 「你是真人还是机器人？」 | （指向文末"AI 自我标识"待讨论项） |
```

### 高频反应清单（陌生电话场景的常用模板）

| 类型 | 典型表述 |
|------|---------|
| 来源质疑 | "你怎么有我电话""你们怎么还有我电话""你哪儿来的我电话" |
| 直接拒绝 | "不需要""不感兴趣""直接挂" |
| 资格否认 | "孩子不学了""我家不补习""孩子早大了""上别的了" |
| 收费质疑 | "免费的吧不是收费的吧""后面是不是要钱""又是来推销的" |
| 身份质疑 | "你是真人还是机器人""你是 AI 吧" |
| 推迟意愿 | "现在不方便""等下次说""等我有空了" |

写脚本时按用户群体（新客 / 断课 / 已购）筛选 3-5 条最高频的，不要全列。

## 适用场景

| 场景 | 是否适用 |
|------|---------|
| 陌生电话外呼 | ✅ 强适用——家长字数最少 |
| 加微后第一条消息 | ✅ 适用——主流程仍按家长极简回应 |
| 微信深度首诊对话 | ⚠️ 部分适用——家长字数会多起来，主流程可保留少量博弈 |
| AI 客服解答 | ✅ 适用——用户单次问题为主，"问完即走" |
| 多轮长对话（家长会、入门测） | ❌ 不适用——这种场景就是要"配合演出" |

## 自检 checklist

写完脚本后对照检查：

- [ ] 主流程里家长每次回复是否 ≤ 3 字？超过的部分能不能挪到阻塞分支
- [ ] 主流程里 AI 是否每句都只做一件事？(身份 / 信息来源 / 钩子 / 行动 各一句)
- [ ] 阻塞分支表格是否覆盖了"来源质疑、直接拒绝、收费质疑、身份质疑"四大类
- [ ] 是否有"主动声明不是推销"在主流程里出现？只能在阻塞分支用一次
- [ ] 跨 case 共性反应（"你是真人吗"）是否指向了统一待讨论项？

## 悬浮病症检查清单

写完一段 AI 销售/服务对话脚本后，再按 5 类病症过一遍。任何一条命中，都要重写或加一轮博弈。

| 病症 | 表现 | 修正 |
|---|---|---|
| AI 太懂事 | "您观察得真准""您说得对"类铺垫过多，每句都得体到不像真实对话 | 删掉拍马屁式反馈，反馈短促一些，把字数留给真正内容 |
| 用户太配合 | 家长每个问题都正面回答，还主动追问 AI 想要的下一句 | 电话场景用"主流程极简 + 阻塞分支"；微信场景至少加敷衍、打断、转话题或真实疑虑 |
| 推销转折太硬 | 高频出现"我们的体验课刚好/正好/恰好..." | 从前一句诊断结论自然延伸，不要突然跳到产品；把"刚好"改成"接着刚才的问题，有两个做法可以试" |
| 价格成交太顺 | 家长问价格 → AI 报价 → 家长立刻成交 | 每个 case 至少加一轮真实博弈，如后续是否加价、是否推大课、谁负责售后、退款是否方便 |
| 专业术语太顺 | AI 说专业概念，家长直接接住继续聊 | 术语要么不用，要么立刻翻译成大白话；不要让家长主动追问术语 |

评审时额外检查：

- [ ] 是否有"您观察得真准"类拍马屁话术？删
- [ ] 家长是否每次都正面回答？至少加一处敷衍/追问/转话题，电话场景则挪到阻塞分支
- [ ] 推产品衔接句是否用了"我们的产品刚好……"？换成自然延伸
- [ ] 价格谈判是否一问一报一买？至少加一轮博弈
- [ ] 是否使用了未解释的专业术语？通俗化或加翻译
- [ ] 关键节点是否有"被拒绝后怎么办"的分支说明？
- [ ] AI 是否在"自己也心虚"的话术上加了 `// 待调：` 标记？

## 什么时候需要回溯经验

- 第一次写陌生电话外呼脚本时
- 评审反馈"对话节奏不对""家长不像家长"时
- 已经按"加敷衍/加打断"改过一轮但仍被 PM 说不真实时
- 发现自己在主流程里写了 AI 的"应急话术"时
- 已经做了可视化 demo 但被指出"话术悬浮"时
- 评审会议上大家都在讨论"卡片好看不好看"而不是"话术对不对"时

- 评审视角 → 用 [PRD完整性检查要走角色动线而非功能清单](../洞察/2026-04-24-PRD完整性检查要走角色动线而非功能清单.md)（动线视角同样适用于对话评审）

## 反模式

| 反模式 | 后果 |
|--------|------|
| 直接在 HTML demo 里写话术 | 话术问题被视觉效果掩盖，评审无效 |
| 文档里只写话术不标 `// 待调` | 评审者不知道哪些是 AI 自己心虚的地方 |
| 一次性写完所有 case 才送审 | 第一个 case 的方向性问题会复制到所有 case |
| 把家长的疑问写在主流程里"展示 AI 能应对" | 让主流程冗长，且 AI 看起来像在自言自语 |
| 阻塞分支写成"如果家长说 X，跳到 Step 5" | 把应急话术变成流程图，研发实现门槛变高 |
| 阻塞分支只列家长反应不写 AI 应对话术 | 留作业给销售/研发，下游接不住 |
| 主流程电话>1 分钟 | 陌生外呼接通后 30 秒内必须把核心钩子讲完，否则对方挂 |
