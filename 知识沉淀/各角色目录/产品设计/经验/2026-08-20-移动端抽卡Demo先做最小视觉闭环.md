# 移动端抽卡 Demo 先做最小视觉闭环

日期: 2026-08-20
角色: 产品设计

## 背景

DeepTalk 小程序仍在方向探索阶段，用户希望先看一张“抽卡页（包含打开的卡片）”的 Demo，不希望一次展开整个产品。产品正式名称、Logo 等品牌资产都还没有确定。

## 经过

先产出了一个可点击的单页 HTML Demo，包含已打开的问题卡、追问、下一题和跳过动作。初版带有桌面宽度预览、进度信息、“换一张”按钮和 DeepTalk 品牌名。

用户反馈后做了四项减法和约束：

1. 页面改为 iPhone 16 Pro 适配尺寸（393 × 852）。
2. 移除与“先跳过”重复的“换一张”按钮。
3. 暂时使用“对话卡”作为中性占位，不锁定正式产品名称。
4. 移除右上角进度条，避免引入不必要的游戏化感。

## 关键收获

1. 探索期的交互方案先做“单页 + 一个真实状态”的可见闭环，用户能直接指出问题，比先写完整 PRD 更容易校准认知。
2. 移动端 Demo 应从目标设备尺寸出发，而不是先做桌面宽度再补响应式。
3. 未确认的名称、Logo、进度等元素不要提前写死；用中性占位保留后续决策空间。
4. 用户反馈优先做减法：保留文档明确要求的“跳过”，去掉额外增加且语义重复的“换一张”。

## Comments

### 产品设计 (2026-08-20)

实际预览发现卡片高度占满页面，且“轻轻点一下卡堆，开始抽卡”是抽卡前状态提示，却错误出现在已打开卡片页，导致底部按钮空间不足。修正为缩短卡片、缩小问题与插画，并移除该状态提示。

### 产品设计 (2026-08-20)

第二轮预览发现移动端卡片顶部元信息发生换行，底部反馈气泡也容易被屏幕裁剪。修正为顶部标签与编号强制单行、压缩编号信息；进一步确认当前页面不需要反馈气泡，直接移除以保持视觉聚焦。

### 产品设计 (2026-08-21)

用户补充了第一版视觉 Style Guide：从规整、偏数字化的圆角组件转向纸质手绘感；核心约束是八参数不规则圆角、深灰描边、奶油白与低饱和暖色，以及圆润字体和 1.6–1.8 倍行间距。已同步到项目 UI/UX 设计文档和 Demo。
