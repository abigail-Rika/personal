# 从石墨需求文档到 PRD + 标注 Demo 的完整产出流程

日期: 2026-04-03
角色: 产品设计

## 背景

大促 H5 抽奖需求。起点是一份石墨文档链接和一个本地 Demo HTML，终点是输出完整 PRD + 带功能标注的交互 Demo + 后台改动标注。全程在一次对话内完成。

## 经过

### 产出物

1. **项目文档** (`大促支持项目.md`) — 从石墨文档提取需求，逐步细化，记录所有决策和待确认项
2. **H5 Demo** (`h5-lottery-demo.html`) — 可交互的手机端页面 Demo，含状态切换、倒计时、弹窗
3. **后台改动 Demo** (`admin-lottery-form.html`) — 后台配置表单，标注 3 项改动
4. **正式 PRD** (`H5抽奖页面-PRD.md`) — 10 章完整 PRD，含验收标准和状态标注
5. **功能标注版 Demo** — 左右分栏布局，左侧手机预览 + 右侧功能详情面板

### 流程复盘

```
石墨文档 → 提取需求 → 向用户提问澄清（10个问题）
→ 记录到项目文档 → 用户逐条回答 → 更新决策表
→ 分析本地 Demo → 对齐差异 → 画 H5 Demo
→ 用户反馈 5 轮修改 → Demo 迭代
→ 画后台改动 Demo → 用户确认
→ 汇总为正式 PRD → 加状态标注
→ Demo 加功能标注（打点+详情）
```

### 关键纠偏

| 轮次 | 用户反馈 | 我的调整 |
|------|----------|----------|
| 1 | "揭晓结果太复杂了" | 移除揭晓按钮，改为自动弹窗 |
| 2 | "每轮中奖 1-2 人" | 调整 Demo 数据 |
| 3 | "九重福利先占位" | 加占位标识 |
| 4 | "中奖后需要弹窗，不是不弹" | 修改 PRD 和 Demo 中的异步回看逻辑 |
| 5 | "九重福利是一张图，不是九宫格" | 改为图片占位 |
| 6 | "标注点不开" | overflow 裁剪 → 改为左右分栏布局 |

## 关键收获

1. **先出项目文档再出 PRD**：项目文档是"工作底稿"，记录所有讨论和决策过程；PRD 是"交付物"，只保留最终结论。两者不能合并——底稿需要保留演变过程，PRD 需要干净清晰。

2. **Demo 先于 PRD**：先画 Demo 让用户看到实际效果，收集反馈后再写 PRD。避免 PRD 写完才发现理解有偏差，返工成本更高。

3. **标注交互用分栏，不用气泡**：在受限容器（overflow:hidden/auto 的滚动区域）内做弹出气泡，会遇到裁剪问题。左右分栏布局（左侧预览 + 右侧详情面板）更稳定、信息承载量更大、不依赖 z-index 和定位计算。

4. **PRD 状态标注很有用**：在 PRD 中用 ✅已确认 / ⏳待确认 / 🔧需开发 / 📌关键决策 / ⚠️边界case 标注每个章节的状态，研发评审时能快速定位重点。末尾汇总表进一步降低扫描成本。

5. **后台改动单独出 Demo**：后台改动不要只在文字里描述，画一个标注了修改项的表单 Demo，研发一看就懂。
