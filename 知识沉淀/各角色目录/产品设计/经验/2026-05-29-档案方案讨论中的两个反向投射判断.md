# 档案方案讨论中的两个"反向投射"判断

日期: 2026-05-29
角色: 产品设计

## 背景

在做"面向家长建立初诊档案"的方案讨论。已经形成了一份《01-讨论纪要》，覆盖了用户路径、问题边界、指标分层、模块草稿等共识，并在"待和组长对齐的关键决策点"里列了 A/B/C 三个决策项（档案性程度、卡点策略、销售首通时序）。

讨论纪要看起来已经收尾了，但用户在两个轮次里又抛出了两个问题，触发了两次"反直觉"判断。

## 经过

### 反直觉发现 1：指标共识其实掩盖了未对齐项

**用户提问**：「档案的指向目标，分别用完习率和首通反馈率作为目标，会有什么区别？」

**初步以为**：这是个常规对比题——比较两个指标的口径、归因清晰度、扰动来源等。

**展开后发现的反直觉点**：
两个指标对应的不是"同一个产品的两种衡量方式"，而是**两套形态完全不同的产品**：

| 指标 | 反向投射出的档案形态 |
|:-|:-|
| 完习率 | 必须是"可成长档案"（决策点 A 选 Y），模块 4-5 必做，时序约束弱，档案 = 家长自用的学习进度看板 |
| 首通反馈率 | "一次性卡"就够（决策点 A 选 X），模块 1-3 必做、4-5 可砍，时序强约束（首诊必须在首通前完成），档案 = 给销售的首诊报告 |

更进一步：纪要 2.5 里写"完习率 + 销售反馈率"作为主指标——这个并列写法**看起来是共识，其实是把矛盾掩盖了**。这两个指标如果不分主辅，最终方案会被指标反向拉着走，做成另一个东西。

**用户的反应**：直接说"整理到文档吧"——认可这个判断的价值，没有反驳。

→ 在讨论纪要里新增了"决策点 D | MVP 主指标的取舍"，把这个未对齐项显式化。

### 反直觉发现 2："用户路径"这个词糅杂了 5 个维度

**用户提问**：「不同用户路径下，档案如何结合插入，以及对销售和其他业务方的影响？」

**初步以为**：纪要 2.1 已经说"电商 / 直投 收口到同一个插入点"，再补一些插入点细节就行。

**展开后发现的反直觉点**：
"路径"这个词在前几轮讨论里被反复使用，但其实糅杂了 5 个独立维度：

| 维度 | 纪要是否覆盖 |
|:-|:-|
| 来源（电商/直投/私域/老带新） | 部分覆盖 |
| 设备（iOS/Android/H5/小程序） | **完全没提** |
| 支付路径（电商支付/直投落地页/销售推链接） | 部分覆盖 |
| 时序（购买→加微→启动→前测→计划页→学→首通） | 决策点 C 在讨论 |
| 激活状态（首启动/二启动/跨设备） | **完全没提** |

→ 纪要 2.1 看似已经给出共识，其实只覆盖了"来源 × 时序"两个维度的一个交叉点，剩下维度是大盲区。这一节如果不先拆维度就直接展开，**会重复制造"看似有共识其实没对齐"的假象**。

按维度展开后，挖出 13 条新的待对齐项（标紧急度），其中"H5/小程序占比"和"问题→课程证据映射表归属人"两条是**卡 MVP 范围 / 物料的关键缺口**，纪要原版完全漏了。

→ 在讨论纪要第四节扩充了所有新增对齐项，并新建 `02-路径插入点分析.md` 作为方案稿第 2 块草稿。

## 关键收获

### 收获 1：方案讨论里"看起来已经达成的共识"，可能只是把矛盾掩盖了

两次都是这个模式——纪要里的某条共识（2.5 主指标 / 2.1 路径插入点）写得很流畅，但**展开一层就会发现**：
- 流畅是因为用了模糊词（"主指标 = 完习率 + 销售反馈率"用并列回避了主辅；"用户路径"用泛指回避了维度拆分）
- 真正的对齐项被字面共识盖住了

**判断标准**：当一条共识里出现并列、泛指、复合名词时，要主动追问"这两个东西是同构的还是异构的？""这个词指代的是哪一个具体维度？"

### 收获 2：某些"辅助元素"其实在反向决定方案主体形态

两次都是这个机制——主指标 / 路径维度看似是方案的"附属决策"，但实际上：
- 选什么指标 → 反向锁死决策点 A/B/C 的选项空间
- 用哪个路径维度看问题 → 反向决定哪些业务方要被对齐、哪些工作台要改造

**这意味着方案讨论的顺序应该反过来**：不是"先定主体再补辅助"，而是"**先把那些会反向锁死主体的辅助决策摆出来**"。

### 收获 3：AI 主动识别 + 用户认可，比用户纠偏更高频

这次没有发生用户纠偏（用户没说"你理解错了"）。两次发现都是 AI 在用户提问后**主动展开发现盲区**，然后用户认可（"整理到文档吧"）。

按 `2026-05-25-重要协作结束前必须做沉淀判断.md` 的口径，这种"AI 主动识别的反直觉发现 + 用户认可"也属于沉淀触发器，**不要等用户纠偏才沉淀**。
