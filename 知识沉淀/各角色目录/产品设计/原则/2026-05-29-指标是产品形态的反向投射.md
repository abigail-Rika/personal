# 指标是产品形态的反向投射

## 原则

**主指标的选择不是方案的附属决策，而是反向决定方案形态的根因决策。**

不要先定方案再选指标，要先把指标摆清楚，因为指标会反向锁死：
- 产品的形态（一次性 vs 可成长 vs 可交互）
- 模块的取舍（哪些必做、哪些可砍）
- 时序的约束（哪些环节必须在哪些环节之前）
- 业务方对齐的优先级（哪些工作台要前置改造）

## 判断标准

### 何时触发本原则

1. 看到"主指标 = A + B"的并列写法 → **追问 A 和 B 是同构指标还是异构指标**
   - 同构：两个指标投射的产品形态一致（如"完成率 + 二次打开率"都指向"产品体验良好"）→ 并列没问题
   - 异构：两个指标投射的产品形态冲突（如"完习率"指向产品体验、"首通反馈率"指向销售工具）→ **必须分主辅，不能并列**

2. 出现指标变化讨论时 → 反推方案的哪些决策项需要重审
   - 决策点 A（产品形态）
   - 决策点 B（卡点策略）
   - 决策点 C（时序）
   - 业务方改造范围

3. 不同的中间人扰动量级 → 离用户行为越近的指标，扰动越小，归因越干净
   - 远端指标（如正价转化率）：扰动大，仅观测不背
   - 中间层指标：是否扰动大要按"中间人是谁"判断，不是按"离收入近不近"判断
   - 近端指标（产品自身行为）：扰动小，但归因风险是"涨了说不清是哪部分功劳"

### 一个指标合格做主指标的条件

| 条件 | 说明 |
|:-|:-|
| 和定位对齐 | 指标方向不能和方案的产品定位冲突 |
| 中间人扰动小 | 指标主要受用户/产品行为影响，不被销售/运营/课程内容个体差异污染 |
| 验证周期可控 | 指标产出的时间窗在 MVP 验证周期内（一般 ≤ 2 周） |
| 归因相对干净 | 指标涨了能定位到方案的具体动作，不是"什么都涨" |

四条都满足 → 主指标
满足 1-2 条 → 辅指标，仅观测
都不满足 → 不进 MVP 指标体系

## 反向校验

写完方案的指标分层后，**反向问一遍**：

1. 如果主指标涨了，能直接证明方案有效吗？
2. 如果主指标没涨，能直接证明方案无效吗？
3. 主指标和辅指标在方向上会不会冲突（一个涨另一个跌）？
4. 主指标 ≠ 同构集合时，**有没有显式分主辅**？

任一条答不上来，就需要把指标讨论拉到决策点级别，让组长 / 业务方拍板。

## 什么时候需要回溯经验

当你发现自己在写方案时反复修改的不是方案本身，而是"做出来到底想测什么"，回看 2026-05-29 档案讨论的经验——根因往往是指标没先定清楚。

也参考相邻原则 `2026-05-29-用户路径要先拆维度.md`——两条原则常常同时触发：方案里同时存在"指标共识掩盖矛盾"和"路径泛指掩盖维度"两类问题。
