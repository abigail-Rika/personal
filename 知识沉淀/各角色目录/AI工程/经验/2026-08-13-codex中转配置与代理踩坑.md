# codex CLI 中转配置与代理踩坑

日期: 2026-08-13
角色: AI工程

## 背景

用户想在 M1 Mac 上用 codex CLI 接 GPT-5.4，走 OpenRouter 中转。过程中连续踩了 402、403 region 两个坑，最终根因是代理。

## 经过

1. 安装：官方 codex v0.147.0 二进制装到 `~/.local/bin/codex`（npm 包内二进制未签名被 macOS kill exit 137，GitHub 直连 502，最后走 ghfast.top 镜像下载官方 tar.gz 成功）。
2. 配置 OpenRouter：`~/.codex/config.toml` 里 `model_provider="custom"` + `[model_providers.custom]` base_url=https://openrouter.ai/api/v1 wire_api=responses；`~/.codex/auth.json` 写 OpenRouter key。
3. 第一坑 402：OpenRouter 免费档未充值，付费模型返回 Insufficient credits。
4. 充值后第二坑 403 region：openai/* 模型（gpt-5.x / gpt-4o 等）对中国大陆全部 403，是 OpenAI 官方地区限制，非配置问题。
5. 真相：用户一直开着 Clash（127.0.0.1:7890，日本节点），但 codex（Rust/reqwest）不读 macOS 系统代理，也不读 Bash 沙箱代理，直连走大陆 → 403。
6. 修复：显式设 `HTTP_PROXY` / `HTTPS_PROXY=http://127.0.0.1:7890` 后，gpt-5.4 走 OpenRouter /responses 返回成功。

## 关键收获

- 命令行程序（Rust/reqwest 等）默认不走 macOS 系统代理，需显式设 HTTP_PROXY / HTTPS_PROXY 环境变量。
- 判断「地区 403」前，先确认本机代理出口 IP，别急着归因到地区限制。
- OpenRouter 上所有 openai/* 模型对中国大陆全部 403（官方地区限制），非充值/配置可解。
- codex v0.147.0 已移除 wire_api="chat"，只支持 wire_api="responses"；OpenRouter /responses 端点支持 deepseek-chat 做临时方案。
