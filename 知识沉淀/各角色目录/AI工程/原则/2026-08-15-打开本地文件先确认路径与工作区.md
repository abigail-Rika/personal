# 打开本地文件先确认路径与工作区

## 原则

**用户要求打开本地文件时，先验证精确路径和当前应用工作区，再选择最轻的打开方式。** 不要一上来读取完整应用状态、调用桌面控制或请求 GUI 权限。

## 操作 Checklist

1. 用最轻量的文件检查确认用户给出的绝对路径是否存在。
2. 路径不存在时，只在明确的工作区范围内用 `find` / `rg --files` 定位；找到候选路径后先向用户说明路径差异。
3. 确认当前编辑器、Obsidian vault 或 IDE workspace 是否包含目标文件。
4. 文件在当前工作区：优先用侧边栏或快速切换器打开，不调用系统 GUI。
5. 文件不在当前工作区：在“切换工作区”和“用系统默认应用打开”之间选择最小成本路径，并提前说明可能的权限边界。
6. 只有在侧边栏、快速切换器或系统打开都不可用时，才使用 Computer Use 读取和操作应用界面。
7. 打开后向用户报告实际打开的绝对路径；如果使用了替代路径，必须明确说明。

## 判断流程

```text
用户给出绝对路径
  ↓
路径存在吗？
  ├── 否 → 限定范围定位候选路径 → 先说明路径差异
  └── 是
       ↓
当前工作区包含它吗？
  ├── 是 → 侧边栏 / 快速切换器
  └── 否 → 切换工作区，或系统默认应用打开
```

## 什么时候需要回溯经验

- 打开文件前发现路径不存在
- 当前 Obsidian / IDE 显示的是另一个库或工作区
- 为一个简单的打开动作开始读取应用无障碍树
- 打开本地文件时出现 GUI 权限请求
- 用户反馈“明明侧边栏就能打开，为什么绕了很久”
