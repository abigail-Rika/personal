# 知识系统运行闭环：读旧知 → 执行 → 沉淀 → 更新索引

## 原则

知识系统不是“写进文件就有用”，必须形成一个完整闭环：

```text
开工前读旧知 → 执行中应用旧知 → 收尾时判断是否沉淀 → 写入新知并更新索引
```

任何一个环节断掉，知识体系都会退化：

- 只写不读：知识库变成档案馆，实际协作还是每次从零开始。
- 只读不沉淀：旧知识能用，但新经验留不下来，系统不生长。
- 写了不更新索引：知识存在但找不到，等于没有。

## 开工前：必须读旧知

涉及 PRD、方案设计、数据分析、复盘、AI 协作机制、工具链路等任务时，第一步必须读 `personal/知识沉淀/知识索引.md`，扫描是否有已有知识可复用。

命中角色后，再读对应 `各角色目录/<角色>/角色说明.md` 和相关具体文件。不要只凭记忆开工。

判断标准：

- 写 PRD / 做交互方案 → 先读产品设计相关知识
- 分析投放 / 转化 / AI 销售 → 先读增长策略相关知识
- 搭建 prompt / context / skill / MCP / 知识系统 → 先读 AI工程相关知识
- 做过类似事但记不清细节 → 搜索 `知识沉淀/`，不要重摸索

## 执行中：让旧知约束行动

读旧知不是形式动作。读到原则 / 技能后，要把它转成当前任务的 checklist。

例如：

- 读到“工具结果为空时必须交叉验证” → 工具返回空时不能直接下结论。
- 读到“外部系统写入需要明确授权” → 写 Notion / Confluence / 日历前先确认授权。
- 读到“增长 PRD 自检清单” → 交付前逐条对照，不是只读一遍。

## 收尾时：必须做沉淀判断

重要协作结束前，AI 必须显式做一次“沉淀判断”：

- 这次有没有踩坑？
- 有没有用户纠偏了我的默认理解？
- 有没有首次跑通的新流程？
- 有没有反直觉发现？
- 有没有可复用的 checklist、原则或洞察？

只要命中其中一项，就应该主动提出沉淀；如果内容明确且不会造成外部系统写入风险，可以直接写入本地知识库并更新索引。

## 写入后：必须更新索引

沉淀完成后必须更新：

- 具体知识文件：放到正确角色和类型目录
- `personal/知识沉淀/知识索引.md`
- 对应角色的 `角色说明.md`
- `.cursor/rules/知识索引.mdc`

当前标准方式是运行：

```bash
python3 personal/知识沉淀/.scripts/build_index.py
python3 personal/知识沉淀/.scripts/build_index.py --check
```

## 为什么

知识体系不主动，通常不是因为不会写，而是两个触发断了：

1. **开工前的读取触发**：旧知识明明存在，但 AI 没加载。
2. **收尾时的沉淀触发**：新经验明明产生了，但 AI 没判断是否该写。

用户没有说“记一下”，只说明用户没有触发手动命令，不说明这次没有知识价值。AI 的责任是先识别，再让用户纠偏。

## 执行口径

每次协作按这个口径执行：

1. 任务开始：判断角色，读取知识索引。
2. 执行过程：把命中的原则/技能转成 checklist。
3. 任务结束：做沉淀判断。
4. 命中沉淀：写知识文件并跑索引脚本。

每次完成以下类型工作后，默认做沉淀判断：

- PRD、方案、数据分析经过多轮修改
- 方案被否定或重做
- 首次跑通一个工具、流程或查询链路
- 发现和预期不一致的现象
- 用户纠偏了 AI 的理解、协作方式或默认行为

## 什么时候需要回溯经验

当用户反馈“你又不主动了”“知识体系没用起来”“这个之前不是说过吗”时，回溯本原则和来源经验，检查是任务开始前没读旧知识，还是任务结束前没做沉淀判断，或者写入后没有更新索引。
