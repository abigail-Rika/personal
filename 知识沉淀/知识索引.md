# 知识库总索引

> 本文件是 AI 助手的知识加载入口。每次协作开始前，AI 应通读本文件确认角色和可用知识。

## 设计理念

**Agent 不是菜，他只是不知道。**

这套知识体系的目的是让 AI 助手在持续协作中积累上下文知识，从"每次从零开始的聪明新人"变成"越用越懂你的协作伙伴"。

核心原则：
- 知识由 AI 自己写，人负责纠偏和追问"为什么"
- 先记再整理——先让知识流动起来，体系在记的过程中自然生长
- 简单性是持续运转的关键——目录结构 + Markdown，grep 就能搜索

## 仓库结构

```
知识沉淀/
├── 知识索引.md                    # 本文件：总索引 + 加载策略
├── 沉淀规范.md                    # 什么时候记、怎么分类、放在哪
│
├── 通用知识/                      # 跨角色通用知识
│   ├── 原则/                      # 通用原则（协作规范、安全底线）
│   ├── 洞察/                      # 通用洞察（跨领域的规律性认知）
│   └── 经验/                      # 不属于特定角色的经验
│
├── 各角色目录/                     # 按角色分类的知识
│   ├── 产品设计/                   # PRD、交互、用户体验
│   ├── 增长策略/                   # 投放、转化、落地页、实验
│   └── AI工程/                    # prompt、context、agent 协作
│
├── 技术文章/                      # 技术文章归档
├── 阅读笔记/                      # 通用阅读笔记
└── 技能评估/                      # AI 技能评估体系
    ├── 技能地图.md
    └── 评估记录/
```

## 知识加载策略

### 与 Cursor Rules 的关系

```
┌─────────────────────────────────┐
│  Cursor Rules (.cursor/rules/)  │  ← 系统级加载，由 Cursor 管理
│  ┌───────────────────────────┐  │
│  │ always_applied            │  │  协作协议.mdc（常驻）
│  ├───────────────────────────┤  │
│  │ agent_requestable         │  │  产品上下文、UI规范、交互原则...
│  └───────────────────────────┘  │  （AI 判断相关时主动加载）
└─────────────────────────────────┘
              ↕ 互补
┌─────────────────────────────────┐
│  知识沉淀/ (本知识库)            │  ← 协作级知识，在对话中按需读取
│  ┌───────────────────────────┐  │
│  │ 知识索引.md（本文件）      │  │  索引入口，知道有什么
│  ├───────────────────────────┤  │
│  │ 各角色目录/<角色>/角色说明 │  │  角色描述 + 细分索引
│  ├───────────────────────────┤  │
│  │ 经验 / 技能 / 原则 / ...  │  │  具体知识，通过索引命中后加载
│  └───────────────────────────┘  │
└─────────────────────────────────┘
```

**Cursor Rules 存"不变的规则"**（产品上下文、UI 规范、交互原则）——这些由人主动维护，变更频率低。

**知识沉淀/ 存"生长的经验"**（踩坑记录、协作模式、复盘洞察）——这些在每次协作中自然产生，由 AI 主动沉淀。

### 加载时机

| 层级 | 内容 | 时机 |
|------|------|------|
| **常驻** | `协作协议.mdc` | 每次对话自动加载 |
| **任务启动** | 本文件 `知识索引.md` | 复杂任务开始时，快速扫描可用知识 |
| **按需** | `各角色目录/<角色>/角色说明.md` → 具体经验/技能 | 命中关键词后深入加载 |
| **触发式** | 特定场景直接读取 | 见下方触发规则 |

### 触发规则

- 写 PRD / 做交互方案 → 先读 `各角色目录/产品设计/角色说明.md`
- 分析投放/转化数据 → 先读 `各角色目录/增长策略/角色说明.md`
- 搭建 prompt / context / skill → 先读 `各角色目录/AI工程/角色说明.md`
- 做过类似的事但记不清细节 → grep `知识沉淀/` 搜关键词

## 沉淀触发

完成以下类型工作后，AI 应主动提出沉淀：
1. PRD 经历了多轮修改才达标
2. 方案被用户否定后重做（说明认知有偏差）
3. 首次跑通某个流程（MCP 接入、新工具使用）
4. 发现了反直觉的产品/业务/技术现象
5. 用户纠偏了 AI 的理解（"不是这样的，应该是……"）

详细规范见 → `沉淀规范.md`
