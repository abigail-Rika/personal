# AI 工程技能地图

> 评估周期：每周一次
> 评估依据：与 AI 的实际协作记录
> 说明：评估个人主导的实践

---

## 评估协议

### 范围

**计入评估的目录（白名单）：**

| 仓库 | 目录 | 说明 |
|------|------|------|
| `personal/` | 全部 | 个人空间 |
| `aries/` | `团队-增长/` | 个人主导搭建和维护的团队空间 |

**不计入的（即使是个人产出）：**
- `aries/` 其他目录（团队-工作台、跨团队项目、产品事务、团队-内容组等）
- `aries-teach/`（教研AI组团队仓库）

> **范围调整**：如需扩大评估范围（如新增其他个人主导的空间），先修改本节白名单，再做评估。不能在评估过程中临时扩大范围。

### 触发条件

以下任一条件触发评估：
1. 每周一（例行）
2. 用户说"评估技能"/"技能评估"

### 评估流程

```
1. 读本文件 → 确认范围和维度
2. 读上次评估 → assessments/ 最新文件
3. 拉 git log → git log --since="上次评估日期" 仅看白名单目录
4. 列出范围内的实际文件变更清单（排除 backups/、_site/、历史聊天/）
5. 逐维度对照变更打分 → 只看范围内产出
6. 写 assessments/2026-WXX.md + 更新本文件
```

### 评分规则

- 0-100%，5% 为最小单位
- 子技能用 1-5 星
- 无新产出的维度 → 维持上次分数，不降不涨
- 单次评估单维度最多 +15%
- 只基于实际产出，不基于"应该能做到"
- 维护性工作（小幅更新已有文件）→ 最多 +5%

## 评估维度

### 1. Prompt 工程

评估什么：设计和编写 prompt / skill / context 的能力

| 子技能 | 评估标准 | 证据来源 |
|--------|----------|----------|
| Skill 结构设计 | 创建/修改了 SKILL.md 或 agent.md，结构是否完整（元数据、能力边界、示例） | `personal/work/*/SKILL.md`、`personal/.cursor/agents/*.md` |
| 行为指令编写 | context 规则和 skill 中的指令是否具体、可执行、无歧义 | `personal/.cursor/rules/*.mdc`、`aries/团队-增长/context/*.mdc` |
| 示例与测试 | 是否有示例文件，是否做了测试迭代 | `examples/` 目录、git log 中的迭代记录 |
| 高级技巧 | 是否有意使用了 chain-of-thought、few-shot、结构化约束等高级手法 | skill / context 文件内容 |

### 2. AI 工具使用与集成

评估什么：日常使用 AI 工具的深度和广度

| 子技能 | 评估标准 | 证据来源 |
|--------|----------|----------|
| Cursor 日常使用 | 用 Cursor 完成了哪些实际工作任务（PRD、分析、项目管理等） | 范围内通过 Cursor 产出的文件 |
| 任务委托意识 | 是否准确拆分了"AI 做什么 / 人做什么" | 产出中人工判断 vs AI 执行的分工痕迹 |
| 自动化搭建 | 是否创建了脚本或自动化流程 | `personal/scripts/`、新增的自动化工具 |
| MCP / 外部工具 | 是否使用或集成了外部工具（Tableau MCP 等） | MCP 调用记录、外部工具集成 |

### 3. 个人知识体系

评估什么：组织和沉淀知识的能力

| 子技能 | 评估标准 | 证据来源 |
|--------|----------|----------|
| 信息架构设计 | 目录结构是否清晰、分类是否合理 | `personal/` 和 `aries/团队-增长/` 的目录变更 |
| 知识沉淀习惯 | 是否持续记录学习、复盘、知识 | `diary/`、`reviews/`、`knowledge/`、`thoughts/`、`知识沉淀/` |
| 流程标准化 | 是否创建或维护了模板和标准流程 | 模板文件、流程文档 |

### 4. Context Engineering

评估什么：构建和管理 AI context 的能力

| 子技能 | 评估标准 | 证据来源 |
|--------|----------|----------|
| Context 分层设计 | context 分层是否合理（always vs requestable vs skill） | `.cursor/rules/` 结构 |
| 隐性知识显性化 | 是否将隐性业务知识转化为 context 文件 | 新增/修改的 `.mdc` 文件 |
| Context 质量管理 | context 是否经过 review、是否持续维护 | context 文件的更新记录、review 标记 |
| 认知与方法论 | 对 Context Engineering 的理解深度 | 方法论文章、分享文档 |
