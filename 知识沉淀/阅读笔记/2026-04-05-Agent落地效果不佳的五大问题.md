# 现阶段 Agent 落地效果不佳的五大问题

## 核心观点

知乎问题「如何评价当前 AI Agent 落地效果普遍不佳」下的系统性回答。从技术视角归纳了五个根因，其中第3点（记忆能力不足 / Context Engineering）和我们的工作直接相关。

## 五大问题

### 一、学术研究与工业实践存在大 gap

RL（强化学习）训练 Agent 模型是热门方向。RL 不给标准答案，而是给"评分规则"——做对加分、做错扣分，AI 自己摸索怎么得高分。但前提是评分必须可自动验证（代码跑测试、数学对答案），所以研究集中在 DeepResearch、Coding 等结果容易验证的窄领域，大量"什么算好"难以量化的真实业务场景用不了这个方法。此外工业场景需要消化、测试、上线，迭代速度跟不上学术。RL 训练环境和真实业务环境不一致，MCP 只解决了工具标准化，执行环境和上下文管理还没有标准方案。

### 二、底座大模型推理泛化不足

LLM 的跨任务跨环境推理有瓶颈。RLVR（可验证的强化学习）依赖可验证奖励信号，但很多现实任务不具备这个条件，限制了泛化。前沿探索方向：RL 前移到预训练（RLP）、rubrics 多维度奖励，都还在早期。

### 三、记忆能力不足（重点）

**短期记忆 = 执行轨迹**：`{a0,o0,a1,o1...an,on}`，任务越复杂 → 轨迹越长 → 上下文膨胀。

**Agent 上下文和 Chatbot 本质不同**：Chatbot 是 QA 对，Agent 大量上下文被工具调用结果占据，管理难度远高于普通对话。

**记忆的核心难点**：不是"记住所有东西"，而是"识别哪些信息对当前决策有用"。

**业界共识 = Context Engineering**。文章明确引用 Manus、Anthropic、OpenAI 三家的实践分享，指出当前主要依赖四种工程化手段：
- **检索（Retrieval）**：短期记忆持久化，按需提取
- **裁剪（Trimming）**：丢弃时间较久的上下文
- **压缩（Compaction）**：总结对当前决策有用的部分
- **缓存（Cache）**：复用上下文降低成本

未来方向：通过 RL 让 Agent 学会自主记忆管理，但难度很大。

### 四、技术范式同质化 + 工程保障薄弱

几乎所有 Agent 都是 ReAct 范式（plan-act-obs 循环），缺少竞争性范式推动突破。工程侧：大模型服务没有公认的测评/测试体系，可观测性、安全审计、human-in-the-loop 都在早期。

### 五、很多场景不具备 Agent 落地条件

前提条件：任务所需工具必须 API 化——很多企业不具备。Demo 容易做，生产可用需要大量投入。

**关键建议**：应投入在工具链、安全验证、可审计等不会被模型进步替代的基础能力上，而不是花大力气在提示词优化、规则兜底等容易被模型能力替代的方面。

## 和我们实践的关联

| 文章观点 | 我们的实践 | 启发 |
|---------|----------|------|
| Context Engineering 是 Agent 落地关键 | 我们已经在做：Rules + 知识沉淀 = context 的两层架构 | 方向正确，可以用行业共识来解释我们为什么这样做 |
| 记忆核心难点是"识别有用信息" | 协作协议定义了五个沉淀触发场景，AI 自己判断要不要记 | 我们用"人纠偏 + AI 写"解决识别问题，是轻量版的记忆管理 |
| Agent 上下文和 Chatbot 不同 | 协作协议已有"对话越长 ≠ AI 越懂你"、规划→清空→执行 | 我们凭直觉发现的规律，文章从技术层面解释了为什么 |
| 提示词优化容易被模型替代 | 我们投入在知识体系（不会被替代）而非精调 prompt | 继续坚持这个方向 |
