# 投放落地页异形弹窗

> 状态：需求对齐中 | 需求方：迎春（投放）| 预计：Q1 内解决

## 背景

- 落地页后台原本支持异形弹窗功能，效果较好
- 去年技术支持做后台配置时**误删/漏掉**了该功能
- 当前仅有标准弹窗样式，适配性不强
- 迎春希望恢复异形弹窗模式，图片由投放团队内部制作产出
- 判断：**不需要重新开发**，后台能力仍在，需要恢复配置

## 下周对齐：前置数据背景准备

和迎春对齐前，需要搞清楚以下问题：

### 1. 异形弹窗 vs 标准弹窗效果对比

- [ ] 去年使用异形弹窗期间的落地页转化率数据（CTR / 留资率）
- [ ] 切换回标准弹窗后，同口径转化率变化
- [ ] 如有，分渠道/分投放场景的对比数据

### 2. 当前标准弹窗的问题量化

- [ ] 迎春说"适配性不强"——具体表现是什么？（不同机型/屏幕尺寸的展示问题？点击率低？）
- [ ] 当前弹窗的曝光→点击→转化漏斗数据

### 3. 技术侧确认

- [ ] 后台异形弹窗配置项是否还在？需要技术侧确认恢复的工作量
- [ ] 去年是哪次配置变更导致丢失的？（避免再次发生）
- [ ] 恢复后是否需要回归测试

### 4. 需求范围

- [ ] 需要支持哪些落地页？全部还是特定页面？
- [ ] 异形弹窗的图片规格/尺寸要求是否有变化？
- [ ] 弹窗触发规则（进入即弹 / 延迟 / 滚动触发）是否和之前一致？

## 备注

- 这是一个恢复性需求，核心是配置恢复而非新开发
- 关键在于用数据说明恢复的必要性和优先级
