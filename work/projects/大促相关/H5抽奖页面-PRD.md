## 一、背景与目标

### 1.1 背景

大促期间（6月6日），公司在 App 内进行直播抽奖活动，但部分用户无法实时在 App 内参加直播。需要一个站外 H5 页面，让已下单/续费的用户在微信场景下也能参与抽奖、感受活动氛围，同时引导未下单用户完成转化。

### 1.2 目标

| 目标 | 说明 |
|------|------|
| 双端联动 | H5 与直播间共用同一套后台配置、同一奖池、同一开奖结果，用户在任一端体验一致 |
| 氛围拉齐 | H5 展示直播间在线人数、同步标识等信息，让用户感知到与直播是同一场活动 |
| 转化抓手 | 未下单用户通过 CTA 引导下单，下单后自动获得全部剩余轮次的抽奖资格 |

### 1.3 入口

销售在**微信群/私聊**中群发 H5 页面链接，用户点击直接打开。

### 1.4 活动节奏

- 活动日期：6月6日
- 活动时段：12:00 - 22:00（一天一场直播）
- 抽奖轮次：由运营在 Gaffey 后台逐轮配置

## 二、用户角色与资格

### 2.1 用户身份判断

```
进入 H5 → 是否登录？
              ├─ 否 → 手机号 + 验证码登录
              └─ 是 → 是否为大促目标池用户？
                        ├─ 否 → Toast "您不符合抽奖资格"（不展示页面内容）
                        └─ 是 → 是否已下单/续费？
                                  ├─ 否 → 展示抽奖页面 + 吸底「下单获资格」CTA
                                  └─ 是 → 展示抽奖页面 + 吸底「已获资格」状态
```

### 2.2 资格定义

| 条件 | 说明 |
|------|------|
| 大促池用户 | 用户在本次大促的目标人群池内（由后端标记） |
| 已下单/续费 | 大促期间产生过有效订单，截止到用户当前的实时状态 |
| 抽奖资格 | 已下单 = 有资格，自动参与所有「抽奖渠道 = 直播间和H5」的轮次 |
| 中奖限制 | 整场活动每人**最多中奖 1 次**（该规则不外显给用户） |

## 三、页面结构与交互

H5 抽奖页面为**单页面**，自上而下包含以下模块：

### 3.1 活动头部

| 元素 | 内容 | 说明 |
|------|------|------|
| 活动标题 | 海豚夏日福利嘉年华 | 固定文案 |
| 活动时间 | 6月6日 12:00 - 22:00 | 固定文案 |

### 3.2 状态栏

| 元素 | 数据来源 | 说明 |
|------|----------|------|
| 当前轮次信息 | 后台配置 | 格式：「🔥 第X轮抽奖中」+「还有N轮 · 共N个奖品」 |
| 直播同步标识 | 前端固定 | 红色闪烁圆点 + "直播同步中" 文字，传达实时联动感 |
| 在线人数 | 直播间接口 | 展示**直播间**在线人数，H5 用户不计入 |

### 3.3 抽奖卡片区

**展示规则：**
- 仅展示「正在抽奖」+「未抽奖」的轮次
- 仅展示后台配置中「抽奖渠道」为「**直播间和H5**」的轮次
- 已开奖轮次自动移入下方「历史开奖记录」
- 卡片横向滚动排列，最后一张卡片为「已展示全部抽奖 · 共N轮」提示

**单张卡片内容：**

| 元素 | 数据来源 | 说明 |
|------|----------|------|
| 轮次状态标签 | 后台 | 正在进行的轮次显示「🔥 正在进行」标签 |
| 奖品示意图 | 后台（新增字段） | 支持动图/静态图，详见后台改动 §5.1 |
| 奖品名称 | 后台 | |
| 轮次 + 中奖名额 | 后台 | 格式：「第X轮 · N个名额」，每轮 1-2 人 |
| 开奖倒计时 | 后台 | 正在进行的轮次：「⏰ 距离开奖 MM:SS」（实时递减）|
| 开奖时间 | 后台 | 未到轮次：显示具体开奖时间「⏱️ 开奖时间 HH:MM」|

### 3.4 自动开奖 & 结果弹窗

倒计时归零后，**自动弹出**中奖/未中奖结果弹窗。

**中奖弹窗：**
| 元素 | 内容 |
|------|------|
| 图标 | 🎉 |
| 标题 | 恭喜您中奖了！ |
| 奖品图片 | 从后台配置读取 |
| 奖品名称 | 从后台配置读取 |
| 说明文字 | 「第X轮 · 奖品将在活动结束后发放」 |
| 按钮 | 「太棒了」→ 关闭弹窗 |

**未中奖弹窗：**
| 元素 | 内容 |
|------|------|
| 图标 | 😢 |
| 标题 | 很遗憾，您未中奖 |
| 说明文字 | 「继续参与后续轮次，好运就在前方！」 |
| 按钮 | 「继续等待好运」→ 关闭弹窗 |

**异步回看场景：** 用户不在页面时开奖的轮次，在用户下次进入页面时不弹窗，结果直接展示在「历史开奖记录」中。

### 3.5 历史开奖记录

| 元素 | 说明 |
|------|------|
| 列表展示 | 每条包含：轮次编号、奖品名称、奖品图、中奖人数、开奖时间 |
| 折叠规则 | 默认展示**最近 3 条**，超过部分折叠，点击「展开全部记录（共N轮）」查看全部 |
| 中奖名单 | 每条可点击「中奖名单 ›」→ 弹出底部卡片，展示中奖人手机号（脱敏：138\*\*\*\*1234） |
| 数据口径 | 与直播间完全一致 |

### 3.6 九重福利

| 元素 | 说明 |
|------|------|
| 展示形式 | 九宫格，每格展示一项福利的图标和名称 |
| 解锁规则 | 下单后解锁全部福利 |
| 当前状态 | **内容占位中**，待业务方确认后补充 |

### 3.7 活动规则

固定文案展示活动规则，包括：
1. 下单/续费后自动获得全部共有轮次抽奖资格
2. 每轮自动参与，中奖名单实时公布
3. 每轮抽取一种奖品，与大促直播间同步开奖
4. 下单用户可同时获得九重专属福利
5. 本活动最终解释权归海豚所有

### 3.8 吸底 CTA

根据用户资格状态展示不同的固定底栏：

| 用户状态 | CTA 内容 | 点击行为 |
|----------|----------|----------|
| 已下单（有资格） | 「🎉 已获得抽奖资格，可参与剩余 N 轮抽奖」 | 无操作（纯展示） |
| 未下单（无资格） | 「🎁 立即下单，获得抽奖资格」<br>副文案：「下单即可参与剩余 N 轮抽奖 + 九重福利」 | 跳转下单页面 |
| 活动已结束 | 「活动已结束，感谢参与」 | 置灰不可点击 |

## 四、页面状态矩阵

| 场景 | 页面表现 |
|------|----------|
| **活动未开始** | 全页面蒙层覆盖，提示文字「直播预计在 12:00 开始」，按钮显示「距离直播开始还有 HH:MM:SS」（实时倒计时） |
| **活动进行中 + 有资格** | 正常展示所有模块，吸底显示「已获得资格」 |
| **活动进行中 + 无资格** | 正常展示所有模块（可看不可中奖），吸底显示「下单获取资格」CTA |
| **活动已结束** | 正常展示历史记录，吸底按钮置灰「活动已结束」 |
| **无更多轮次** | 卡片区域显示「已展示全部抽奖 · 共N轮」 |
| **非大促池用户** | Toast「您不符合抽奖资格」后，不展示页面内容 |

## 五、后台改动（Gaffey 系统）

### 5.1 奖品池增加图片配置

| 维度 | 说明 |
|------|------|
| 改动位置 | 奖品池配置表单，每个奖品新增「奖品图片」字段 |
| 字段类型 | 图片上传（支持 JPG/PNG/GIF） |
| 用途 | H5 和直播间卡片展示奖品示意图 |
| 是否必填 | 是 |

### 5.2 参与条件增加「仅下单」

| 维度 | 说明 |
|------|------|
| 改动位置 | 抽奖配置表单 →「参与条件」下拉 |
| 现有选项 | 仅评论 / 评论且下单 |
| 新增选项 | **仅下单** |
| 用途 | H5 场景下用户无法发评论，需要一个仅基于下单状态的参与条件 |

### 5.3 新增「抽奖渠道」字段

| 维度 | 说明 |
|------|------|
| 改动位置 | 抽奖配置表单，新增字段 |
| 字段类型 | 单选 |
| 选项 | **仅直播间**（默认）/ **直播间和H5** |
| 逻辑 | 选「仅直播间」→ 该轮次仅在直播间展示和开奖<br>选「直播间和H5」→ 该轮次同时在 H5 页面展示，H5 用户可参与 |
| 说明 | 不自动生成 H5 页面，H5 页面由前端独立开发，仅读取后台数据 |

> 后台改动 Demo 见 [admin-lottery-form.html](./admin-lottery-form.html)

## 六、数据接口需求

以下为 H5 前端所需的数据接口，具体字段和格式由前后端协商确定。

### 6.1 用户鉴权

| 接口 | 说明 |
|------|------|
| 登录 | 手机号 + 验证码，返回 token |
| 用户身份校验 | 入参：token；返回：是否在大促池、是否已下单 |

### 6.2 抽奖数据

| 接口 | 说明 |
|------|------|
| 获取轮次列表 | 返回所有「抽奖渠道 = 直播间和H5」的轮次信息（轮次号、奖品名称、奖品图片、中奖人数、开奖时间、当前状态） |
| 获取开奖结果 | 入参：轮次ID、用户ID；返回：该用户在该轮次的中奖状态、中奖奖品信息 |
| 获取中奖名单 | 入参：轮次ID；返回：中奖用户列表（脱敏手机号） |
| 获取活动状态 | 返回：活动状态（未开始/进行中/已结束）、距离开始的倒计时 |

### 6.3 直播间数据

| 接口 | 说明 |
|------|------|
| 在线人数 | 读取直播间当前在线人数（轮询或 WebSocket，前端决定方案） |

## 七、非功能性需求

| 维度 | 要求 |
|------|------|
| 终端适配 | 移动端 H5（微信内置浏览器为主），适配 iPhone / Android 主流机型 |
| 性能 | 首屏加载 < 3s（4G 网络），倒计时流畅不卡顿 |
| 兼容性 | 微信内置浏览器、Safari、Chrome |
| 安全 | 用户登录态校验，防刷（同一用户多次请求开奖结果不重复中奖） |

## 八、不在本期范围

| 事项 | 说明 |
|------|------|
| 发奖流程 | 中奖后的奖品发放由运营线下处理，不在本需求内 |
| 评论抽奖轮次 | 直播间内「仅评论」参与条件的轮次不同步到 H5 |
| H5 页面自动生成 | 后台不自动生成 H5 页面，前端独立开发 |
| 九重福利具体内容 | 当前占位，待业务方确认后补充 |

## 九、关联需求

### 9.1 中奖通知（独立需求，可单独排期）

用户中奖后需发送通知，不阻塞 H5 主流程开发。

| 通知方式 | 说明 |
|----------|------|
| 短信 | 中奖后自动发送，包含奖品信息 |
| 站内信 | 中奖后自动发送至 App 消息中心 |
| 触发范围 | H5 端 + 直播间端中奖均触发，复用同一套通知逻辑 |

## 十、验收标准

### 10.1 核心流程

- [ ] 非大促池用户进入页面，展示 Toast 提示后无法查看内容
- [ ] 未登录用户进入页面，展示手机号验证码登录页
- [ ] 登录后正确识别用户下单状态，展示对应 CTA
- [ ] 未下单用户点击 CTA 可跳转下单页面
- [ ] 下单后资格自动回写，CTA 切换为「已获资格」状态

### 10.2 抽奖展示

- [ ] 正确展示所有「抽奖渠道 = 直播间和H5」的轮次卡片
- [ ] 不展示「仅直播间」渠道的轮次
- [ ] 不展示「仅评论」参与条件的轮次
- [ ] 正在进行的轮次有实时倒计时
- [ ] 卡片横滑正常，末尾展示「已展示全部抽奖」

### 10.3 开奖

- [ ] 倒计时归零后自动弹出中奖/未中奖弹窗
- [ ] 用户离开后再进入，已开奖轮次直接展示在历史记录中，不弹窗
- [ ] 整场活动同一用户最多中奖 1 次
- [ ] 中奖结果与直播间一致

### 10.4 历史记录

- [ ] 默认展示最近 3 条，可展开查看全部
- [ ] 每条可查看中奖名单（手机号脱敏）
- [ ] 数据与直播间口径一致

### 10.5 页面状态

- [ ] 活动未开始：蒙层 + 倒计时
- [ ] 活动已结束：CTA 置灰
- [ ] 无更多轮次：正确展示提示

### 10.6 后台配置

- [ ] 奖品池可上传图片（动图 + 静态图）
- [ ] 参与条件可选「仅下单」
- [ ] 抽奖渠道可选「仅直播间」/「直播间和H5」
- [ ] H5 页面正确读取后台配置数据
