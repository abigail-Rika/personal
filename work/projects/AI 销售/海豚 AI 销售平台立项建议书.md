## 1. 项目背景与战略意义

**AI 销售是行业趋势，也是海豚的战略方向。** 在线教育行业正在从"真人销售驱动"转向"AI 销售驱动"，这不是效率工具的升级，而是销售模式的根本性变化。

**行业已有验证。** 斑马口语已经跑通了 AI 销售（来源：[兄弟业务调研](https://moxt.ai/w/69n5htoq/1c563df5-2d11-4f08-b6bc-e8a179271b23)），几个关键结论：

* AI 全替代真人做体验课转正式课，业务上可行

* AI 跟真人是并行 AB 测的关系，不是"AI 辅助真人"

* 短期不一定省钱，但人效没有上限

* 电话能力是硬门槛，电话不行转化就上不去

* 必须先想清楚终局再动手，不能先做几个零散功能再拼

**AI 销售相比真人的结构性优势：**

* **过程可控**：真人销售的话术执行、跟进节奏、异议应对全看个人水平，好销售和差销售的转化率差好几倍，培训和管理的边际效果在递减。AI 的每条线索处理方式都可标准化，每通对话都可回溯，策略调了立刻全量生效

* **降本增效空间大**：AI 没有人效上限，量级涨了不用加人，长期成本结构会完全不同

* **数据闭环快**：每一通电话和每一条消息都可回溯分析，策略迭代周期从"月"缩短到"天"

**现在有条件冷启动。** 真人团队跑了很长时间，SOP、录音、典型案例和过程数据都有积累，不是从零开始。

## 2. 这个项目要做什么

**先从 CC leads 中切一小部分量，让 AI 独立跑完从建联到成交的完整转化流程。**

不是做辅助工具给销售用，是让 AI 自己打电话、自己发企微、自己挖需、自己催课、自己做完课回访和异议处理，最终自己促成交。

一期目标：

* 从 CC leads 中切出小流量（具体比例灰度期确定），AI 独立承接

* 跑通完整转化链路，验证 AI 独立转化的可行性

* 转化率对标真人团队，持续 AB 测迭代

### 关于终局

终局不是现在就能定死的，需要边跑边看。目前可以预见两种可能：

**终局一：AI 主攻部分渠道，其他渠道 AI+真人协作。** 有些渠道的用户画像清晰、需求集中，AI 可以独立跑完全流程；但有些渠道用户情况更复杂（比如异议多样、决策周期长、需要深度信任建立），可能更适合 AI 负责前置环节（建联、挖需、催课等标准化动作），真人负责关键转化节点。

**终局二：AI 全面替代真人，独立承接所有渠道的转化。** 随着 AI 能力迭代和用户对 AI 销售的接受度提升，AI 在各类渠道上都能做到真人水平，真人团队逐步退出日常转化。

走向哪个终局，取决于几个在跑的过程中才能验证的东西：

* AI 在不同渠道上的转化效果差异有多大

* 哪些环节 AI 比人做得好（比如跟进及时性、执行一致性），哪些环节人比 AI 强（比如复杂异议处理、情感共鸣）

* AI 能力本身的迭代速度——电话自然度、多轮对话深度、个性化讲解精度

* 家长对 AI 销售的心智接受度，会不会随时间和体验改善而变化

所以一期的定位很明确：**先跑起来，用数据回答这些问题**，而不是现在就押注某一个终局。

## 3. 一期做什么

### 重点打透两个指标

一期集中打两个对结果影响最大的指标：**完习率**和**完习转化率**。

* **完习率**：用户不完课就不可能转化，完习率直接决定了后面有多少人能进入转化环节。现在线索到完课的损耗是整条链路里最大的。

* **完习转化率**：完课后能不能转化为付费用户，是最终检验 AI 销售能力的核心指标。

**影响完习率的两个关键因子：加微率和挖需程度。**

一期测试的用户有一个重要前提：**这些用户都还没加上微信**。所以 AI 外呼是一期的核心动作——AI 需要通过电话完成挖需、邀约课程和引导加微，这三件事都要在外呼中一并解决。

* **加微率**：用户不加微，后续的催课、课程提醒、完课回访都触达不了，完习率就没有基础。加微是从外呼到持续服务的关键衔接点。

* **挖需程度**：如果第一通电话里没搞清楚孩子什么年级、学什么科、当前水平怎么样、家长核心诉求是什么，后面的邀约、催课就是盲打——推了不匹配的课、说了家长不关心的话，完习率自然上不去。挖需做到位了，后续的邀约话术、催课节奏、课程推荐才能精准。

所以一期的逻辑是：**AI 外呼完成挖需并引导加微 → 加微后精准催课拉动完习率 → 完课后针对性转化拉动完习转化率。**

### 一期先跑 0 转低，但按 0 转低 + 0 转正来搭

一期验证的转化目标是 **0 转低**（leads 转化为低价体验课用户，具体价格待定）。但搭建系统时，能力设计要同时考虑 0 转低 和 0 转正的需要——挖需、用户画像、对话引擎、通道能力这些是共用的，不能只为 0 转低 搭一套。

节奏上：先把 0 转低 跑起来、跑出数据，在迭代 0 转低 的同时，逐步搭建 0 转正所需的差异化链路和能力（比如完课回访、正式课价值讲解、异议处理策略等）。

### 一期用户范围：从初中入口开始

一期先从**初中入口**的 CC leads 开始跑，初中流量在 CC 中占比最多，样本量够做验证。断课和新客二类同时尝试，但两类用户的 SOP 和策略需要做区分，AI 在外呼前要能识别用户类型，对应不同的对话策略。

| 维度   | 断课用户               | 新客二类                  |
| ---- | ------------------ | --------------------- |
| 用户特征 | 之前上过课，有历史学习数据和沟通记录 | 没有历史数据，首次接触           |
| 挖需策略 | 基于已有信息做补充和确认       | 从零开始，需要完整摸底           |
| 邀约侧重 | "回来继续学"，强调课程延续性    | "了解和体验"，强调低门槛试听       |
| 选择原因 | CC 存量中占比大，召回价值高    | 补充增量，验证 AI 对全新用户的转化能力 |

### 几个原则

* 按"AI 独立转化"的方向设计，不按"辅助工具"设计，终局边跑边验证

* 电话和企微双通道同步做，不能只做企微

* 从 CC leads 中小流量灰度起步，初中入口先行

* 0 转低 先跑通，能力建设兼顾 0 转正

* 允许业务侧观测，但人工接管不是默认方案

## 4. 系统要做哪些事

### 用户画像整合

AI 打电话之前得知道这个用户是谁。需要把线索来源、孩子年级学科、历史行为（上没上过课、完没完课、之前聊过什么）、当前阶段整合到一起，让 AI 带着信息去沟通，而不是每次都当新用户。

### 销售决策

AI 得自己判断：这个用户现在该打电话还是发企微？该做挖需还是催课？该用什么节奏跟进？还是暂时放一放？这些不能写死规则，得根据用户状态和历史行为来动态决策。

### 对话能力

这是核心。AI 要能完成完整的销售对话——开场怎么说、怎么引导家长说出真实需求、怎么介绍课程、怎么处理"太贵了""孩子没时间""再考虑考虑"这类异议、怎么促单。不是一问一答的客服，是有目标、有节奏的销售对话。

### 课程理解和个性化讲解

这是海豚和通用 AI 销售最大的区别。同样是介绍课程：

* 跟一年级家长讲数学启蒙和跟五年级家长讲小升初备考，完全是两套话

* 孩子上过 D1 但没完课的，和完课了正在犹豫要不要报正式课的，关注点不同

* 有的家长在意教学方式（AI 课靠不靠谱），有的在意效果（能不能提分），有的在意价格

AI 要能根据这些差异调整自己怎么讲，不能一套话术打天下。

### 电话 + 企微双通道

AI 外呼是主通道（电话成交占 60-70%），企微是辅助和承接。电话没接通的走企微补触达，企微没回的择机再打电话。两个通道的状态要同步，不能电话聊了半天、企微又从头来。

### 过程可观测、策略可迭代

所有对话要能回放，关键节点要有数据。哪步流失最多、哪个话术效果好、哪类用户 AI 搞不定，要能看到、能分析、能快速调整。

### 风控

灰度放量控制、触达频次限制、敏感话术拦截（不能乱承诺、不能说竞品坏话）、异常中断处理（用户突然挂电话了怎么办）、投诉监控。

## 5. 一期能力优先级

**必须做的：**

| 能力      | 说明                       |
| ------- | ------------------------ |
| AI 外呼   | 一期核心动作，用户未加微，电话是唯一主动触达方式 |
| 外呼中挖需   | 通过电话对话抽取孩子年级、学科、水平、家长诉求  |
| 外呼中邀约课程 | 基于挖需结果推荐匹配的体验课，引导用户上课    |
| 外呼中引导加微 | 在电话中引导家长添加企微，为后续服务建立通道   |
| 对话状态管理  | 跟踪每个用户聊到哪一步了，下次接着来       |
| 用户阶段识别  | 判断用户当前在漏斗哪个位置            |
| 催课和完习跟进 | 邀约成功后的催课提醒，拉动完习率         |
| 异议处理    | 识别常见异议并做针对性回应            |
| 人工观测台   | 对话回放、关键指标看板、异常告警         |

**一期先做基础版、后续加深的：**

* 个性化课程讲解（先覆盖 CC 主力学段和学科，再扩展）

* 人群策略分层（先按基础标签区分，再做更精细的分层）

* 触达时机优化（先按规则触达，后续用数据优化最佳时间）

* AI 质检（先人工抽检 + 系统辅助，后续做自动化质检）

**一期不能做成这样：**

* 只做一个 AI 企微机器人——电话才是主通道

* 只做一个 AI 外呼机器人——没有策略编排和状态管理就是一个自动拨号器

* 只做知识库——没有销售执行链路，知识库没地方用

* 只做质检——不做转化链路，质检检什么

## 6. 分阶段推进

### 阶段 0：准备期

把基础素材备齐，让产研能开工：

* 梳理清楚线索阶段定义（什么算建联成功、什么算挖需完成…）

* 把现有 CC 销售 SOP 结构化，让 AI 能用

* 整理常见异议库（TOP 20 异议 + 对应话术）

* 整理 CC 主要学段学科的课程讲解要点

* 对齐指标口径和灰度方案（从 CC 中切多少量、怎么分组）

### 阶段 1：灰度验证

从 CC leads 中切出小流量，跑通挖需和完课回访两个环节：

* 电话和企微能打通、能正常对话

* 对话过程可回放、可观测

* 策略和话术能快速调

* 关键指标能收回来和真人做 AB 对比

### 阶段 2：CC 完整转化闭环

把剩下的环节补齐——建联、邀约、催课、异议处理都由 AI 跑，做到一条 CC 线索从进来到成交（或确认放弃）全程 AI 独立完成。逐步扩大 CC 中的 AI 承接比例。

### 阶段 3：扩展和平台化

根据前两个阶段的数据，明确 AI 在哪些渠道/环节可以独立跑、哪些需要和真人配合，确定最终的分工模式。策略可配置、实验可自助跑、复盘有工具，逐步向更多渠道扩展。

## 7. 怎么衡量成功

核心就一条：**AI 在 CC leads 上跑出可衡量的转化效果，并通过数据明确 AI 和真人各自的最优分工。**

具体拆开看：

**结果指标**：CC 正式课转化率、完课后转化率、AI 独立成交占比

**过程指标**：电话建联率、加微率、挖需完成率、线索到完课率、回访完成率、有效对话率

**替代程度**：人工介入率、AI 独立完成完整链路的占比

**风险指标**：单客转化成本、投诉率、敏感话术触发率、异常中断率

## 8. 分工

| 角色       | 干什么                                  |
| -------- | ------------------------------------ |
| 业务运营     | 定业务目标和阶段策略，输出 SOP、话术、异议库、课程讲解逻辑，参与复盘 |
| 产品       | 把业务链路抽象成系统方案，拆需求、定里程碑                |
| 算法/AI 应用 | 对话能力、策略引擎、效果评估、模型迭代                  |
| 工程       | 电话和企微通道、任务编排、状态管理、系统稳定性              |
| 数据       | 指标口径、实验设计、归因分析                       |
| 销售专家     | 提供优质录音和典型案例，参与效果判断和复盘                |

## 9. 主要风险

**AI 前期转化率不如真人** —— 几乎是确定的。所以才从 CC 小流量开始，AB 测 + 快速迭代，不指望一上来就追平。

**电话能力不行导致效果差** —— 电话占成交的 60-70%，如果 AI 电话体验太差（延迟高、声音假、不会接话），整体就起不来。电话能力是一期硬要求。

**课程讲解太通用，说不到点上** —— 家长最关心的是"这课适不适合我家孩子"，如果 AI 只会说"我们课程很好"这种话，不可能转化。课程理解能力要同步建设。

**家长对 AI 身份敏感** —— 提前和法务确认合规口径，配好敏感场景的规避策略，建投诉监控。

**项目做散了，最后拼不起来** —— 最大的风险。要按平台项目立项，统一 owner、统一目标。

## 10. 对产研的要求

这个项目不能按"做几个 AI 功能"来理解，要按"做一套销售系统"来做。

* 业务定方向和阶段目标，终局随验证结果调整

* 产品把业务链路抽象成平台结构，不是一个需求一个需求拼

* 算法负责对话和策略能力

* 工程负责跑得通、看得到、稳得住

* 数据负责指标闭环和归因

一期虽然只切 CC 的一小部分量，但系统设计要考虑后续扩展，不要做成只能给 CC 用的一次性东西。
