# 项目归纳

> 海豚工作经历的项目档案库，**为简历 + 面试服务**。

## 这个文件夹是干嘛的

把在海豚做过的项目按 STAR 法则整理成标准化档案，目的是：

1. **写简历时**：从档案库挑 3-5 个项目，按目标 JD 风格精简成 bullet point
2. **面试时**：被问到某个项目，能快速调出完整的「背景 / 我做了什么 / 结果」叙事
3. **平时**：边做边沉淀，避免"年底想跳槽时啥都记不住"

## 怎么用

### 触发词（让 AI 主动归纳）

- **「同步项目」/ 「归纳一下项目」/ 「沉淀项目经历」**：AI 扫描 `personal/work/projects/` 下的新文档和更新，提示哪些需要新建或更新档案
- **「review 项目档案」**：AI 通读所有档案，挑出哪些字段空缺、哪些数据已过期、哪些故事讲得不够好
- **「为 [公司/JD] 挑项目」**：AI 根据 JD 关键词，从档案库挑出最匹配的项目，输出简历版 bullet point

### 文件命名约定

- `_` 开头的是底座文件（模板、清单），不是某个具体项目
- 数字前缀的是叙事项目档案（按重要性/时间顺序排）
- 一个叙事项目可以包含多个执行项目（比如 AI 销售档案下包含 0 转体、立项、未析出新客承接三个子阶段）

## 目录索引

| 文件 | 用途 |
|------|------|
| `_模板.md` | 项目档案的标准结构（新建项目时复制） |
| `_项目清单.md` | 所有项目的一句话定位 + 标签 + 状态总览 |
| `_待补充清单.md` | AI 整理档案时识别出的待回填信息（用户专用） |
| `01_*.md` ~ `0N_*.md` | 各项目档案 |

## 维护原则

1. **数据真实**：宁可留 placeholder 写「待补充：上线 1 个月后的实际转化率」，也不要瞎编数据
2. **故事完整**：S/T/A/R 四段都要有，缺哪段就是面试时要被追问爆的地方
3. **持续更新**：项目上线后回填实际数据；被面试官追问后补「面试常见追问」字段
4. **能力标签化**：每个项目挂能力标签（如「从0到1」「跨团队协作」「AI 产品」），方便按 JD 反向挑项目
