# 项目复盘 - 数据回收规范

## 定位

PRD 数据闭环的最后一环。解决一个反复出现的问题：**项目做完了想复盘，发现数据不够用——没埋、埋错、口径对不上、没有对照组。**

两个使用时机：
- **PRD 阶段**：写完「数据需求」后，用本规范自检埋点是否够复盘用
- **复盘阶段**：项目/实验结束，用本规范梳理需要回收哪些数据，向商分提需求

### 与现有体系的关系

| 环节 | 工具 | 衔接点 |
|------|------|--------|
| 写 PRD | prd-writer 第六章「数据需求」 | 写完后用本规范「埋点自检清单」检查 |
| Review PRD | prd-review v1 第 8 维度「效果评估思路」 | review 时同步检查埋点能否支撑复盘 |
| 增长 PRD | 增长产品PRD规范「实验结论」 | 用本规范「复盘数据需求模板」指导回填 |

## 一、复盘需要什么数据

每个项目复盘都要回答以下问题，每个问题都需要对应的数据支撑：

| # | 复盘问题 | 需要的数据 | 常见踩坑 |
|---|---------|-----------|---------|
| 1 | **触达了吗？** | 目标人群数、实际曝光数、曝光率 | 只埋了点击没埋曝光，算不出触达率 |
| 2 | **参与了吗？** | 各环节参与人数、完成率、流失节点 | 只埋了入口和终点，中间环节黑盒 |
| 3 | **有效果吗？** | 实验组 vs 对照组核心指标对比 | 没设对照组，或对照组划分有污染 |
| 4 | **假设对了吗？** | 与 PRD 假设直接相关的行为数据 | PRD 假设写的是 A，埋点量的是 B |
| 5 | **有副作用吗？** | 防护指标（次留、投诉率、学习时长等） | 只盯目标指标，忽略防护指标 |
| 6 | **谁受益/不受益？** | 分人群的指标拆解 | 埋点没带关键用户属性维度 |
| 7 | **效果持续吗？** | 活动期 vs 结束后 1-2 周的趋势 | 活动一结束就不看了 |

## 二、埋点自检清单

PRD「数据需求」写完后，逐项检查：

### 基础层 — 没有这些就复盘不了

- [ ] **全链路埋点**：核心路径每一步都有曝光 + 行为事件（不只是首尾两端）
- [ ] **实验标识**：keyfrom / AB 实验标识能区分实验组和对照组
- [ ] **口径定义**：核心指标的计算口径写清楚了（分子分母是什么、时间窗口、去重逻辑）

### 归因层 — 没有这些只能看相关性，不能归因

- [ ] **对照组**：有对照组设计，或有可对比的历史基线
- [ ] **行为串联**：实验标识能关联到用户后续行为（如转化、留存），不只是当场的点击
- [ ] **时间窗口**：明确从什么时候开始观察、观察多久（特别是转化、留存类指标）

### 分析层 — 没有这些只能看总数，不能深挖

- [ ] **防护指标**：至少有 1 个防护指标有对应埋点（防止"指标提升但质量下降"）
- [ ] **维度可拆**：关键维度有字段可拆（用户类型、渠道、年级等，按业务需要）
- [ ] **过程指标**：中间环节有埋点，能定位"效果差是卡在哪一步了"

### 持续性 — 短期活动/实验额外检查

- [ ] **活动后可追踪**：活动结束后相关数据仍能继续采集（不会随活动下线而断）
- [ ] **观察期计划**：明确活动结束后看几周数据、看什么

## 三、数据可用性评估

上线前或复盘前，用这张表评估现有埋点和数据能不能撑住复盘：

| 评估维度 | ✅ 可以复盘 | ⚠️ 勉强复盘 | ❌ 复盘不了 |
|---------|-----------|------------|-----------|
| **触达与参与** | 全链路曝光+行为数据齐全 | 有部分环节数据，能估算 | 只知道"做了"，不知道多少人看到 |
| **效果归因** | 有对照组，可做因果推断 | 只有前后对比，混杂因素多 | 没有基线，无法判断是方案的效果还是自然变化 |
| **假设验证** | 埋点直接对应假设中的行为变量 | 能间接推断 | 假设和可用数据完全对不上 |
| **人群拆解** | 关键维度字段齐全 | 部分维度可拆 | 只有大盘数据，无法分人群看 |
| **持续性** | 有活动后观察期数据 | 可事后从数仓补拉 | 数据随活动下线断了 |

**评估结果的处理：**
- 全 ✅：可以正常复盘
- 有 ⚠️：复盘结论需注明局限性，标注"相关性≠因果性"
- 有 ❌：**上线前**发现 → 补埋点；**复盘时**发现 → 记录为经验教训，下次避免

## 四、向商分提复盘数据需求 — 模板

复盘时向商分提数据需求，按以下结构整理，减少来回沟通：

```markdown
## 复盘数据需求：{项目名称}

### 背景
- 项目简述：{一句话说明做了什么}
- 上线时间：{YYYY-MM-DD}
- 实验/活动周期：{起止日期}
- 实验分组：{实验组/对照组的划分方式和标识}

### 需要的数据

#### 1. 触达与参与
| 指标 | 口径说明 | 拆分维度 | 时间范围 |
|------|---------|---------|---------|
| {如：活动页曝光UV} | {分子分母、去重逻辑} | {如：按用户类型} | {如：活动期间} |

#### 2. 核心效果指标
| 指标 | 口径说明 | 对比方式 | 时间范围 |
|------|---------|---------|---------|
| {如：周完习率} | {口径} | {实验组 vs 对照组} | {活动期间 + 结束后2周} |

#### 3. 防护指标
| 指标 | 口径说明 | 关注阈值 |
|------|---------|---------|
| {如：次日留存率} | {口径} | {低于 XX% 则需关注} |

#### 4. 分析维度
需要按以下维度拆解上述指标：
- {维度1：如新老用户}
- {维度2：如渠道}

### 产出要求
- 希望产出形式：{看板 / 表格 / 一次性取数}
- 期望交付时间：{日期}
```

## 五、复盘数据报告结构

数据回收后，按以下结构组织复盘结论：

```markdown
## 项目复盘：{项目名称}

### 一句话结论
{成了 / 没成 / 部分成了——核心判断依据}

### 假设验证
- PRD 假设："{原文照抄}"
- 结论：{成立 / 不成立 / 部分成立}
- 数据依据：{关键数据}

### 核心数据

#### 触达与参与
{曝光、参与、完成的关键漏斗数据}

#### 效果对比
| 指标 | 实验组 | 对照组 | 差异 | 显著性 |
|------|-------|-------|------|-------|
|      |       |       |      |       |

#### 防护指标
{防护指标是否异常}

### 关键发现
- 超预期：{什么比想象中好}
- 低于预期：{什么没达到预期，可能原因}
- 意外发现：{没想到的事}

### 下一步
- 效果好 → {放大 / 长期化 / 扩大人群}
- 效果差 → {止损 / 调整假设 / 换方向}
- 不确定 → {需要什么额外数据或实验来确认}

### 经验沉淀
- 数据侧：{这次埋点/数据有什么教训，下次怎么避免}
- 方法论：{对类似项目有什么可复用的认知}
```

## 六、常见反面案例

记录典型的"复盘不了"场景，提醒自己别重复踩坑：

| 场景 | 问题 | 教训 |
|------|------|------|
| 活动做了但不知道效果 | 只埋了活动页点击，没埋曝光，也没和后续转化关联 | 埋点要覆盖全链路，且能串联后续行为 |
| 指标提升了但归因不了 | 没有对照组，同期还有其他活动在跑 | 必须有对照组或干净的实验窗口 |
| 数据有了但口径对不上 | PRD 写的是"完习率"，商分拉的是"完课率"，定义不同 | 口径必须在 PRD 阶段就对齐，写清分子分母 |
| 想看人群差异但拆不了 | 埋点没带用户属性字段 | 埋点时就要想好需要哪些拆分维度 |
| 活动效果好但不知道能不能持续 | 活动结束就收工了，没看后续数据 | 短期活动至少追踪活动结束后 1-2 周 |
