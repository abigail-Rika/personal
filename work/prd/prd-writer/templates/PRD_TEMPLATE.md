## 一、背景

### 1.1 业务背景

- 当前业务/产品所处阶段
- 核心数据概览（用户规模、关键指标）
- 本次需求要解决的核心问题

### 1.2 用户视角 🟢可简化

- 🔵 从用户角度理解问题：用户为什么会出现这个行为/现象？
- 🔵 定性信息来源（如与一线/助理沟通的结论）
- 🔵 用户的真实痛点或动机是什么
- 🟢 快速验证型：简要说明对用户的影响，重点确认方案不会对用户造成负面影响

### 1.3 问题诊断 🟢可简化

- 现状数据与漏斗分析
- 🔵 **问题归因链**：现象 → 原因（追问 1-2 层 why）→ 归因结论
- 🔵 数据线索的追问（例：某指标高/低说明了什么？背后原因是什么？）
- 🟢 快速验证型：描述问题现象和基本判断即可，承认"具体原因需要验证"
- 机会点与切入方向

## 二、目标测算

### 2.1 收益目标

- 主要关注的指标（如 leads 数、转化率、GMV 等）
- 收益测算表或链接

### 2.2 目标设定

- 【保守】预期目标及假设
- 【激进】乐观目标及假设
- 关键假设说明

### 2.3 目标依据与成本

- 目标数字的来源（历史数据推算 / 类似活动参考 / 业务期望）
- 成本预估（人力、奖品、补贴等）
- 大致 ROI 判断
- （如为短期活动）活动结束后的预期影响

## 三、现状 🟢可简化或合并到背景

### 3.1 现状梳理

- 当前链路/流程
- 相关点位与转化数据
- 竞品或历史方案参考

### 3.2 用户/需求分析

**调研结论**（如有）：

- 抽样调研/访谈发现
- 用户核心诉求与痛点
- 未转化/流失原因归类

**数据分析**（如有）：

- 用户行为数据
- 漏斗转化数据
- 关键结论

## 四、设计思路

### 4.1 方案定位

- 本方案在整体策略中的位置（短期运营手段 / 长期产品机制 / 阶段性实验）
- 🔵 与其他策略的关系和边界
- 🔵 对方案局限性的正视（如外部激励的长期效果、活动结束后的回落风险等）
- 🟢 快速验证型重点回答三个问题：
  1. **有效性**：基于什么逻辑/数据认为方案能起作用？
  2. **成本可控**：开发和运营成本是否在合理范围？
  3. **无副作用**：是否会造成用户认知混乱、破坏现有体验、或其他附带损害？

### 4.2 方案对比 🟢可跳过

- 达成目标的可选路线有哪些（简要列举）
- 为什么在当前阶段选择了这个方案
- 各方案的优劣势对比（简要即可）
- 🟢 快速验证型：如果方案本身就是"低成本试一下"，不需要和重方案做对比

### 4.3 方案设计

- 核心设计思路
- 着力点与变量说明
- 关键规则/参数的设计依据（如无依据，标注"初始方案，根据数据迭代"）

### 4.4 问题/流程设计（如适用）

- 问题结构设计
- 逻辑分支与跳转
- 文案与配置说明

### 4.5 竞品/行业参考 🟢可跳过

- 行业内类似机制的常见做法与效果
- 可借鉴点
- 差异化设计

### 4.6 实验设计（如适用）

- AB 实验分组
- 变量定义
- 流量占比
- 实验预期与关注指标

- 页面/步骤流程

### 5.4 实验分组（如适用）

- 各实验组变量与流量
- 对应展示差异
