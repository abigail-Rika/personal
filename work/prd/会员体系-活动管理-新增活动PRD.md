# 会员体系管理中心 · 活动管理 · 新增活动 PRD

> 业务方向：二手手机回收平台 · 会员体系 · 实时况价场景下的运营活动
> 文档版本：v0.1（基于原型图编写）
> 路径：`会员体系管理中心 / 活动管理 / 实时况价 / + 新增活动`

---

## 1. 背景与目标

针对二手手机回收业务中的**报价师 / 回收商**两类核心角色，运营需要通过后台灵活配置激励活动，以拉动指定品类/品牌/机型/成色等维度下的**成交量、报价量、上架量、成交额、充值额**等关键业务指标。

本需求为后台**新增活动**配置页，运营在不需开发介入的情况下，可完成：

- 圈定参与人群（全量 / 上传名单）
- 圈定计算口径（活动目标 + 多维限制条件）
- 配置奖励公式（分段函数 `y = ax + c`）
- 配置活动生命周期、报名机制、前端进度展示样式、规则文案

---

## 2. 名词解释

| 名词 | 含义 |
| --- | --- |
| 活动目标 | 用于统计用户完成度的业务指标，例如「成交量」 |
| 活动目标值 / `x` | 用户在活动期间实际完成的指标数值 |
| 限制条件 | 在统计 `x` 时附加的过滤条件（场次/品类/品牌/机型/成色/单价），不选则视为全量 |
| 奖励公式 | `y = ax + c`，分区间生效，`y` 为奖励金额（或奖品数量） |
| 报价师 | 平台内为机器进行回收报价的角色 |
| 回收商 | 平台合作的下游回收商家 |
| 场次 | 业务侧的渠道/来源分类，如 OPPO 厂家、vivo 厂家、话机世界等 |

- **入口**：会员体系管理中心 → 活动管理 → 实时况价 → 右上角「+ 新增活动」按钮
- **页面性质**：弹窗 / 抽屉 / 独立页（**待确认**，建议独立页，因表单较长）
- **操作权限**：仅「活动运营」「会员体系运营」两类角色可见入口（具体权限编码待与权限系统对齐）
- **页面标题**：「新增活动」

## 4. 字段配置详情

> 表头说明：`必填`列中 ✓ 表示必填、空 表示选填；`校验`列描述前端 / 后端校验规则；所有字段提交时统一做 trim。

### 4.1 活动名称

| 项 | 说明 |
| --- | --- |
| 控件 | 单行文本输入框 |
| 必填 | ✓ |
| 长度 | 1 ~ 30 个字符（中英文均按 1 字符计） |
| 校验 | 不允许纯空格；同一活动类型下不允许重名（**待确认**：是否需要全局唯一） |
| 提示 | placeholder：「请输入活动名称，30 字以内」 |
| 报错 | 「活动名称已存在，请修改」/「活动名称不能为空」 |

### 4.2 活动类型

| 项 | 说明 |
| --- | --- |
| 控件 | 下拉单选 |
| 必填 | ✓ |
| 默认 | 「达成-1 个活动目标」 |
| 选项 | ① 达成-1 个活动目标 ② 达成-2 个活动目标 ③ 达成-指定机型多倍计算 |
| 说明文案 | 「2 个活动目标取交集，即满足目标 1 和目标 2，才可发放奖励；指定机型多倍计算需要配置一样的活动目标」（常驻显示在下拉框下方） |
| 联动 | 影响下方「活动目标」「奖励设置」区块的呈现，详见 §5.1 |

**业务规则**：

- 「达成-1 个活动目标」：仅配置 1 组活动目标 + 1 组奖励公式
- 「达成-2 个活动目标」：配置 2 组活动目标，**用户需同时满足两组目标对应的 `x`** 才发奖；奖励公式分别按目标 1/目标 2 配置
- 「达成-指定机型多倍计算」：要求两组目标的「限制条件」配置完全一致，仅差异在「机型」维度；命中指定机型时按倍率叠加（**倍率公式待业务侧补充**）

### 4.3 目标人群

| 项 | 说明 |
| --- | --- |
| 控件 | 单选（3 选 1） + 文件上传 |
| 必填 | ✓ |
| 选项 | ① 全量报价师 ② 全量回收商 ③ 上传（自定义名单） |

**上传交互**：

- 仅当选中第三项「上传」时，「上传」按钮亮起；其它两项时按钮置灰
- 「上传模板」为一个可点击下载的链接（右侧文本），点击下载 `.xlsx` 模板
- 模板字段：`用户ID`（必填）、`角色`（必填，枚举：报价师/回收商）、`备注`（选填）
- 上传后展示：`已上传：xxx.xlsx · 共 N 人 · [重新上传] [下载已上传文件]`
- 校验：
  - 文件大小 ≤ 5MB
  - 行数上限 50,000 行（**待确认**）
  - 用户 ID 必须存在于系统中，不存在的行需返回错误明细
  - 报价师 / 回收商角色与系统记录不一致时报错
- 报错时给出明细下载：`错误明细.xlsx`，包含「行号 / 字段 / 错误原因」

### 4.4 活动目标

> **本区块在「活动类型 = 达成-2 个活动目标 / 指定机型多倍计算」时复制一份为「活动目标 1 / 活动目标 2」。**

#### 4.4.1 活动目标（指标项）

| 项 | 说明 |
| --- | --- |
| 控件 | 下拉单选 |
| 必填 | ✓ |
| 选项 | 成交量 / 报价（量）/ 上架（量）/ 成交额 / 充值额 |
| 统计口径 | - 「成交量/报价/上架」单位为「单」<br>- 「成交额/充值额」单位为「元」<br>- 统计窗口与「有效期」一致<br>- 统计粒度：每用户、每自然日累计后再汇总（**待确认**） |

#### 4.4.2 限制条件（统计口径过滤器）

> 说明：「选填，多个条件取交集，不选则全量。」每一项内部**取并集**（多选）。

| 序 | 字段 | 控件 | 选项 | 备注 |
| --- | --- | --- | --- | --- |
| 1 | 场次 | 多选 checkbox | OPPO 厂家、vivo 厂家、小米厂家、话机世界、零售 KA、运营商 | **原型中出现两个「小米厂家」，需确认是否为「小米之家」或其它场次，下文统一去重** |
| 2 | 品类 | 多选 checkbox | 手机、平板、手表、手环、笔记本、耳机、运动相机、数码相机、其他 | 选「手机」时通常会联动「品牌」可见列表（**待确认**） |
| 3 | 品牌 | 多选 checkbox | OPPO、vivo、小米、苹果、华为、荣耀、一加、iQOO、红米、其他 | — |
| 4 | 机型 | 弹窗多选 | 点击「+ 活动机型」唤起机型选择弹窗 | 弹窗内支持按品牌筛选 + 关键词搜索；已选机型以 tag 形式回显在主表单中，每个 tag 可删除 |
| 5 | 成色 | 多选 checkbox | 充新、靓机、小花、大花、外爆、内爆 | — |
| 6 | 单价（元） | 数字输入框 × 2 | `[ 左值 ]（含） — [ 右值 ]（含）` | 整数或最多 2 位小数；左 ≤ 右；任一为空表示该方向不限 |

**交互细节**：

- 每个子条件后有「多选取并集」的小字提示，需保留
- 至少一个子条件被勾选时，需在右侧出现一个「清空全部限制条件」的次要操作（**建议补充，原型未画**）
- 「机型」选择弹窗中：
  - 弹窗标题：「选择活动机型」
  - 左侧品牌树，右侧机型卡片
  - 顶部搜索框（按机型名称模糊匹配）
  - 底部：「已选 N 项 / [清空] / [取消] / [确定]」
  - 单次最多选 200 个机型（**待确认**）

### 4.5 奖励设置

| 项 | 说明 |
| --- | --- |
| 控件 | 表格 + 「+ 增加奖励区间」按钮 |
| 必填 | ✓ |
| 公式 | `y = ax + c`，其中 `x` 为活动目标值，`m ≤ x ≤ n`，`c` 为常数 |

**表格列**：

| 列 | 控件 | 校验 |
| --- | --- | --- |
| `a` | 数字输入框 | 必填；最多 2 位小数；允许负数？（**待确认**，建议仅允许 ≥ 0） |
| `c` | 数字输入框 | 必填；最多 2 位小数 |
| `m`（左闭） | 数字输入框 | 选填，**为空写「/」**表示无下限；整数；与同表其它区间不允许重叠 |
| `n`（右闭） | 数字输入框 | 选填，**为空写「/」**表示无上限；整数；`m ≤ n`；与其它区间不允许重叠 |

**交互细节**：

- 初始默认 1 行空白
- 点击「+ 增加奖励区间」追加一行；每行末尾提供「删除」icon（仅剩 1 行时禁用删除）
- 提交前校验：
  - 多行区间之间不能有「数值重叠」或「数值断档」（**断档是否允许待确认**）
  - 区间需按 `m` 升序展示（保存时后端按 `m` 排序）
- 「活动类型 = 达成-2 个活动目标」时：
  - 奖励设置区块复制两份（奖励设置-目标 1 / 奖励设置-目标 2）
  - 「指定机型多倍计算」时奖励公式增加「倍率」列（**待业务补充字段**）

**计算示例**（用作 PRD 评审对齐用）：

| a | c | m | n | 表达 |
| --- | --- | --- | --- | --- |
| 5 | 0 | / | 9 | x ≤ 9 时，奖励 = 5x |
| 6 | 10 | 10 | 19 | 10 ≤ x ≤ 19 时，奖励 = 6x + 10 |
| 8 | 50 | 20 | / | x ≥ 20 时，奖励 = 8x + 50 |

### 4.6 报名按钮

| 项 | 说明 |
| --- | --- |
| 控件 | 开关（默认：开） |
| 必填 | ✓ |
| 说明 | 「若为开，则需用户点击报名才可计算（有效期内报名即视为参加）」 |

**业务规则**：

- 开：用户必须在「有效期」内主动点击「报名」按钮才会被纳入活动统计；未报名用户的行为不计 `x`
- 关：「有效期」内所有命中目标人群 + 限制条件的行为都计入 `x`，无需报名

### 4.7 有效期

| 项 | 说明 |
| --- | --- |
| 控件 | 日期范围选择器（含时分秒，精度到秒） |
| 必填 | ✓ |
| 校验 | - 开始时间 ≥ 当前时间 + 5 分钟（**待确认**）<br>- 结束时间 > 开始时间<br>- 最长跨度不超过 90 天（**待确认**）<br>- 同一目标人群下，活动有效期不允许与已上线活动重叠（**待确认**） |

### 4.8 活动进度展示

| 项 | 说明 |
| --- | --- |
| 控件 | 开关（默认：关） |
| 必填 | — |
| 联动 | 开启后展开下方「展示配置」表单；关闭时隐藏并清空配置 |

#### 4.8.1 展示配置（开关开启时必填）

> 说明文案：「若有多个样式，则当用户实际完成情况 > 目标值时，顺序展示下一样式，直到最后一个停留至活动结束。」

**表格列**：

| 列 | 控件 | 校验 |
| --- | --- | --- |
| 展示顺序 | 数字（系统按表格行序自动写入，从 1 递增，只读） | 行间拖拽排序可调整顺序 |
| 奖励 icon 文案 | 富文本 / 文本输入 + icon 上传（**待确认是文案还是含 icon**） | 文本：1 ~ 20 字；icon：仅支持 png/jpg，≤ 200KB |
| 活动目标目标值 | 数字输入框 | 整数 ≥ 0，行内需严格递增（下一行 > 上一行）|

**交互细节**：

- 默认 1 行
- 「+ 增加展示样式」追加一行；行末有「删除」icon
- 展示逻辑：用户实际完成值 `x` 命中区间 `[当前样式目标值, 下一样式目标值)`，前端展示当前样式
- 达到最后一行目标值后，前端定格在最后一个样式直至活动结束

## 5. 交互细节

### 5.1 活动类型联动

| 活动类型 | 「活动目标」区块 | 「奖励设置」区块 |
| --- | --- | --- |
| 达成-1 个活动目标 | 1 组 | 1 组 |
| 达成-2 个活动目标 | 2 组（目标 1 / 目标 2） | 2 组（分别匹配目标 1 / 目标 2）|
| 达成-指定机型多倍计算 | 2 组，且要求**限制条件完全一致**，仅「机型」可不同 | 2 组 + 倍率字段（**待业务补充**）|

**校验**：「指定机型多倍计算」提交前，比对两组限制条件中 1~3、5、6 项是否完全一致，不一致拦截并 toast：「指定机型多倍计算下，两组活动目标除「机型」外的限制条件必须保持一致」。

### 5.2 全表单联动 / 校验时机

- **失焦校验**：输入类字段失焦立即校验
- **提交校验**：点击「提交」时整表校验，错误字段红框 + 锚点定位到第一处错误
- **必填红色星号**：原型中以红色 `*` 标识，需在所有必填项前保留
- **保存中态**：「提交」按钮变 loading，期间禁用所有表单操作

### 5.3 字段说明文案样式

- 灰色（#999）小字号（12px），左缩进与字段值对齐
- 例如「2 个活动目标取交集……」「多选取并集」「（含）」等说明保留原文案

### 5.4 状态保留 / 草稿（建议补充）

> 原型未提及，建议产品评审决策：
> 是否提供「保存草稿」入口？建议提供，避免长表单填一半被打断丢失数据。

## 6. 业务规则汇总

### 6.1 奖励发放计算

1. 实时（**或 T+1，待确认**）统计每个参与用户的活动目标值 `x`，按限制条件过滤行为
2. 根据 `x` 命中的区间取出对应的 `(a, c)`，计算 `y = ax + c`
3. 活动结束后，按 `y` 完成最终核算 → 奖励发放（具体发放渠道、节奏在「奖励发放」需求里另写）

### 6.2 「达成-2 个活动目标」逻辑

- 设两个目标的实际完成值分别为 `x₁` / `x₂`
- 用户必须同时满足 `x₁ ∈ [m₁, n₁]`、`x₂ ∈ [m₂, n₂]` 才有奖
- 实际发奖 `y = y₁ + y₂`（**待确认是相加、取最大、还是其它聚合方式**）

### 6.3 「达成-指定机型多倍计算」逻辑

- 两组目标公用大部分限制条件，仅「机型」不同
- 命中「指定机型」时该笔行为按倍率叠加进入 `x` 累计
- 倍率字段、计算细节由业务侧补充

### 6.4 活动状态机

| 状态 | 触发条件 | 可执行操作 |
| --- | --- | --- |
| 草稿 | 保存草稿（如支持） | 编辑、删除 |
| 待开始 | 提交成功且当前时间 < 开始时间 | 编辑（部分字段）、撤销 |
| 进行中 | 当前时间在有效期内 | 查看、强制终止 |
| 已结束 | 当前时间 > 结束时间 | 仅查看、查看核算结果 |
| 已终止 | 运营手动终止 | 仅查看 |

> 「进行中可编辑哪些字段」需单独评审（建议仅允许编辑「展示配置」「规则链接」，其它字段冻结）。

## 7. 异常 / 边界处理

| 场景 | 处理 |
| --- | --- |
| 上传名单中存在不存在的用户 | 阻断提交，下载错误明细 |
| 奖励区间数值重叠 | 实时校验，标红提示「奖励区间不能重叠」 |
| 奖励区间存在断档（`n₁ + 1 < m₂`）| 弹窗提示并由运营确认（**待确认是否允许断档**）|
| 规则链接 404 / 无效 | 提交时校验 URL 格式即可，不做存活性探测；上线前由运营自行验收 |
| 限制条件全部为空 | 默认全量，前端给出 toast 二次确认「未设置任何限制条件，将对全量数据生效」 |
| 「报名按钮 = 开」但用户未报名 | 前端展示「未报名」状态，所有行为不计入活动统计 |
| 「活动进度展示 = 开」但展示配置为空 | 提交时校验拦截 |
