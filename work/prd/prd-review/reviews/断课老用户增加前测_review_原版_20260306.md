# PRD Review：断课老用户增加前测

> 版本：v5 | PRD 类型：🟢快速验证 | Review 深度：标准 | 日期：2026-03-06

## 门禁判断

**⚠️ 需在 v5 上修改（方向没变）**

交互设计整体可行，但实验组 2 的交互方案缺失，且有几处细节需要补充才能交付研发。

## 各维度评价

### 1. 场景还原

- **判断**：⚠️
- **评价**：主流程为"用户打开 APP → 欢迎页（3s）→ 答题（3 题）→ 落地页 → 点击领取 → 跳转加微页"，整体走得通。但 PRD 中提到 AB 实验有 3 个实验组，实验组 2 为"前测答题（1 个题目）+营销落地页"，没有说明具体展示哪道题目以及对应的交互流程。此外，用户中途退出（如答到一半退出、kill APP）的处理逻辑未说明。
- **领导可能会问**："实验组 2 的 1 题方案研发怎么做？你自己写清楚了吗？"
- **改进思路**：补一份实验组 2 的交互流程，包含：展示哪个题目、是否有欢迎页、落地页文案内容。补充各种退出场景的处理策略。

### 2. 交互逻辑自洽

- **判断**：⚠️
- **评价**：3 题版本的分支逻辑清晰——问题 2 选"基础巩固"跳 Q3.1，选"拓展拔高"跳 Q3.2，没有逻辑断裂。按钮状态（未选中不可点击 + toast 提醒）也合理。但有两个点不清楚：1）问题 1 用户修改年级后，这个信息是否回写用户档案；2）用户的答题选择是否上报并传递给 CC，PRD 的数据需求部分只写了曝光和点击的埋点，没有答题结果的上报。
- **领导可能会问**："用户答的内容 CC 看得到吗？"
- **改进思路**：明确年级变更的处理方式。在数据需求中增加答题结果上报的说明，并关联到 leads 信息供 CC 使用。

### 3. 与 v1 方向一致

- **判断**：✅
- **评价**：v1 方向是通过前测流程提升断课用户的广告曝光率和参与度，进而提升析出率。v5 的交互设计——欢迎语引入 → 问题归类用户现状 → 痛点唤起 → 落地页转化——忠实落实了这个方向。

### 4. 设计一致性

- **判断**：⚠️
- **评价**：APP 中已有新用户前测流程，应复用相同的前端组件（问题卡片、选项按钮、进度指示等）。PRD 未说明是复用还是重新开发。另外 PRD 提到"文案可在 luban 配置"但未给出配置结构。
- **领导可能会问**："这个和新用户前测是同一套组件吗？"
- **改进思路**：明确复用新用户前测组件，说明差异点。luban 配置 schema 可在 v9 补充。

### 5. 交互层待决策点

- **判断**：⚠️
- **评价**：以下待决策点需要明确：
  1. 前测流程与现有首页召回弹窗的关系——两者是否同时展示？如果都展示，用户体验偏重
  2. 各实验组落地页文案不同（实验组 1 个性化文案 vs 实验组 3 "寒假提升礼包"），是有意设计还是未统一？会影响实验归因
  3. 实验周期预估——10% 流量跑多久能置信？PRD 写了"需要商分估算"但没有结论
- **改进思路**：说明前测和弹窗的优先级关系。统一落地页文案或明确文案差异是独立变量。补充实验周期的初步预估。

## 修改优先级

1. **实验组 2 交互流程补充**（必须）
2. **中途退出处理策略**（必须）
3. **前测与召回弹窗的关系说明**（建议）
4. **答题结果上报给 CC**（建议）
5. **落地页文案统一或说明差异原因**（建议）

## 给你的建议

问题分析做得比较扎实，数据拆解到了分点位粒度，用户调研也做了 70 个样本，这些是好的。AB 实验考虑了 CC 人效承接、调整了流量比例，说明有全链路意识。主要需要加强的是 v5 的交互完整度——每个实验组都应该有完整的交互说明，让研发看完能直接排期。
