# PRD Review：断课老用户增加前测

> 版本：v5 | PRD 类型：🟢快速验证 | Review 深度：标准 | 日期：2026-03-06

---

## Review 思考过程

1. **问题概括**：断课老用户析出率只有 3%，主因是广告曝光率低（41%）且 CTR 低，缺少一条有效的主动召回路径。

2. **方案概括**：在断课用户打开 APP 时用前测问卷替代分散的广告位，通过更高覆盖率（目标 80%）和更有参与感的互动方式提升析出率，用 AB 实验验证效果。

3. **领导第一反应会挑战什么**：
   - 前测通过率 50%-70% 的假设哪来的？断课用户和新用户心理状态不同，新用户前测 80%+ 不能直接类比
   - 实验组 2 说"1 个题目"，具体展示哪个题？PRD 没写
   - 3 个实验组的落地页文案不同（个性化 vs 通用 vs 寒假礼包），这是不是混淆变量？

4. **v5 维度快速扫描**：
   - 场景还原：主流程走得通，但冷启动逻辑、app kill 后的行为有模糊
   - 交互逻辑自洽：3 题版本逻辑清晰，1 题版本没有交互说明
   - 与 v1 一致：一致
   - 设计一致性：需确认是否复用新用户前测组件
   - 待决策点：有几个需要明确的点

5. **门禁判断**：⚠️ 方向对，但有几处交互细节必须补充后才能交付开发

---

## 门禁判断

**⚠️ 需要补充后可推进到 v9**

方向没问题——用前测替代分散广告位来提升曝光和参与度，逻辑成立。但有 **3 个交互层面的硬伤** 必须在进 v9 前补齐（见下文维度 1、2），否则研发会卡你。

## 各维度评价

### 1. 场景还原

- **判断**：⚠️
- **评价**：3 题版本的主流程（打开 APP → 欢迎页 3s → 3 道题 → 落地页 → 领取 → 加微）走得通，但有以下场景没有说清楚：

  **a) 实验组 2（1 题版本）的完整流程缺失。** PRD 只在 AB 表格里提了一句"前测答题（1 个题目）"，但没有说明：展示哪个题？是固定展示问题 2 还是随机？欢迎页还有吗？落地页文案和实验组 1 一样吗？——研发看到这里会停下来问你。

  **b) 用户中途退出的处理不完整。** PRD 写了"叉掉后 90 天内不再展示"，但没有区分几种退出场景：
  - 欢迎页期间退出（还没答题）→ 下次进 APP 重新展示？
  - 答到第 2 题退出 → 下次是从头开始还是接着上次的？
  - 直接 kill APP → 算不算"叉掉"？

  **c) 与现有召回弹窗的冲突。** 现在断课用户已经有首页召回弹窗（CTR 20-25%），加了前测后，弹窗还展示吗？如果都展示，用户打开 APP 先看前测再看弹窗，体验会比较重。PRD 没有说明前测和现有弹窗的优先级关系。

- **领导可能会问**："实验组 2 的 1 题到底是哪题？你自己想清楚了吗？"
- **改进思路**：
  1. 补一张实验组 2 的完整交互流程图，明确哪个题、欢迎页有没有、落地页文案
  2. 补一个"中途退出"的状态表：每种退出场景对应什么处理策略
  3. 加一段说明前测与现有召回弹窗的关系——建议前测展示期间屏蔽首页召回弹窗，避免双重打扰

### 2. 交互逻辑自洽

- **判断**：⚠️
- **评价**：3 题版本的分支逻辑清晰（Q2 选择 → 分叉到 Q3.1/Q3.2），这部分没问题。但有两个逻辑点需要确认：

  **a) 问题 1 的年级变更结果如何处理。** PRD 说"默认压中用户年级"，用户可以改。但改完之后呢？这个信息只影响落地页文案（"x 年级"），还是会回写到用户档案？如果用户把年级从 3 改成 5，后续 CC 联系时看到的是新年级还是老年级？

  **b) 前测答题数据的上报和使用。** 用户选了"基础巩固"+"跟不上学习进度"，这些信息除了影响落地页展示，会传递给 CC 吗？如果 CC 拿到了这些信息，在外呼时就能更有针对性。PRD 的数据需求部分只有埋点曝光/点击，没有提到答题结果的上报和流转。

- **领导可能会问**："用户的答题数据 CC 能看到吗？如果 CC 都不知道用户选了什么，那这些题不就白问了？"
- **改进思路**：
  1. 明确年级变更是否回写用户档案，加一行说明
  2. 在数据需求部分补充：用户的答题选择结果需要上报，并关联到 leads 信息，CC 外呼时可见。这是一个能显著提升 CC 转化效率的点，值得做

### 3. 与 v1 方向一致

- **判断**：✅
- **评价**：v1 的核心方向是"增加一个主动的、有参与感的召回路径来提升析出率"，v5 的前测流程设计完整地落实了这个方向。问题设计参考了 CC 挖需话术和竞品，节奏合理（欢迎语 → 现状归类 → 痛点唤起）。

### 4. 设计一致性

- **判断**：⚠️
- **评价**：APP 内已有新用户前测流程，断课用户前测应该尽量复用同一套组件（问题卡片、选项按钮、进度条等），避免重复开发。PRD 没有明确说明是复用还是新做。另外，luban 配置结构只提了"以上问题的文案可在 luban 配置"，但没有给出具体的配置 schema，研发可能需要你补充。
- **改进思路**：加一句说明复用新用户前测的前端组件，差异点在于文案和跳转逻辑。luban 配置 schema 可以放在 v9 细化。

### 5. 交互层待决策点

- **判断**：⚠️
- **评价**：以下几个点 PRD 没有明确决策：
  1. **实验周期和置信度**：PRD 提到"需要商分估算一下"，但 v5 阶段应该有个初步的结论——按 10% 流量大概需要跑多久能出结果？这会影响后续排期
  2. **落地页文案的差异是有意为之还是疏忽**：实验组 1 是个性化文案（含年级+学习目标），实验组 3 是通用文案（"寒假提升礼包"），这个差异如果是有意的，应该说明原因；如果不是，应该统一，否则无法干净地归因"前测"这个变量的效果
  3. **"寒假"过期后的文案更新**：PRD 自己也提到"这个文案随着特殊时段过去需要更换"，但没有给出替换方案。现在已经 3 月了，寒假早过了，如果实验还在跑，用户看到"寒假提升礼包"会觉得奇怪

## 给你的建议

**做得好的地方**：
- 问题分析扎实。70 个用户录音抽样 + 分点位数据拆解 + 竞品分析，能看出来做了大量前期工作。
- AB 实验设计考虑了 CC 人效承接，从 33% 调到 20% 流量，说明你有全链路思维，不是只看自己的漏斗。
- 前测问题的迭代过程（从"问身份+成绩"到"现状归类+价值展示+痛点唤起"）记录在 PRD 里，这个很好，让 reviewer 能看到你的思考路径。

**核心提升点**：
- **实验组之间的差异要干干净净**。现在实验组 1/2/3 除了"有没有前测""题目多少"之外，落地页文案也不同，这会让你后续归因变得困难。如果实验结论是"实验组 1 效果最好"，你没法说清楚是因为前测答题的参与感，还是因为个性化落地页文案更吸引人。建议要么统一文案，要么把文案差异作为明确的第二层实验变量写清楚。
- **v5 的核心是让研发能直接做**。你的 3 题版本写得很清楚，但 1 题版本几乎是空白。如果我是研发，看到"前测答题（1 个题目）"这一句话，会直接找你问：哪个题、什么交互、什么跳转。v5 的目标是研发看完能直接排期，不需要再和你对齐。
