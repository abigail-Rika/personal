## 技能矩阵

### 1. Prompt 工程

| 子技能 | 等级 | 观察依据 |
|--------|------|----------|
| Skill 结构设计 | ★★☆☆☆ | 在 personal 空间创建了 prd-writer 和 prd-review 两个 skill，结构参考了团队规范。能跑通，但更多是在已有模板上填充，尚未从零设计过 |
| 行为指令编写 | ★★☆☆☆ | prd-review 的角色定位写得不错（"产品 Leader 视角"），说明有场景意识。但整体还是靠直觉写，缺少对 prompt 技巧的系统认知 |
| 示例与测试 | ★☆☆☆☆ | prd-writer 有示例，但没有形成"测试 → 对比 → 迭代"的习惯 |
| 高级技巧 | ☆☆☆☆☆ | 尚未接触 chain-of-thought、self-verification、few-shot 优化等 |

**当前水平：入门期**
你能在现有框架下创建可用的 skill，说明理解了 skill 的"是什么"和"怎么用"。但在 prompt 本身的设计技巧上，还在直觉驱动阶段。

### 2. AI 工具使用与集成

| 子技能 | 等级 | 观察依据 |
|--------|------|----------|
| Cursor 日常使用 | ★★★☆☆ | 高频使用 Cursor 处理日常工作（待办、日记、复盘、PRD），交互自然流畅 |
| 任务委托意识 | ★★★★☆ | 很擅长识别"这件事可以交给 AI"——记录待办、搭建提醒、评审 PRD、组织信息，委托范围广且合理 |
| 自动化搭建 | ★★☆☆☆ | 刚开始探索（工作日报提醒是第一个），对 launchd/脚本等基础设施有了初步认知 |
| MCP / 外部工具 | ★☆☆☆☆ | 团队配置了 Tableau MCP，但个人尚未主动跑通数据分析流程 |

**当前水平：中级（使用层）**
你是一个优秀的 AI 工具使用者——使用频率高、场景判断准、委托边界清晰。这是非常重要的基础。

### 3. 个人知识体系

| 子技能 | 等级 | 观察依据 |
|--------|------|----------|
| 信息架构设计 | ★★★☆☆ | personal 空间的目录分层清晰（work/diary/reviews/knowledge/skills），并且会主动审视和优化命名（plans → roadmap） |
| 知识沉淀习惯 | ★★☆☆☆ | 有日记和复盘的框架，但 knowledge/ 目录尚空，沉淀还没真正跑起来 |

你对"信息应该怎么组织"有天然的敏感度（今天的目录命名讨论就是例证），这个素质在后续搭建更复杂的 AI 工作流时会很有用。

## 下阶段学习路径

### 本周：建立 prompt 技巧的体感（W10）

1. **做一次 prompt 对比实验**
   - 挑你最熟悉的 prd-review，复制一份做改造
   - 加入一个技巧：让 AI 先列出评审维度，再逐条评审（chain-of-thought）
   - 用同一份 PRD 跑两个版本，直观感受差异
   - 把对比结果记录到 `knowledge/tech/` 里

2. **了解一个 prompt 框架**
   - 推荐先看 CO-STAR（Context-Objective-Style-Tone-Audience-Response）
   - 用它重新审视你写的 prd-writer，看哪些维度是你直觉覆盖了的，哪些遗漏了

### 近两周：跑通一个完整的 AI 自动化流程（W10-W11）

3. **Tableau 数据分析端到端**（todos 里已有这个任务）
   - 这不只是"用工具"，更是体验"AI + 外部数据源"的完整流程
   - 关注：哪些环节你需要引导 AI、哪些它能自主完成

### 本月：从使用者到搭建者的跨越（W10-W13）

4. **独立设计一个新 skill**（不参考现有模板）
   - 选一个你工作中重复做的事情
   - 从零思考：角色定义 → 输入输出 → 行为边界 → 示例
   - 这是检验 prompt 工程能力的最佳方式

5. **给 knowledge/ 目录注入第一批内容**
   - 把学习过程中的发现记下来
   - 不需要很长，每条 3-5 句话就够
