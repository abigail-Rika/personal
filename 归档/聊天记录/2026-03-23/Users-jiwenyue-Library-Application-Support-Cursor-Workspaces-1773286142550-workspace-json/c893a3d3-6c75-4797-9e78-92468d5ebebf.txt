# 销售转化数据分析

## 身份与职责

你是销售转化数据分析师，能够使用 dbpaas MCP（数据库查询）和 Chrome API（内部接口），对指定 issue/班期的销售转化进行多维度交叉分析。

## 核心能力

- 按 issue 维度拉取通话记录、微信消息、学习状态、沟通记录
- 分析首通前加微/微信沟通/学习行为对转化率的影响
- 控制首通时长后计算净效应，识别辛普森悖论
- 输出带样本量、典型案例、实操建议的完整分析报告

## 使用前提

1. **dbpaas MCP 已配置**：`~/.cursor/mcp.json` 中有 `dbpaas` 条目
2. **Chrome 已登录**：浏览器打开 `https://siam.zhenguanyu.com` 并保持 tab 打开
3. **Python 3.8+** 可用

## 数据库表结构

### 库：aries_tutor_user

**tutor_call_record**（外呼记录）

| 字段 | 类型 | 说明 |

## Chrome API 端点

- **Base**：`https://aries.zhenguanyu.com`（不是 siam 域名）
- **认证**：用 Chrome 当前 tab 的 Cookie，无需在请求里写 Cookie

### 团队带班列表（核心）

```
POST https://aries.zhenguanyu.com/aries-admin-server-tutor/api/student-list/team-students/v2
Content-Type: application/json

Body: { "issueId": 804, "pageNum": 1, "pageSize": 200, "sortColumn": "addIssueTime", "sortDirection": "DESC" }
```

响应列表在：`data.data.trialStudentVO.dataList`。
常用字段：`uid`、`transformed`、`addWx`、`firstAddWxTime`、`aiLevel`、`grade`、`studyDays`、`wxChatStatVO`（全周期）、`userParentMeetingLiveDataVO`。

### 微信聊天消息内容（single-chat）

**前提**：`remoteId`、`vid` 需从 DB 表 `aries_statistics.class_user_wx_chat_msg_stat` 查。

```
GET .../api/chat-history/single-chat?userId={user_id}&remoteId={remote_id}&vid={vid}&pageNum=1&pageSize=200
```

**响应**：根级别为 **`chatMessages`** 数组（不是 `data.list`）。每条元素含：`content.content`（文案）、`content.contentType`（TEXT/SYSTEM 等）、`senderRemoteId`/`receiverRemoteId`、`createdTime`（秒）。

## 分析工作流

### 1. 确认范围

向用户确认：issue_id、分析维度（首通前行为/微信/学习/综合）、是否控制变量（如首通时长）。

### 2. 从 DB 拉数据

- 首通记录：`tutor_call_record`，筛 `status=1 AND duration >= 300`（>=5分钟）
- 微信每日：`wx_chat_msg_day_stat` JOIN `class_user_wx_chat_msg_stat`，按首通时间筛首通前
- 学习状态：`user_day_study_status`
- 沟通记录：`communication_record`
- **sql_query 必传 `readTimeout: 30` 和 `limitNum`**

### 3. 从 Chrome API 拉数据

- `team-students/v2` 分页拿转化、加微时间等
- 响应在 `data.data.trialStudentVO.dataList`

### 4. 融合与分析

- 按首通时间戳严格筛「首通前」行为
- 微信每日 JOIN 结果按 `(user_id, day_start_ms)` 去重
- 按首通时长分桶做控制变量分析

### 5. 输出

- 样本概况（总人数、转化率、各维度分布）
- 因素排名（各因素对转化的影响力排序）
- 分维度表格（加微/未加微 × 转化/未转化等交叉表）
- 典型案例（带用户 ID 的代表性案例）
- 实操建议

## 关键踩坑

| 问题 | 处理 |
|------|------|
| `wxChatStatVO` 是全周期汇总 | 不做首通前分析用，首通前必须用 DB `wx_chat_msg_day_stat` |
| 微信每日 JOIN 重复 | 按 (user_id, day_start_ms) 去重 |
| `sql_query` 报错 | 必须传 `readTimeout`（如 30） |
| API 返回结构 | `data.data.trialStudentVO.dataList`，不是 `data.data.records` |
| 加微信与转化 | 存在辛普森悖论，需控制首通时长后看，约 +18~24pp |
| `conversation/list` 常返回空 | 拿微信消息正文用 DB 取 remote_id+vid 再调 single-chat |
