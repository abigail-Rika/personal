## Cursor Rules 是什么

Cursor Rules 是 Cursor IDE 提供的一个功能，让你可以**预先给 AI 助手写"指令"**，这样每次对话时 AI 就自动知道你的项目背景、编码规范、技术栈等信息，不用你每次都重复说。

你可以理解为：**给 AI 贴的"备忘录"**。

## 为什么要放在 `.cursor/rules/` 下

Cursor 会自动扫描项目根目录下的 `.cursor/rules/` 文件夹，读取里面的 `.mdc` 文件作为规则。放在别的地方（比如 Downloads），Cursor 不会识别它，就只是一个普通文件。

## `.mdc` 文件的结构

以你刚才那个文件为例：

```
---
description: 数学AI课前端代码库结构、技术栈...   ← 描述，AI 用来判断是否相关
alwaysApply: false                              ← 是否每次对话都生效
---

（下面是正文内容，AI 读到后会作为上下文）
```

头部的 YAML 配置有几个关键字段：

- **`alwaysApply: true`** — 每次对话都会自动加载这条规则（比如你的 `CLAUDE.md` 就是始终生效的）
- **`alwaysApply: false`** — AI 会根据 `description` 判断当前对话是否需要这条规则，相关时才加载

## 你已经在用的 Rules

其实你已经有了。你的三个项目各有一个始终生效的规则：

| 项目 | 规则文件 | 作用 |
|------|---------|------|
| aries-teach | `CLAUDE.md` | 定义你是 AI 能力工程师的协作伙伴，管理 skill/agent |
| personal | `CLAUDE.md` | 定义你是文悦的个人 AI 助理，管理工作和生活 |
| aries | `.cursor/rules/前端技术上下文.mdc` | 刚归档的，提供前端项目背景 |

`CLAUDE.md` 放在项目根目录也是一种 Rules 机制（始终生效），`.cursor/rules/*.mdc` 是更细粒度的按需加载方式。

## 实际效果

拿刚归档的文件举例：当你在 aries 项目里问 AI "例题讲解的代码在哪"，AI 会自动关联到这条规则，知道去看 `src/pages/ai-live-tutor-solo/stages/example/`，而不是一脸茫然地全局搜索。

简单总结：**Rules = 提前告诉 AI 项目背景，让它不用每次从零了解你的项目。**

一节数学AI课的典型流程：
1. **例题讲解**（example）— AI老师逐步讲解例题，配合板书动画
2. **练习题**（exercise）— 学生独立做题，AI实时判断和反馈

- **题目面板**：展示题干、选项

## 业务核心指标

| 指标 | 说明 |
|------|------|
| 首单 ROI / UE | 首次付费的投入产出比和单位经济模型 |
| 体验课转化率 | 体验课用户转为正价课付费用户的比例 |
| 周完习率 | 在课用户每周完成学习的比例（在课留存） |
| 长续率 | 老用户续费下一期课程的比例 |
| 退费率 | 用户申请退费的比例 |

## 用户生命周期

```
获客 → 体验课 → 首单转化 → 在课学习 → 续费/断课

      转化率              周完习率    长续率/退费率
```

- **断课用户**：曾付费但未续费、当前不在课的老用户

# 竞品认知与差异化定位

## 一、Khanmigo（Khan Academy）

- **定位**：基于GPT-4的苏格拉底式AI家教，$4/月
- **核心设计**：永远不给答案，通过追问引导学生自己思考
- **理论框架**：ICAP——确保学生处于"主动建构"而非"被动接收"状态
- **海豚可借鉴**：不给答案的引导设计、学习科学理论指导产品、教师端免费渗透策略

## 二、精准学

- **定位**：名师级一对一家教的"平民化平替"，硬件一次性6699元
- **核心能力**：L4级AI原生——大模型驱动的超拟人语音教学；纳米级知识图谱+千万级题库；1.2-1.8秒响应
- **关键差异**：精准学是"辅导工具"，海豚是"课程产品"——对"不爱学"的学生，缺乏课程引导是致命短板
- **威胁**：AI深度碾压（L4 vs L1-L2），向小学延伸的风险

## 三、探索一对一

- **技术路线差异**：探索走"运行时智能"（26个Agent协作实时决策），海豚走"物料预制+精简运行时"（5离线+3运行时Agent）
- **多角色社交**：卡诺（犯错型）和小美（直觉型）解决安全感、新鲜感、掌控感三个底层问题
- **核心判断**：多角色社交的代价被低估（三人讨论比1v1慢）；海豚最应借鉴的是**动态推题**（P1），而非多角色社交（暂缓）

## 四、海豚差异化优势

1. **中国教材精准适配**（vs Khanmigo的通用内容）
2. **结构化课程产品**（vs 精准学的辅导工具——对"不爱学"的学生有课程引导）
3. **丰富多模态交互形式**（板书/选择/填空/语音/3D等）

## 五、行业趋势判断

- 不卖"AI课"，要卖"个性化学习服务"——前者卖方法，后者卖结果
- 定价锚定"1对1个性化服务"而非"AI软件"——家长心智："我在为谁的时间付费"
- **"真人奢侈化"假说**：当所有人做AI课时，真人教学因稀缺性变得更贵，市场分成真人名师（身份信号）和AI课（务实性价比）两层
- **小切口专项优于校内同步**：AI在精准诊断+个性化训练路径+可量化结果上有绝对优势
- **语文阅读理解是最大蓝海机会**：痛点极高、竞品极少、AI苏格拉底式对话天然适配

# 协作协议

## Token 效率

1. **文件只读一次**：读过的文件内容已在上下文中，不要重复读取同一个文件。如需确认某个细节，用 Grep 精准定位，不要整文件重读。
2. **搜索任务精简化**：先用 Grep 精准搜索关键词，命中后再局部读取。不要一上来就用 explore subagent 做大范围扫描。只有在完全不知道目标在哪时才用 explore。
3. **长对话及时分段**：当一个阶段的结论已经明确，主动建议总结并开新对话，避免上下文膨胀导致每次交互都携带巨量历史。
4. **写文件一次到位**：写完整文件内容，不要先写一个骨架再多次小修补。每次写文件都是大量 Token 输出。
5. **subagent 用完即止**：不要同时启动超过 2 个 subagent，除非任务确实独立且都有明确目标。

## 迭代类需求：先理解现状

做功能迭代时，AI 必须先建立对现有产品的完整认知，再设计新方案。**代码只包含"实现层"信息，缺少"意图层"（为什么这样设计）和"体验层"（用户实际看到和感受到什么）。**

1. **PRD 优先于代码**：理解一个功能，首先读该功能的历史 PRD（在 `海豚AI学/数学AI课/产品功能/` 下按功能分文件夹存放，含一期/二期/三期迭代的图片版 PRD）。PRD 包含设计意图、交互状态、用户反馈和迭代原因——这些信息代码里没有。
2. **代码作为补充验证**：PRD 说明了"应该是什么样"，代码说明了"实际实现成了什么样"。两者结合才是完整的现状认知。
3. **输出理解 → PM 纠偏 → 沉淀为知识**：读完 PRD 和代码后，先输出自己的理解（"我理解这个功能是……"），由 PM 纠偏，确认后再开始设计新方案。不要默认自己已经理解正确。
4. **UI 图是"体验层"的直接来源**：`海豚AI学/数学AI课/UI/` 存放了接近线上效果的 UI 设计图，按设备分 `pad/` 和 `phone/` 两个目录。UI 图告诉你用户真实看到什么——视觉层级、空间比例、元素位置、适配规则。PRD 说"有一个按钮"，UI 图告诉你这个按钮在哪、多大、什么颜色。
5. **三层信息源互补**：
   - **PRD**（意图层）：为什么这样设计、交互状态机、业务规则、用户反馈
   - **UI 图**（体验层）：用户真实看到什么、视觉层级、空间比例、适配细节
   - **代码**（实现层）：实际实现成了什么样、技术约束
   三者缺一不可，只看代码相当于只有 1/3 的信息。
6. **已有资料索引**：
   - 课堂环节 PRD（一/二/三期）：`产品功能/课堂环节/` — 课程流程、小白行为、练习交互、打断机制、导航、任务体系、金币雨、道具系统
   - 讲解过程新增动态交互 PRD：`产品功能/讲解过程新增动态交互/` — v1（方向）和 v5（交互方案）
   - UI 设计图：`UI/pad/` 和 `UI/phone/` — 例题板书、练习题选择/填空、目标页、道具、金币雨、成就结算、挽留弹窗、学习笔记等完整页面

## 执行纪律

1. **不擅自降级**：遇到技术卡点时，用"哪个效果实现不了"来描述，由用户决定降级方案。绝不在用户不知情的情况下简化需求。
2. **编码前自检**：写代码前，先对照需求 Checklist 逐条确认技术方案能满足。写完代码后，再对照 Checklist 确认交付物符合需求。
3. **理解 ≠ 执行**：口头复述需求正确不代表代码会正确。在从"理解"到"代码"之间，增加"checklist 自检"环节。
4. **分步交付**：复杂任务分步做，每步有可验证的产出。不要试图一步到位。

## 沟通规范

1. **用效果语言，不用技术术语**：向用户描述进展或问题时，说"页面上能看到什么 / 看不到什么"，不说技术概念。
2. **卡点即沟通**：遇到任何可能影响最终效果的障碍，立即告知用户，而不是默默绕路。
3. **优先级意识**：始终记住用户最看重什么（通常会明确告知），在做取舍时优先保护核心需求。

# 课程产品机制

## 一、课程基本结构

- **学习节奏**：一周两节课，每节25-30分钟，时间地点灵活
- **课程结构**：每节课2-3个学习目标，每个目标下有三个稳定环节：
  1. **例题讲解**（AI引导作答，脚手架式教学）
  2. **延展练习**（独立答题，做错后AI讲题）
  3. **快问快答**（语音快速互动）
- 推荐平板横屏学习，支持全开麦和半开麦两种模式

## 二、题目体系

### 例题 vs 练习题
- **例题**：AI"小白"引导作答，脚手架式逐步教学
- **练习题**：学生独立答题，做错后AI讲题

### 难度分层
- **基础题 + 进阶题**：基础题全对才出进阶题
- 进阶题解锁条件：基础例题（例1+例2）全对

### 推题策略
- 学的越好题目越多，区间4-6道（压缩后常见3-4道），题目越多金币奖励越多
- 简单题"先做后讲"：例题做对 → 跳过练习题
- 课堂题目不进错题本（因做错会触发讲解直到做对）

## 三、讲解过程新增动态交互方向

### 认知类型 → 交互形态映射

| 认知类型 | 判断标准 | 推荐交互 |
|---------|---------|---------|
| 知识回忆 | 问"是什么" | 选择题 |
| 数值计算 | 问"等于多少"且需留板书 | 填写框 |
| 验算/判断 | 问"对不对" | ✓/× 点选 |
| 简单确认 | 一两个字、不涉及板书构建 | 语音快答（ASR+字符匹配） |
| 逻辑推理 | 问"为什么""怎么想的" | 语音对话（LLM） |

### 三层提效（乘法关系）
- **课程级**：推题策略Bot（P2）
- **题目级**：多问大题格式（P1）
- **子步骤级**：多模态交互（P0，当前重点）

### 实测数据
- 22个子步骤中仅2个必须语音（9%），基础交互覆盖91%
- 中等生目标：从32分钟降至18-20分钟

## 四、游戏化激励

### 金币雨
- 课程最后的激励环节，最高50金币，完成才算完课
- **三种道具**：时间延长、速度增幅、炸弹转化，当天有效

### 成就结算
- 三个等级：零失误大神、基础王者、无敌闪电手
- 跳过的题不计入成就结算

## 五、AI深度评

- **定位**：利用大模型分析课中对话数据，提供多维学情反馈
- **内容**：标题与评星 → 客观数据 → 高光时刻（含视频）→ 学情分析 → 学习笔记
- **发送时机**：课后立即发送 + C端入口
- **排名展示**：排名前15%才展示
- **正确率提升**：强调首答到最终正确率的提升，突出AI辅导价值

# 交互设计原则

完整产品专属文档：`海豚AI学/数学AI课/讲解过程新增动态交互/交互原型设计标准.md`

---

## 第一部分：产品专属规则（23条速查）

### 验证原则
- **真实约束**：脱离真实条件的验证是无效的，必须在真实设备尺寸和视觉语言下验证
- **通道分离**：语音输出和设备端UI是不同通道，展示上必须分离
- **还原度**：原型不能引入真实产品中不存在的元素
- **全平台**：手机和Pad都需要验证

### 交互形态原则
- **形态匹配**：交互形态服务于任务的认知特点，不是默认模板
- **保持教学意图**：交互不能降低原有的考察难度
- **操作成本比例**：操作开销不应超过任务本身的复杂度

### 信息暴露原则
- **不替代思考**：系统不能替用户完成应由他自己完成的思考
- **信息适度**：展示信息不多不少，不能泄露后续需要思考的答案

### 作答反馈原则
- **逻辑自洽**：一个环节内不能出现矛盾的机制（如同时有实时反馈和整体提交）
- **独立思考**：给学生完整的独立作答空间，默认整体提交
- **错误即资源**：答错后由AI讲解，不简单重试
- **反馈深度**：肯定对的、解释错的原因、补充漏的逻辑
- **对比反思**：保留修正过程，不直接覆盖原始答案

### UI交互原则
- **路径无歧义**：一个动作对应一个触发点
- **操作可逆**：任何操作不应把用户带进死胡同
- **心智模型**：交互应顺应用户已有的认知预期
- **物理约束**：原型必须反映键盘弹出等真实环境影响

### 信息架构原则
- **规范一致**：布局遵循产品设计规范
- **信息不丢失**：关键决策和知识点在板书中永久保留
- **视觉简洁**：减少不必要的视觉分割，保持清爽
- **自成体系**：信息区域不依赖外部上下文也能被理解
- **目标先行**：任务目标先出现，再让用户操作

## 第二部分：通用交互原则

> 来源：Don Norman 六原则、Nielsen 十启发式、Laws of UX、Apple HIG、Material Design 3、WCAG 2.2

### A. 教育产品的根本约束

- **认知负荷分离**：交互操作成本（"怎么用"）尽可能低；学习思考成本（"怎么解"）刻意保留。降低前者，保护后者。（Tesler's Law：复杂性只能转移不能消除）
- **渐进披露**：不一次性暴露所有信息。按教学节奏分步展示——题目条件先出、操作区域随之出现、反馈在作答后给出。（Hick's Law + Progressive Disclosure）

### B. 感知与可供性（Don Norman）

- **可供性清晰**：可交互元素外观上让用户知道"这里能操作"
- **示能符明确**：用视觉线索指示"在哪里操作、怎么操作"
- **约束防错**：限制输入类型、限制选择数量，从源头阻止错误
- **映射直觉化**：控件位置和操作方向应与效果在空间或逻辑上对应
- **反馈分三层**：操作层（<100ms即时响应）→ 处理层（<400ms loading）→ 语义层（按教学节奏的AI评价）
- **心智模型一致**：设计与用户已有的交互认知一致

### C. Nielsen 可用性检查清单

| # | 检查项 | 通过标准 |
|---|--------|---------|
| 1 | 系统状态可见 | 用户知道当前在第几步、系统在做什么 |
| 2 | 匹配真实世界 | 用学生听得懂的语言，数学符号和课本一致 |
| 3 | 用户控制与自由 | 误操作可撤销、键盘可收起、选错可重选 |
| 4 | 一致性 | 同类交互行为跨环节一致 |
| 5 | 错误预防 | 约束优于提示——数字键盘只有数字、单选自动互斥 |
| 6 | 识别而非回忆 | 题目保持可见、板书保留历史步骤 |
| 7 | 美学极简 | 每个视觉元素都必须有存在理由 |
| 8 | 错误恢复 | 错误提示说人话、指明具体错在哪 |

### D. 认知心理学法则（Laws of UX）

- **Miller's Law**：一屏独立信息单元 ≤7个，超过就分组/分步
- **Von Restorff**：当前操作区域视觉差异化（高亮是预算，不能处处用）
- **Hick's Law**：一次只问一个问题、选项不超过5个
- **Fitts's Law**：触控目标 ≥44×44pt；主按钮在拇指热区内
- **Goal-Gradient**：让学生感知进度（第几步/共几步）
- **Peak-End Rule**：课中高光时刻和课程结尾必须重点打磨
- **Doherty Threshold**：系统响应 <400ms 保持心流

### E. 平台规范约束

- 触控安全区：所有可交互元素最小 44×44pt，远离刘海/药丸区域
- 对比度：大文本 ≥3:1、小文本 ≥4.5:1
- 键盘适配：弹出时内容上推、顶部有"完成"按钮、不遮挡关键内容
- 按钮层级：用 Filled/Tinted/Plain 区分重要程度
- 动画时长：0.2-0.35s 区间

## 5分钟快速审查流程

1. **教育约束**：交互有没有替学生做了本该自己完成的思考？信息暴露恰到好处？
2. **操作直觉性**：学生第一次看到界面，不听语音引导，能否知道该做什么？
3. **认知负荷**：一屏信息量是否超载？是否需要分步/分组？
4. **反馈完备性**：操作有即时反馈？处理中有loading？结果有具体解释？
5. **平台适配**：按钮够大？拇指够得到？键盘会遮挡？
6. **一致性**：和产品中其他同类交互一致吗？

# 学习环节 UI 规范

> 来源：`海豚项目/UI规范/学习环节/` 设计稿
> 学习环节是海豚AI课的核心教学场景，有独立于App通用规范的专属组件和布局体系。

---

## 一、布局框架

### 1. Phone 端

#### 1.1 横屏（核心场景）

**基础框架 — 双栏布局**：
- **左侧**：内容区域（题目、文章、板书等），占比约 40%-70%
- **右侧**：板书/互动区域（AI板书、学生交互），占比约 30%-60%
- **顶部**：导航栏（返回 + 标题/进度 + 积分/操作）
- **底部**：操作栏（固定高度，放置主要操作按钮）

布局约束：
- 内容区最小宽度约 40%
- 板书区根据内容弹性伸缩，最小 196px，最大 768px
- 底部操作栏固定高度

**基础框架 — 面板叠加布局**：
- 面板可从侧方滑入或浮层覆盖在内容区之上
- 板书区域最低高度约 96px
- 适用于需要临时展示额外信息的场景
- 交互方式为内容面板叠加覆盖

**特殊框架**：
- 全屏模式，不分左右栏
- 适用于特殊教学环节（如视频播放、大面积图形展示）
- 内容区占满整个屏幕，底部操作栏可隐藏

#### 1.2 竖屏

**通栏框架**：
- 全宽纵向布局，导航在顶部
- 内容区域可纵向滚动
- 底部固定操作栏

**卡片框架**：
- 卡片式内容展示
- 适用于阅读类、展示类环节

### 2. iPad 端

#### 2.1 横屏

**基础框架**：
- 与 Phone 横屏类似但更宽敞
- 左右分区更清晰，间距更大

**两栏大框布局**：
- 两栏并列，各栏内可放置大面积内容（如文章 + 板书）
- 板书区域可包含选项卡（题目/文章/板书切换）

**三栏通知栏布局**：
- 三栏结构用于需要同时展示多类信息的场景

**特殊框架（三栏通知栏 + 通栏布局）**：
- 适用于信息密集型环节
- 可同时展示导航通知 + 主内容 + 侧栏信息

#### 2.2 竖屏

- 两栏大框的竖屏适配
- 三栏通知栏的竖屏适配
- 整体按竖向重排，内容区域纵向堆叠

## 二、适配规则

### 核心适配原则

| 目标设备 | 适配策略 |
|----------|----------|
| **Phone 横屏** | 设计基准（1x），所有组件以此为标准尺寸 |
| **iPad 横屏** | 基于 Phone 端 **1.5 倍**放大 |
| **竖屏（Phone/iPad）** | 根据屏幕宽度**等比放大** |

### 基础按钮适配

- **横屏适配**：保留微页面的通用页面，基于 Phone 端 1.5 倍放大；组件系统按照客户端效果，保持 Phone 尺寸自适应
- **竖屏适配**：根据屏幕宽度等比放大

### iPad 样式说明

- iPad 竖屏以 1024 宽度为基准
- iPad 横屏以 1.5 倍示意（相对 Phone）

## 三、环节组件

> 组件化原则：将**稳定且具备通用性的原子和分子**做成组件，目的是**统一和提效**。
> 已组件化内容：导航、按钮、选择题、拖拽题、标签、图标、翻页器。

### 3.1 Button（学习环节按钮）

区别于 App 通用按钮，学习环节按钮有独立的视觉风格。

#### 按钮类型

| 类型 | Phone 横屏 | iPad 横屏 | 说明 |
|------|-----------|-----------|------|
| 主要按钮 | 实心填充（紫/橙，随学科色） | 尺寸放大 | 核心操作 |
| 次要按钮（描边） | 描边线框 | 尺寸放大 | 次要操作 |
| 次要按钮（浅底） | 浅色填充底 | 尺寸放大 | 辅助操作 |
| 幽灵按钮 | 浅色描边、文字跟随学科色 | 尺寸放大 | 可选操作 |
| 组合按钮 | 文字 + 右侧箭头图标 | 尺寸放大 | 引导性操作（如"继续学习 →"） |

#### 按钮状态

三种状态：**默认** → **点击**（按下高亮） → **禁用**（整体置灰）

#### 横屏尺寸规范

- 基础按钮：button 内心要素最大宽度 68px，字号按需加小圆图标
- 特殊按钮可容纳超长文案，文字超 70% 后截断适配
- 组合按钮：按钮尺寸 32px，文字 + 箭头图标组合

### 3.2 导航（学习环节导航）

学习环节导航有四套布局变体：

#### 竖屏导航

**基础导航（新增积分）**：
- 返回按钮（<） + 右侧积分（金币图标 + 数字）
- 标题可选展示

**基础导航 + 标题**：
- 返回 + 居中标题 + 右侧积分

#### 横屏导航

**基础导航（新增积分+跳过）**：
- 返回 + 标题 + 积分 + 跳过按钮

组合元素说明：

| 元素 | 说明 |
|------|------|
| 返回 | 左侧「<」图标，固定 |
| 积分样式 | 金币图标 + 数字（如"2333"），右上角位置 |
| 标题 + 积分样式（标题+翻页器的总字数限制） | 标题字号 16pt，字号不超过可用宽度 7 个汉字 |
| 进度条 | 线性进度指示 |
| 翻页器 | XX/XX 格式（如 05/06） |
| 跳过 | 文字按钮"跳过"，右侧位置 |
| 副标文字 | 标题下方副标题 |

**个性化导航样式**：
- 支持导航栏下方展示任务提示文字（如"小明同学是否去过很多不同的城市游玩？请选择你觉得推荐的地方吧"）
- 提示文字区域有独立背景色和间距

#### iPad 导航适配

- iPad 竖屏（1024 宽度示意）
- iPad 横屏（1.5 倍示意）
- 横屏适配：保留微页面通用页面，基于 Phone 端 1.5 倍放大；做到来和端效果保持 Phone 尺寸自适应
- 竖屏适配：根据屏幕宽度等比放大

### 3.3 题目选项

#### 选择题

**Phone 横屏**：
- 默认态：灰底白字圆角卡片，左侧序号（A/B/C/D）+ 选项文案
- 选中态：底色加深
- 答对：绿色描边 + 绿色勾（✓）
- 答错：红色描边 + 红色叉（✗）

**iPad 横屏**：
- 结构相同，尺寸放大
- 选项卡片可容纳更长文案（多行自适应）

#### 判断题

**Phone 横屏**：
- 两个按钮：「正确」和「错误」
- 默认态：灰底 + 图标
- 选中态：背景高亮
- 结果态：正确→绿色填充+勾，错误→灰色+叉

**iPad 横屏**：
- 结构相同，按钮尺寸放大

#### 题目选项适配说明

- 选择题选项高度不固定，横横页面布局适应顺序正常
- 判断题和选择题属于不同题目环节
- iPad 端基于手机端截屏大小，不受拉伸宽度影响

#### 颜色

- 选项底色：`#E3E3E3`（默认）
- 选中正确：绿色系
- 选中错误：红色系
- 颜色不固定，根据学科色进行调整（对标 XY 轴上下显示）

### 3.4 拖拽填空

#### Phone 横屏 / iPad 横屏

四种填充状态：

| 状态 | 视觉表现 |
|------|----------|
| 拖拽有内容 | 橙底白字（实心填充，学科色） |
| 置空 | 米色/浅黄底，无文字 |
| 已填 | 橙色描边 + 橙色文字（学科色） |
| 未填 | 浅底 + 虚线边框 |

#### 适配与颜色

- 颜色不固定，根据学科色进行调整
- 边制基础规则：投影、圆角按原始大小不固定，照横填完整保持主题风格及色调
- iPad 以 Phone 为基本横比放大

### 3.5 翻页器

#### 显示格式

`XX/XX`（如 01/06、05/06、06/06）

左右箭头按钮 + 中间页码。

#### 按钮状态

| 状态 | 说明 |
|------|------|
| 首页 | 左箭头禁用（灰色），右箭头可用 |
| 中间页 | 左右箭头均可用（学科色高亮） |
| 末页 | 左箭头可用，右箭头禁用（灰色） |

#### 翻页 Button 状态

三种状态：**默认**（学科色）→ **点击**（深色） → **禁用**（灰色）

#### 适配说明

- 颜色不固定，根据学科色进行调整
- 翻页器属于导航的一部分，适配规则同导航一致

### 3.6 图标（学习环节 Icon）

#### 颜色语义

| 颜色 | 含义 | 示例 |
|------|------|------|
| 蓝色 | 常规类 | 写作主题、写作技法、我的行文 |
| 黄色 | 用户内容类 | 初始案例卡、写作技巧/互评方案/编辑改善、提示标识 |
| 橘色 | 反馈类 | 精选点评、写作点题、课文题跟、练写分析 |

#### 适配说明

- iPad 适配以竖屏为基本横比放大，iPad 横屏基于 Phone 端 1.5 倍放大
- 颜色会根据学科色变化
- 讲解入口 icon（大圆形）：颜色 + 圆图标，需根据学科和页面背景色调整

## 四、学科色体系

### 品牌色

`#6072FF`（紫蓝色，RGB: 124, 114, 252，HSB: 246, 55, 100）

### 学科色定义

| 学科 | 主色 | 色系 | RGB 参考 |
|------|------|------|----------|
| 语文 | `#FF5F33` | 暖橙红 | 255, 61, 61 / HSB: 13, 63, 90 |
| 数学 | `#1A02FF` | 紫色 | 0, 148, 253 / HSB: 265, 85, 100 |
| 英语 | `#FF8D00` | 橙色 | 255, 136, 0 / HSB: 35, 92, 100 |
| 物理 | `#3C6B5C` | 蓝绿 | 10, 54, 82 / HSB: 145, 55, 97 |

### 学科辅助色

| 类别 | 色系 | 说明 |
|------|------|------|
| 文科色 | 暖色（橙色系） | 用于语文等文科场景 |
| 理科色 | 冷色（待补充） | 用于物理等理科场景 |

### 基础色板

每个学科有完整的 **6 级渐变色板**（从浅到深），用于不同层级的背景、文字、强调等：

- 语文：橙色渐变（浅杏 → 深橙红）
- 数学：紫色渐变（浅紫 → 深紫）
- 英语：蓝绿渐变（浅青 → 深蓝绿）
- 物理：蓝色渐变（浅蓝 → 深蓝）

### 颜色分层模型（从底层到顶层）

| 层级 | 名称 | 说明 |
|------|------|------|
| 1 | 背景层 (Background) | 页面整体背景色，随学科色渐变 |
| 2 | 内容层-文科色 (Content) | 内容区域的填充色，区分 Card、文本区、高亮区等 |
| 3 | 内容层-学科色 (Content) | 学科专属的内容强调色 |
| 4 | 全局控制层 (Global Control) | 顶部导航栏色、按钮色、进度条色等 |

| 用途 | 字重 | 字号 |

| 正文字体 | Regular | 16pt |

- 选项文案（如 A/B/C/D 选项）：Regular 14pt，次要文字色

- 基本复用横屏的两栏/三栏结构，按竖向重排
- 特殊框架保持独立适配

## 四、通用组件：导航栏

### APP 导航

- **高度**：状态栏 + 导航栏（Nav 高度 ≈ 56px）
- **标题**：居中显示，最多 10 个汉字，字号 16-17pt
- **返回按钮**：左侧「<」图标

### 导航栏变体

1. 纯返回（无标题）
2. 返回 + 标题
3. 返回 + 标题 + 右侧文字按钮
4. 返回 + 标题 + 右侧图标按钮
5. 返回 + 搜索栏
6. 返回 + 标题 + 多个右侧操作
7. 大小字混合标题

### 平板/横屏导航

与手机导航结构一致，但宽度拉伸，标题和操作区域保持相对位置。

### 小程序导航

底部 Tab 切换样式，标题居中，左侧无返回按钮。

## 五、通用组件：按钮

### 按钮层级

| 层级 | 名称 | 用途 |
|------|------|------|
| 主要 Button | 实心填充 | 页面核心操作（每个页面最多 1 个） |
| 次要 Button | 描边/线框 | 次要操作 |
| 幽灵 Button | 透明底+描边 | 可选操作 |
| 文字 Button | 纯文字 | 辅助操作 |

### 按钮状态

三种状态：**默认** → **点击**（按下） → **禁用**（置灰不可点击）

### 按钮尺寸

| 尺寸 | 说明 |
|------|------|
| 大 | 全宽或大面积操作 |
| 中 | 常规操作 |
| 小 | 紧凑空间 |
| 超小 | 行内操作 |

### 按钮颜色

按钮颜色跟随品牌色（`#6075FF` 紫色系），特殊场景使用功能色（橙色、红色等）。

### 核心指标

| 指标 | 定义 | 备注 |
|------|------|------|
| 析出率 | 从广告曝光到体验课购买的转化 | 受投放素材、落地页、前测等影响 |

| 周完习率 | 在课用户每周完成学习的比例 | 分"全完习"(55-60%)和"到习完习"(90-92%) |
| 长续率 | 老用户续费下一期的比例 | 衡量长期留存 |
| 退费率 | 用户申请退费的比例 | 防护指标 |

## 三、CC 团队业务详解

### 建联标准

| 阶段 | 操作 |
|------|------|
| 首次建联 | 两次手机号拨号 + 一次工作台外呼（都没接→下一个） |
| 二次跟进 | 两次工作台外呼 + 工作台群发加微短信 |
| 重点跟进 | 以上均未联系上 → 手机发送加微短信 |

### CC 工作流

```
建联（电话接通）
    ↓
加微（电话中确认添加，不挂断后加）
    ↓
挖需（SPIN：现状→痛点→影响→价值）
    ↓
产品介绍（学练补三环节）
    ↓
约习（确定上课时间，工作台标注）
    ↓
微信留痕 + 到课提醒
    ↓
完课后回访
    ↓
转化沟通
```

### 用户分层标签体系

**建联后分层（A/B/C）**：

| 标签 | 条件 |
|------|------|
| A | 有线上/线下学习经验 + 现未报班（或不满意现有班）+ 明确需求 + 购买力强 + 配合度高 + 倾诉欲强。朋友推荐的直接标A |
| B | 互动配合度高，但不完全满足A类条件 |
| C | 互动配合度低，且不满足A类条件 |

**回访后分层（S/A+/B+）**：

| 标签 | 条件 |
|------|------|
| S | 完课后有主动回复动作 + 家长认可 + 孩子喜欢 |
| A+ | 完课后无主动回复，但家长认可、孩子喜欢 |
| B+ | 课后回访不配合，微信不回复，难建立联系 |

**转化后**：考虑 / 不考虑

### 挖需框架（SPIN）

- **S（现状）**：成绩、学科表现、补习经历、走读/住校、作业时间
- **P（痛点）**：基础薄弱还是思维固化？计算板块还是应用板块？
- **I（影响）**：不解决会怎样（落后、厌学、升学压力）
- **N（价值）**：海豚的个性化解决方案如何匹配

### 工作台操作

- 建联记录模板：培优/补差、各科成绩、走读/住校、补习班情况、意向度、约习时间
- 标签管理：建联 A/B/C、回访 S/A+/B+、转化 考虑/不考虑
- 约习时间：工作台勾选确认到习时间

## 一、增长业务板块总览

业务主要流量来源于外部买量（信息流效果广告、直播电商、app直投），市场团队也在探索分销、达人合作等机会。

### 1. 线索获取（Leads 析出）

日常主要关注内部渠道 leads 析出，尤其是端内部分。从三个层面理解：
- **数量**：充分利用所有流量，关注 leads 析出效率
- **抓手**：基于渠道和用户特点设计流程和抓手，平衡用户体验和流程效率
- **质量**：确保析出 leads 质量，不同质量的 leads 适配不同的承接人效和转化形式

### 2. 线索转化（体验流程设计）

两类承接转化模式：**销售** 和 **CC**。

| 维度 | 销售（标准单周） | CC |
|------|----------------|-----|
| 周均人效 | 35-40 | 120-150 |

## 二、增长漏斗

```
市场投放（信息流/直播电商/app直投）
    ↓ 曝光
落地页/电商渠道
    ↓ leads析出（析出率）
体验课购买
    ↓ 分配（按用户质量/年级分给销售或CC）
建联（电话+加微）
    ↓ 加微率 ~95%
约习（安排试听课时间）
    ↓ 到习率
体验课完课
    ↓ 完课率
回访
    ↓ 转化率
首单购买（正价课）
    ↓ 首单ROI / UE
在课学习
    ↓ 周完习率
续费 / 断课
    ↓ 长续率 / 退费率
```

### 核心指标

| 指标 | 定义 | 备注 |
|------|------|------|
| 析出率 | 从广告曝光到体验课购买的转化 | 受投放素材、落地页、前测等影响 |
| 加微率 | 购买体验课后添加微信的比例 | 已达~95%，天花板效应 |
| 到习率 | 约习后实际到课学习的比例 | 受跟进、提醒触达影响 |
| 完课率 | 到习后完成全部学习环节的比例 | 学练补三环节都完成 |
| 转化率 | 体验课用户购买正价课的比例 | 核心北极星指标之一 |
| 首单ROI / UE | 获客成本与首单收入的投入产出比 | 衡量获客效率 |
| 周完习率 | 在课用户每周完成学习的比例 | 全完习55-60%，到习完习90-92% |
| 长续率 | 老用户续费下一期的比例 | 衡量长期留存 |
| 退费率 | 用户申请退费的比例 | 防护指标 |

## 三、CC 团队业务详解

### 建联标准

| 阶段 | 操作 |
|------|------|
| 首次建联 | 两次手机号拨号 + 一次工作台外呼（都没接→下一个） |
| 二次跟进 | 两次工作台外呼 + 工作台群发加微短信 |
| 重点跟进 | 以上均未联系上 → 手机发送加微短信 |

### CC 工作流

```
建联（电话接通）→ 加微（电话中确认添加）→ 挖需（SPIN）→ 产品介绍（学练补）→ 约习 → 微信留痕+到课提醒 → 完课后回访 → 转化沟通
```

### 用户分层标签体系

**建联后（A/B/C）**：

| 标签 | 条件 |
|------|------|
| A | 有学习经验 + 现未报班/不满意 + 明确需求 + 购买力强 + 配合度高。朋友推荐直接标A |
| B | 配合度高，但不完全满足A类条件 |
| C | 配合度低，且不满足A类条件 |

**回访后（S/A+/B+）**：

| 标签 | 条件 |
|------|------|
| S | 完课后主动回复 + 家长认可 + 孩子喜欢 |
| A+ | 无主动回复，但家长认可、孩子喜欢 |
| B+ | 回访不配合，微信不回复 |

**转化后**：考虑 / 不考虑

### 挖需框架（SPIN）

- **S（现状）**：成绩、学科表现、补习经历、走读/住校、作业时间
- **P（痛点）**：基础薄弱还是思维固化？计算板块还是应用板块？
- **I（影响）**：不解决会怎样（落后、厌学、升学压力）
- **N（价值）**：海豚个性化方案如何匹配

### 工作台操作

- 建联记录：培优/补差、各科成绩、走读/住校、补习班、意向度、约习时间
- 标签管理：建联 A/B/C、回访 S/A+/B+、转化 考虑/不考虑
- 约习时间：工作台勾选确认

# 增长业务上下文

> 核心参考文档：[电商增长产品101](https://confluence.zhenguanyu.com/pages/viewpage.action?pageId=924793399) | [海豚电商白皮书](https://confluence.zhenguanyu.com/pages/viewpage.action?pageId=678633072) | [新课建联2.0](https://shimo.zhenguanyu.com/docs/qnvK1x6Bd2llcp00/)

## 一、产品概述

- **产品**：海豚AI学，猿辅导旗下 AI 教育产品，面向 1-9 年级
- **模式**：订阅制，按时长收费，可学任意年级学科
- **核心体验**：学（知识探究）+ 练（小试牛刀）+ 补（定向提升）三环节
- **转化路径**：新用户 → 体验课（5天体验会员）→ 正式会员

---

## 二、增长全链路与核心指标

### 漏斗总览

```
市场投放（信息流/直播电商/app直投）
    ↓ 曝光
落地页 / 电商渠道
    ↓ leads 析出（析出率）
体验课购买
    ↓ 分配（按用户质量/年级分给销售或CC）
建联（电话 + 加微）
    ↓ 加微率 / 首通率
催习
    ↓ day1 到习率
体验课完课
    ↓ day1 完习率 / day2 到习 / 完习率
回访和服务
    ↓ 转化率
首单购买（正价课）
    ↓ 首单 ROI / UE
在课学习
    ↓ 周完习率
续费 / 断课
    ↓ 长续率 / 退费率
```

### 核心指标定义

| 指标 | 定义 | 备注 |
|------|------|------|
| 析出率 | 从广告曝光到体验课购买的转化 | 受投放素材、落地页、前测等影响 |
| 加微率 | 购买体验课后添加微信的比例 | 已达 ~95%，天花板效应 |
| 到习率 | 约习后实际到课学习的比例 | 受跟进、提醒触达影响 |
| 完课率 | 到习后完成全部学习环节的比例 | 学练补三环节都完成 |
| 转化率 | 体验课用户购买正价课的比例 | 核心北极星指标之一 |
| 人头转化率 | 购买正式会员的 leads 数 / 总 leads 数 | |
| GMV 转化率 | 购买正式会员总 GMV / 基准价 / 总 leads 数 | |
| 首单 ROI / UE | 获客成本与首单收入的投入产出比 | 衡量获客效率 |

## 三、组织角色与分工

### 线索获取

日常关注端内 leads 析出，从三个层面理解：
- **数量**：充分利用所有流量，关注析出效率
- **抓手**：基于渠道和用户特点设计流程，平衡用户体验和流程效率
- **质量**：不同质量的 leads 适配不同的承接人效和转化形式

### 线索转化：销售 vs CC

| 维度 | 销售（标准单周） | CC |
|------|----------------|-----|

## 四、CC 业务详解

### 建联标准（SOP）

| 阶段 | 操作 |
|------|------|
| 首次建联 | 两次手机号拨号 + 一次工作台外呼（都没接 → 下一个） |
| 二次跟进 | 两次工作台外呼 + 工作台群发加微短信 |
| 重点跟进 | 以上均未联系上 → 手机发送加微短信 |

### CC 工作流

```
建联（电话接通）→ 加微（电话中确认添加）→ 挖需（SPIN）→ 产品介绍（学练补）→ 约习 → 微信留痕 + 到课提醒 → 完课后回访 → 转化沟通
```

### 挖需框架（SPIN）

- **S（现状）**：成绩、学科表现、补习经历、走读/住校、作业时间
- **P（痛点）**：基础薄弱还是思维固化？计算板块还是应用板块？
- **I（影响）**：不解决会怎样（落后、厌学、升学压力）
- **N（价值）**：海豚个性化方案如何匹配

### 用户分层标签

**建联后（A/B/C）**：

| 标签 | 条件 |
|------|------|
| A | 有学习经验 + 现未报班/不满意 + 明确需求 + 购买力强 + 配合度高。朋友推荐直接标A |
| B | 配合度高，但不完全满足 A 类条件 |
| C | 配合度低，且不满足 A 类条件 |

**回访后（S/A+/B+）**：

| 标签 | 条件 |
|------|------|
| S | 完课后主动回复 + 家长认可 + 孩子喜欢 |
| A+ | 无主动回复，但家长认可、孩子喜欢 |
| B+ | 回访不配合，微信不回复 |

**转化后**：考虑 / 不考虑

### 工作台操作

- 建联记录：培优/补差、各科成绩、走读/住校、补习班、意向度、约习时间
- 标签管理：建联 A/B/C、回访 S/A+/B+、转化 考虑/不考虑
- 约习时间：工作台勾选确认
