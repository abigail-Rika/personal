## 1. 背景与定位

### 1.1 一句话上下文

档案 = 给已购 9 元体验课的家长建立**目标感**、提升 app 体验联动的工具。

### 1.2 定位（最容易被误解，先框死）✅

| 是 / 不是 | 内容 |
|:-:|:-|
| ✅ 是 | 付费后到开始学之间的**目标感载体**——"我家孩子要解决什么问题、用什么解决、看得见的路径" |
| ❌ 不是 | 销售析出工具 |
| ❌ 不是 | v2 AI 销售 0 转体的钩子 |
| ❌ 不是 | 解决电商用户产品认知（那是新人引导的事） |

### 1.3 定位漂移的预警 ⚠️

如果有人提议"档案要做销售破冰物料的强抓手"或"档案要承担电商用户的产品认知建立"——**说明定位被悄悄拉走了**，回到 1.2。详见 `01-讨论纪要.md` D.4。

## 2. MVP 范围

### 2.1 用户 ✅

- **MVP 仅锁定新用户付费路径**（已购 9 元体验课、首次进 app）
- 不覆盖：历史已购、AI 销售析出、未填首诊补建、私域、老带新 → 参 `02-路径插入点分析.md` 第三节

### 2.2 来源路径 ✅（v2 扩展为 3 条）

详见全景图 `demo/档案-路径全景.html`。

| 路径 | 来源 | 档案首诊容器 | 档案插入点 | 完成档案后 |
|:-|:-|:-:|:-|:-|
| **①** | 直投/自然 | **app 端** | 付费 → 进 app → **替换原"销售加微页"** | 已分配→跳微信小程序加微 / 未分配→跳计划页 |
| **②** | 效果广告 | 路径分叉：<br>A. 小程序端（先点档案诊断短信）<br>B. app 端（先下载 app，走路径①） | A：广告→h5 购课→双短信→**小程序档案** → 加微/公众号→进 app→**「确定前测」**<br>B：同路径① | 同对应分支 |
| **③** | 直播 | **小程序端** | 店铺购课→短信激活→h5 注册→**小程序档案** → 加微/公众号→下载 app→**「确定前测」（已做档案）/ 新用户前测→app 档案首诊（未做档案）** | 同上 |

**核心设计原则**：
- 档案 = 付费 → 开始学之间的**目标感建立环节**，三条路径都必经
- 档案首诊**不依赖销售首通**（"档案不作为销售首通的抓手"，详见 §1.2）
- 入口文案做 2 个变体：电商加"欢迎"叙述，直投不加

**「确定前测」是什么** ✅（v2 新增概念）：
路径②③的用户先在小程序完成档案后，下载 app 时会落到一个**轻量补充页**——只确认"年级 + 教材版本"两项开课必填项（不重做完整前测、不重做档案）。详见 §6.7 跨端档案设计。

### 2.3 设备 / 工程方案 ✅（v2 定稿）

MVP **方案 C**：

| 端 | 形态 | 服务路径 | 理由 |
|:-:|:-|:-|:-|
| **app 端** | **原生** | 路径① 主入口 | 体验拉满（购买意愿/信任度最高，多吃一截转化） |
| **小程序端** | **h5 嵌 webview** | 路径②③ 兜底 | 一套代码、快速上线、对齐微信生态体验 |

**未来演进 ⏳**：如果路径②③小程序档案完成率显著低于路径①，再补小程序原生版本。MVP 不做。

**两端共用 UX 框架**：所有路径用同一套档案模块/字段/文案逻辑，只在"容器适配"层做差异化（按钮跳转目标不同、小程序去掉某些字段等）。

## 3. 目标与指标

### 3.1 解决的问题 ✅

让家长在"付费后 → 开始学"之间形成 3 件事的最低判断：

1. 我家孩子要解决什么问题
2. 海豚用什么解决（看得见的课程证据）
3. 接下来的路径长什么样

### 3.2 指标分层 📌（v2 收紧：北极星 = day1 到习 / 双完习）

| 角色 | 指标 | 用途 | 拍板状态 |
|:-:|:-|:-|:-:|
| **北极星** | **Day1 到习率 / 双完习率** | 直接决定档案设计形态（**模块 4 重构为"3 步行动"就是为这个**） | ✅ 本轮迭代已锁 |
| 辅指标（仅观测） | 首触反馈率 | 验证档案的破冰副价值，**不背指标** | ⏳ |
| 近端 | 档案完成率、二次打开率、深度浏览时长 | 过关线，不进业务汇报 | ✅ |
| 远端 | 正价转化率 | 仅观测 | ✅ |

**v2 关键变化**：
- 之前 v1 的"Day1 完习率"被收紧为更小颗粒度的「**Day1 到习率 / 双完习率**」——更近端、更可操作、更直接对应"3 步行动"中 Step 1（入门测）+ Step 2（体验课程）
- 「档案不作为销售首通的抓手」✅—— 档案的产品价值由产品本身承担（让家长被听懂、看到方案、相信能解决），不依赖销售接得住

**对应的用户动机缺口** ✅

| 北极星 | 用户动机缺口 | 档案的价值主张 | 档案的 CTA |
|:-:|:-|:-|:-|
| **Day1 到习 / 双完习** | 不理解产品 + 没目标感 + 不知道下一步要做什么 | "你家孩子要解决什么、用什么解决、立刻能做的 3 步" | **"现在开始行动"3 步**：完成入门测 → 体验课程 → 等老师反馈学情 |

详见 §6.4 模块 4 重构。

### 3.3 反向约束的设计含义 📌（v2 更新）

北极星 = day1 到习 / 双完习 → 设计含义：

| 模块 | 北极星反向约束的设计要求 |
|:-:|:-|
| 模块 4（首诊态） | **重构为"3 步行动指引"**——把模糊的"12 节·4 周路径预告"压成立刻能做的 3 步，每步对齐北极星里程碑 |
| 模块 3（解决方案） | **简化为纯文字方案卡**——MVP 不展示具体课程缩略卡（家长会拿放大镜挑），让"被听懂"的力量先建立 |
| 模块 5（下一步建议） | **合并进模块 1 「孩子情况汇总」**，下一步动作（家长应该做什么）由完成档案后的微信小程序老师承担 |
| 卡点策略 | **档案首诊必经**——不许跳过，否则用户根本到不了"3 步行动" |

详见 §6.4、§6.3、§6.5、§8 各章。

## 4. 家长视角的端到端动线 ✅（v2 重画·按三路径）

详见全景图 `demo/档案-路径全景.html`。三条路径的家长动线差异：

### 4.1 路径 ①·直投/自然（app 内闭环）

```
app 注册 → 站内购买 9 元体验课 → 档案首诊 Step 1+2（app 端）
                                       │
                                       ├─ 已分配 → 跳微信小程序加微页（老师二维码）→ 学习
                                       │
                                       └─ 未分配 → 跳 app 计划页（更快进入入门测）→ 学第 1 节
```

### 4.2 路径 ②·效果广告（h5 购课 + 双触达，分叉）

```
广告 → h5 落地页购课 → 双短信：① 下载 app  ② 档案诊断（跳小程序）
                              │
              ┌───────────────┴───────────────┐
              │                                │
        A 先点档案短信                    B 先点下载 app
              │                                │
        小程序档案 Step 1+2              （同路径①的 app 流程）
              │
        ├─ 已分配 → 加微页（小程序）
        └─ 未分配 → 关注公众号
              │
        进入 app（销售电话引导，无固定页面）
              │
        ⭐「确定前测」（已做档案 → 只确认年级 + 教材）
              │
        学第 1 节
```

### 4.3 路径 ③·直播（小程序档案 + 下载 app + 双分叉）

```
店铺购买 → 短信激活 → h5 注册 → 小程序档案 Step 1+2
                                      │
                                ├─ 已分配 → 加微页
                                └─ 未分配 → 关注公众号
                                      │
                                下载 app
                                      │
                          ┌───────────┴───────────┐
                          │                       │
                    已做过档案              未做档案
                          │                       │
                    ⭐「确定前测」          完整新用户前测 → app 档案首诊（同路径①）
                          │                       │
                          └────── 学第 1 节 ──────┘
```

### 4.4 家长关键时刻（共 7 个，v2 增加跨端时刻）

| # | 时刻 | 家长动作 | 档案该呈现什么 |
|:-:|:-|:-|:-|
| ① | 进入档案首诊 Step 1 | 填基本信息 + 选问题 + 写"希望改善" | 默认收起前测已填项，问题用"被听懂"的标签语言 |
| ② | 进入档案首诊 Step 2 | 看「孩子情况汇总」+ 解决方法 + 3 步行动 | 孩子名字开头 + 海豚建议高亮，立刻有目标感 |
| ③ | 点「完成档案」按钮 | 跳转 | 按分配状态分流（4 种跳转，详见 §6.6） |
| ④ | 跨端跳转（路径②③） | 小程序档案做完，下载 app | 看到「确定前测」轻量页（**不重做档案、不重做完整前测**） |
| ⑤ | 学完第 1 节后 | 二次进档案 | 模块 4 出现真实进度（v2 学习中态） |
| ⑥ | 任意时刻 | 在计划页/首页看到档案入口 | 显示当前进度状态 |
| ⑦ | 销售首通（如有） | 接到电话 | 销售可参考档案破冰，但**档案不为销售首通负责**（详见 §1.2、§3.2） |

## 6. 模块详细设计

### 6.1 模块 1：孩子画像（静态层）✅（v2 简化）

**目标**：让家长一眼看到"档案是为我家孩子建的"。

#### 6.1.1 字段

| 字段 | 数据来源 | MVP | 备注 |
|:-|:-|:-:|:-|
| 孩子姓名 / 昵称 | 档案首诊新增 | ✅ | 必填，3-12 字 |
| 年级 | 前测已收 | ✅ | 🔧 **不重复打扰**，前测有则带入展示 |
| 教材版本 | 前测已收 | ✅ | 同上 |
| 当前数学成绩段 | 档案首诊新增 | ✅ | **3 档**：高 / 中 / 低（v1 的 4 档已简化）|
| ~~学习习惯标签~~ | ~~档案首诊新增~~ | ❌ 删除 | v2 删——选填字段拖长 Step 1，由模块 2 的问题选择隐含覆盖 |
| **「希望孩子改善到什么样」** ⭐ | 档案首诊新增（v2 新增）| ✅ | **选填**·开放输入·family text + 引号举例。是模块 1+2 的"被听懂"素材 |

#### 6.1.2 Step 1 排版

| 区块 | 视觉 | 默认态 |
|:-|:-|:-|
| 用户基本信息（姓名+年级+教材） | 浅灰底卡片，单行摘要 | **默认收起**（前测已带入），点击展开修改 |
| 当前数学成绩段 | 3 个 chip 单选 | 必填 |
| 主要问题 | 详见 §6.2 | 必填 |
| 希望孩子改善到什么样 | 浅蓝渐变背景 + ✨ 图标 + textarea | **选填**（标题副文案"写一句话能帮老师更懂你家孩子"） |

⚠️ **前测 vs 档案首诊去重边界**：年级 / 教材两项前测已收，档案首诊**只展示不复填**；如果前测被跳过，档案首诊兜底收一次（路径②③小程序档案也兜底收）。

⚠️ **「希望改善」为空时降级**：模块 1 在 Step 2 的"孩子情况汇总"里**不引用希望改善那一句**，文案模板自动切换为"基于你选的问题，海豚建议从 XX 入手"。

### 6.2 模块 2：问题清单（家长视角）✅（v2 调整呈现）

**目标**：让家长用自己的话表达孩子问题，海豚翻译成可解决的形式。

#### 6.2.1 问题来源

| 来源 | 内容 | 是否 MVP |
|:-|:-|:-:|
| 家长在首诊里勾选 | 6 大类问题标签（**4 高频 + 2 折叠**） | ✅ |
| ~~家长自由补充文本框~~ | ~~0-100 字~~ | ❌ 删除（被模块 1 「希望改善」字段替代）|
| 后续追加 | 家长可在档案页随时新增 | ⏳ 是否 MVP 待确认 |

#### 6.2.2 6 大类问题标签 ✅（v2 调整：4+2 折叠呈现）

| 序 | 类型 | 家长常见表达 | 海豚翻译 | 默认呈现 |
|:-:|:-|:-|:-|:-|
| 1 | 基础薄弱型 | 基础差、听不懂、跟不上 | "前置知识有断层，需要先补回来" | **首屏可见** |
| 2 | 错题吸收型 | 错题不整理、同类型不会、粗心 | "错题没转成能力，需要变式吸收" | **首屏可见** |
| 3 | 习惯执行型 | 拖拉、不自觉、玩手机 | "学习习惯没建立，需要短任务正反馈" | **首屏可见** |
| 4 | 兴趣动力型 | 不想学、抗拒、没兴趣 | "学习驱动不足，需要低压力切入" | **首屏可见** |
| 5 | 时间受限型 | 住校、作业多、补课多 | "学习时间稀缺，需要短时高密度方案" | **折叠在「查看更多 (2 类)」** |
| 6 | 家庭管理困难型 | 家长忙、管不了、不在身边 | "家庭陪学有限，需要老师/系统接管提醒" | **折叠在「查看更多 (2 类)」** |

**v2 设计变化**：v1 是 6 类全部一屏展示，Step 1 太长；v2 改为 4 高频上屏 + 2 类折叠。前 4 类的高频判定来源：`反馈环节分析.md` 第六章 + 反馈电话样本分析。

**关键设计**：每类的「海豚翻译」要让家长感觉"被听懂"——这是档案"解释性"的第一道印象，不能模板化到 3 秒识破。

#### 6.2.3 ⏳ 待教研对齐
- **家长视角问题标签 vs 教学视角的对应关系**（依赖 `01-讨论纪要.md` 4.5 项的对齐）
- **4 高频 vs 2 折叠的拆分是否稳定**（看上线后数据，若 5/6 类点击率 ≥ 前 4 类的某一类，则调换序）

### 6.3 模块 3：解决方案（解释性核心）📌（v2 简化）

**目标**：把家长选的问题，映射到"海豚的具体方法"上，让家长看到"我的问题 → 海豚怎么解决"。

#### 6.3.1 MVP 实现机制 ✅

**问题标签 → 方法描述 映射表**（手动维护）

- 形式：6 类问题 × N 个细分子标签 × **方法描述（纯文字）**
- 维护者：⏳ 教研侧（待 4.5 项对齐）
- 颗粒度：每个问题至少给 2-3 个有差异化的方法描述，避免家长 3 秒识破模板

#### 6.3.2 展示形态 ✅（v2 简化：纯文字方案卡 + 视频下移）

每个家长勾选的问题 → 一张**纯文字方案卡**，纵向排列。

| 字段 | 来源 | 示例 |
|:-|:-|:-|
| 对应的问题（针对：XX） | 模块 2 | "针对：错题吸收" |
| 海豚的方法描述（2-3 句话）| 映射表 | "用变式题让同类错题被反复练到掌握。孩子每错一题，海豚会给 2-3 道同类型变式，验证是真懂了还是粗心，错题不再重复犯。" |

**通用产品介绍视频**（放在所有方案卡**下方**，前面带 `想看海豚整体怎么用？` 分隔提示）：
- 内容：1 分钟海豚学习方式介绍
- MVP 用同一支视频，所有用户都看
- 时长建议 60-90s，移动端不 autoplay

**v2 关键变化（v1 → v2）**：

| 项 | v1（已删） | v2（保留） | 删除原因 |
|:-|:-|:-|:-|
| 课程缩略卡（错题精讲 15min · 第 2 节 / 变式 3 连 12min · 第 4 节）| ❌ | / | MVP 阶段不一定能给出"对的真实题/课程"，过早展示具体课程反而被家长拿放大镜挑刺 |
| 课程封面 / 标题 / 时长 | ❌ | / | 同上 |
| "去学这节" CTA（跳计划页对应课程） | ❌ | / | MVP 不做课程跳转，归并到模块 4「现在开始行动」的统一入口 |
| 通用产品介绍视频位置 | 顶部 | **下方**，方案后 | 家长先看"对我家的针对方案"（强相关），再看"海豚整体怎么用"（通用补充），按注意力优先级排 |

⚠️ **边界**：MVP 阶段不做对话式诊断、不做个性化推荐算法，就是静态映射表 + 纯文字方案描述。完整方案再升级（带具体课程、CTA、跳转）。

#### 6.3.3 差异化输入的硬要求 ⚠️

家长不同输入必须产生**有差异化**的方案描述文案，**不允许**所有问题都跳到同一段方法描述。研发评审时要校验映射表至少有 N 条独立路径（N 待教研定）。

⚠️ 方法描述要写到"**具体可信**"——不能空泛"用变式题让错题被掌握"，要给到"每错一题给 2-3 道同类型变式，验证是真懂还是粗心"的具体感。

### 6.4 模块 4：行动指引 / 学习进度（档案性核心）📌（v2 重大重构）

**这是档案区别于"一次性卡"的关键模块**。v2 将其按档案状态分成两种形态：

| 档案状态 | 模块 4 形态 | 用途 |
|:-|:-|:-|
| **首诊态 v1**（刚生成档案，未开始学） | **「现在开始行动！」3 步引导** | 把模糊的"长期路径"压成立刻能做的 3 步，对齐 day1 到习 / 双完习北极星 |
| **学习中 v2**（已学 ≥ 1 节课） | **学习进度 + 已解决 / 进行中 / 未开始** | 档案性体现——随每节课更新 |

#### 6.4.1 首诊态 v1·「现在开始行动！」3 步 ✅（v2 新设计）

> **设计依据**：v1 的"12 节·4 周路径预告"对家长是"还没开始就压力大"，反而拉低 day1 到习。3 步行动是"立刻能做 + 目标看得见"，更服务北极星。

| 步骤 | 标题 | 副标题 / 描述 | 对应北极星阶段 |
|:-:|:-|:-|:-|
| Step 1 | **完成入门测** | 基础诊断 + 错题摸底，约 8 分钟 | 解锁课程 |
| Step 2 | **体验课程学习** | 小试牛刀，跟孩子一起感受 | **Day1 到习** |
| Step 3 | **等老师反馈学情** | 基于孩子的体验情况，看是否适合 | **双完习 + 反馈** |

**视觉**：三步纵向排列，每步左边圆角 chip（Step N），右边标题 + 描述；步骤间用渐变竖线连接。

**v2 模块 4 关键变化**：

| 项 | v1（已删） | v2（保留） |
|:-|:-|:-|
| 形态 | 12 节·4 周路径预告（分 4 段，每段对应一类问题） | 3 步行动引导 |
| 进度条 | 0/12 节 | **删除**（首诊态不显示进度，避免"还没开始就压力大"）|
| 学习计划安排卡 | 含总节数 / 周期 / 每日时长 | **删除** |
| 路径分组 | 4 段 todo 态 | **删除** |

#### 6.4.2 学习中态 v2·学习进度（保留 v1 设计）✅

家长学完第 1 节后，模块 4 升级为"学习进度"形态：

| 字段 | 来源 | 示例 |
|:-|:-|:-|
| 已学课节数 / 计划总数 | 学习行为数据 | "1 / 12" |
| 已解决的问题（绿勾） | 学习行为 + 课-问题映射 | "✅ 错题吸收：通过 3 道变式题验证" |
| 进行中的问题 | 同上 | "⏳ 基础薄弱：还需 2 节课" |
| 未开始的问题 | 模块 2 输入 - 已解决 - 进行中 | "○ 兴趣动力（等开始学后激活）" |

#### 6.4.3 "问题已解决"的判定规则 ⏳（学习中态用）

**两套候选规则，待数据 / 学情侧拍板**：

| 选项 | 规则 | 优劣 |
|:-:|:-|:-|
| A | 完成对应课程节数 + 练习正确率 ≥ X% | 客观，但 X 值待教研定 |
| B | A 的基础上 + 老师人工标记 | 准但慢，依赖老师介入 |
| C | A + AI 自动判定 | 自动化，但 AI 误判风险 |

📌 **推荐 A 作为 MVP 起点**，B/C 留到完整方案。

#### 6.4.4 课-问题映射表 ⏳（学习中态用）
谁来维护？映射颗粒度？详见 `01-讨论纪要.md` 4.4 项的对齐。

#### 6.4.5 同步频率 ⏳（学习中态用）
学习行为 → 档案的同步频率：实时 / 每节课结束 / 每日批量？默认建议**每节课结束触发**。

### 6.5 模块 5：下一步建议 ✅（v2 重大调整：合并 + 移交）

**v2 设计变化**：v1 把"下一步建议"作为独立模块（给家长一句话、给孩子一句话），v2 拆解为两半：

#### 6.5.1 在档案首诊里 → 合并进 Step 2 顶部「孩子情况汇总」

不再单独成模块，而是融进 Step 2 的「孩子情况汇总」一段话里：

> **示例文案**：
> 「{孩子名}同学，主要卡在 {问题1} 和 {问题2} 两点上。结合你希望孩子能"{希望改善原文}"——**海豚建议从 {方案标签} 入手**。」

**关键设计**：
- 孩子名字开头（轻、亲近）
- 中间引用家长输入的"希望改善"原文（带引号，"被听懂"的第二层证据）
- 末尾「海豚建议」**加粗高亮**，方案标签用金色 chip（与正文区分）

**模板规则**：
- 4-6 个差异化文案模板，按"问题组合"分流
- "希望改善"为空时降级文案："基于你选的问题，海豚建议从 XX 入手"
- 维护方：教研侧（待 4.5 项对齐）

#### 6.5.2 完成档案之后 → 「下一步动作」职能移交微信小程序老师 ✅

档案首诊**不再承担"下一步该做什么"的引导**——这一职能由：

1. **「现在开始行动！」3 步**（模块 4 首诊态）告诉家长"立刻能做什么"
2. **加微后微信小程序老师**承担更深入的、个性化的下一步沟通（基于完成的档案接待）

⚠️ **本 PRD 不再描述模块 5 在档案首诊里的独立 UI**——v1 那一套"给家长一句话 / 给孩子一句话"卡片在 v2 中**取消**。

#### 6.5.3 v2 学习中态的模块 5 ⏳

学习中态（学了 ≥ 1 节课后）的下一步建议——v2 待定，可能形式：
- 学习计划页内嵌的"明天计划"提示
- 微信小程序老师推送的提醒
- ⏳ 与销售/客服侧对齐

### 6.6 「完成档案」按钮的 4 种差异化跳转 📌（v2 新增）

档案首诊 Step 2 底部「完成档案」按钮，根据用户的端 + 分配状态走 4 种不同跳转。

| 端 | 分配状态 | 按钮文案 | 跳转目标 | 视觉 |
|:-:|:-:|:-|:-|:-|
| **app 端** | 已分配 | 完成档案，联系老师开始学习 → | 跳转微信小程序加微页 | 绿色（WeChat 色） + 💬 图标 + 副提示"→ 跳转微信小程序" |
| **app 端** | 未分配 | 完成档案，开始学习 → | 跳 app 计划页（更快进入入门测） | 主色（蓝紫色） |
| **小程序端** | 已分配 | 完成档案 → | 同小程序内加微页（老师二维码） | 绿色（WeChat 色） |
| **小程序端** | 未分配 | 完成档案 → | 关注公众号页（24h 内关注接收通知）| 黄色（公众号兜底色） |

⚠️ **路径② 立即分配的两条分支汇入「下载 app」无具体页面**（销售电话推进），用户进 app 后看「确定前测」（详见 §6.7）。

### 6.7 跨端档案 + 「确定前测」📌（v2 新增）

档案在三条路径里出现在两种容器，但 **UX 框架统一**：

| 容器 | 字段 | 视觉 | 工程方案 |
|:-|:-|:-|:-|
| **app 端档案**（完整版） | 同 §6.1-6.5 | app 原生 | 路径① 核心入口，体验拉满 |
| **小程序端档案**（兜底版）| 同上（不简化字段） | h5 嵌 webview，适配小程序导航栏 | 路径②③ 兜底，方案 C |
| **「确定前测」**（轻量补充页）| 只问年级 + 教材版本 | app 原生 | 已做小程序档案的用户下载 app 后看到 |

#### 6.7.1 「确定前测」是什么 ✅

**触发条件**：用户在小程序完成档案首诊 → 下载 app 进入 → 系统检测"档案已存在但教材未确认" → 展示「确定前测」页

**字段**：
- 计划学习的年级（下拉 / 已带入）
- 数学·教材版本（下拉，必选）
- 语文·教材版本（下拉，必选）

**为什么需要这个页**：
- 小程序档案虽然问了年级 + 教材，但**教材版本对家长不直观**（很多家长不知道是哪个版本，需要看课本封面）
- app 端给一个"二次确认"的机会，让家长打开课本拍照确认后再选
- 比"完整新用户前测"轻得多——不重做完整诊断、不重做档案

#### 6.7.2 两端共用 + 差异化点

| 项 | app 端 | 小程序端 | 备注 |
|:-|:-|:-|:-|
| 5 模块字段 | 全部 | 全部 | UX 框架统一，不简化 |
| 文案 | 同 | 同 | 用同一份文案模板 |
| 「完成档案」按钮跳转 | 详见 §6.6 | 详见 §6.6 | 按容器 + 分配差异化 |
| 数据同步 | 写 app 后端 | 写 app 后端（手机号唯一标识） | 跨端读写同一份档案 |

#### 6.7.3 数据同步 🔧

- **手机号是唯一标识**：小程序档案完成 → 写后端时用手机号关联到用户
- 用户下载 app 后用同一手机号登录 → 后端检测到已有档案 → 跳过完整档案首诊，直接展示「确定前测」
- ⏳ **跨端登录边界**：用户家长在小程序填档案，但 app 用孩子账号登录怎么办？详见 §9 状态机边界 case

## 8. 卡点策略 📌（v2 重写：档案首诊必经 + 差异化兜底）

### 8.1 v2 决策：档案首诊**必经**（不再讨论"软引导 vs 强卡点"）✅

档案首诊在三条路径里都是**必经环节**——这是 v2 的关键决策：

| 路径 | 档案首诊位置 | 不做档案能否继续？ |
|:-|:-|:-|
| ① 直投/自然 | 购买体验课后，**替换原销售加微页** | ❌ 不做就出不去（继续不了到加微 / 计划页） |
| ② 效果广告·A 分支 | 双短信跳小程序档案 | ❌ 不做就到不了加微 / 公众号 |
| ② 效果广告·B 分支 | 同路径①（先下载 app） | ❌ 不做就出不去 |
| ③ 直播 | 小程序档案 | ❌ 不做就到不了加微 / 公众号 |

**v1 vs v2 决策变化**：

| 项 | v1（草案）| v2（已定）|
|:-|:-|:-|
| 卡点形态 | 推荐 (b) 软引导 + 可跳过 | 必经，不允许跳过 |
| 理由 | 怕硬卡点影响 D1 到习 | 「现在开始行动」3 步已经把档案设计为"通往学习的桥"，跳过反而到不了 day1 到习 |

### 8.2 完成档案后的差异化兜底 ✅

档案虽然必经，但**完成后的去向按"端 + 分配"分流**（详见 §6.6 的 4 种跳转）。

| 端 + 分配 | 兜底逻辑 | 服务的主指标 |
|:-|:-|:-|
| **app 端·已分配** | 跳小程序加微页 | 让销售/老师接住，承接首触反馈率 |
| **app 端·未分配** | 跳计划页 | 让用户**更快进入入门测**，承接 day1 到习率 |
| **小程序端·已分配** | 跳小程序加微页 | 同上 |
| **小程序端·未分配** | 跳关注公众号页 | 24h 内关注接收通知，间接承接 day1 到习 |

**关键点**：未分配的用户**不强推加微**（因为没销售可加），分流到"自己开始学"或"关注公众号等通知"，比把用户卡在加微页转化更高。

### 8.3 已填档案的"二次入口"呈现（计划页 / 首页）⏳

完成档案进入 app 后，计划页 / 首页顶部需要持续展示档案入口，便于家长二次查看：

| 状态 | 入口呈现 |
|:-|:-|
| 已填档案、未开始学 | 标准入口 "查看孩子档案 →" |
| 已填档案、有进度（学习中态） | 入口带进度提示 "已解决 X 个问题，还剩 Y" |

⚠️ "未填档案"状态在 v2 中**不存在**——档案必经，所以二次入口只关心"未学/有进度"两态。

```
   │                                              检测档案已存在 → 【确定前测】轻量页
   │                                                                   ↓
   │                                                  确认年级 + 教材 → [v1.0 跨端补齐]
   │
   └── 用户未做档案直接进 app（边界 case） ──→ 完整新用户前测 → app 档案首诊 → [v1 app已生成]
                                                                                  │
                       ┌──────────────────────────────────────────────────────────┘
                       ↓
                  首节课完成
                       ↓
            [v2 学习中] ←── 每节课完成 ──┐
                       │                  │
                       └──────────────────┘
                       │
            家长编辑画像/追加问题 ──→ [v1.1 已编辑]
```

| 状态 | 含义 | 模块呈现 |
|:-|:-|:-|
| 未生成 | 家长还没完成首诊 | 路径起点（不应长期停留） |
| v1 app 已生成 | app 端首诊完成，未开始学 | 模块 1-3 显示，模块 4 显示"3 步行动"，模块 5 已合并 |
| v1 小程序已生成 | 小程序端首诊完成 | 同上，等下载 app 后跨端补齐 |
| v1.0 跨端补齐 | 小程序档案 + app「确定前测」都完成 | 同 v1 app 已生成 |
| v1.1 已编辑 | 家长追加 / 编辑过 | 模块 3 跟随重算 |
| v2 学习中 | 至少完成 1 节课 | 模块 4 从"3 步行动"切换为"学习进度"形态 |

⚠️ **边界 case**：

| case | 处理 |
|:-|:-|
| 家长跳过首诊后直接学了几节 | 学习行为正常累积，回头补建档案时模块 4 直接显示已学进度 |
| 跨设备登录（手机 A 买、平板 B 学） | 用同一手机号登录则档案自动同步；不同手机号 ⏳ 待客户端拍 |
| 跨端登录边界（小程序档案 → app 用孩子账号登录） | 检测手机号不一致 → 提示家长用相同手机号登录；否则按"新用户"走 |
| 家长在小程序填档案后**始终不下载 app** | 档案数据保留 ≥ 90 天，期间任意时刻下载 app 可同步到「确定前测」 |
| 「确定前测」用户跳过 / 关闭弹层 | 不强卡，但 app 内任意学习入口前再次拦截一次（不超过 2 次拦截后放过）|
| 家长清空模块 2 问题清单 | 模块 3-4 同步清空，模块 4 学习进度归零展示但学习行为数据保留 |
| 课程下架导致映射表失效 | 模块 3 卡片显示"该方案已更新"，重新走映射 |

## 10. 验收标准（v2 扩展）

### 10.1 功能验收 🔧

**首诊 Step 1**：
- [ ] 年级/教材**不重复打扰**（前测已收时默认收起，可点击展开修改）
- [ ] 当前数学成绩段 = 3 档（高/中/低）
- [ ] 主要问题 4 高频上屏 + 「查看更多 (2 类)」可展开
- [ ] 「希望孩子改善」字段**选填**，副文案"写一句话能帮老师更懂你家孩子"
- [ ] 6 类问题标签全部支持

**首诊 Step 2**：
- [ ] 「孩子情况汇总」段落用孩子名开头，正确引用「希望改善」原文（带引号），「海豚建议」加粗高亮
- [ ] 至少 4-6 个差异化「孩子情况汇总」文案模板
- [ ] 解决方法用纯文字方案卡（**不展示具体课程缩略卡**）
- [ ] 通用产品介绍视频在方案卡**下方**
- [ ] 「现在开始行动」3 步（Step 1/2/3）正确展示

**完成档案按钮**：
- [ ] 4 种跳转覆盖（app 端 / 小程序端 × 已分配 / 未分配，详见 §6.6）
- [ ] 按钮文案、颜色、副提示文字按表格执行

**跨端 + 确定前测**：
- [ ] 小程序档案 → 下载 app 后，同手机号登录能识别到档案
- [ ] 「确定前测」轻量页只问年级 + 教材，不重做完整诊断
- [ ] 未做档案的用户进 app 走完整新用户前测后再走 app 档案首诊（同路径①）

**学习中态**：
- [ ] 模块 4 在第 1 节课完成后 ≤ X 分钟内从"3 步行动"切换为"学习进度"形态（X ⏳ 待数据侧定，建议 ≤ 5 分钟）
- [ ] 问题 → 方法描述映射表至少 N 条独立路径（N ⏳ 待教研定）

**卡点策略**：
- [ ] 档案首诊**必经**（三条路径都不允许跳过）
- [ ] 计划页 / 首页二次入口正确展示（"未学" / "有进度" 两态）

### 10.2 数据验收 🔧

- [ ] 学习行为数据能在每节课结束后回写档案
- [ ] 档案状态变更全部埋点（v1 生成 / 编辑 / v2 升级 / 模块 4 每次更新 / 跨端补齐）
- [ ] 完成档案按钮的 4 种跳转分别埋点（用于看哪种分流转化率最高）
- [ ] 近端指标可观测：档案完成率、二次打开率、深度浏览时长

### 10.3 体验验收（依赖体验设计稿）⏳

- [ ] 首诊 Step 1+2 总耗时 ≤ 3 分钟（家长侧抽测）
- [ ] 模块 1-4 视觉呈现差异化（不能让家长感觉"4 张一样的卡")
- [ ] 入口文案 2 个变体（电商 + 直投）测试通过
- [ ] 「希望改善」填写率 ≥ 30%（验证文案是否激发输入欲）
