# 面向家长建立初诊档案 - 讨论纪要

> 用途：和 AI 多轮讨论后的共识 + 待对齐项整理，**待和组长 review 后定稿**
> 上下文（一句话）：档案 = 给已购 9 元体验课的家长建立目标感、提升 app 体验联动的工具。**不是**销售析出工具，**不是** v2 AI 销售 0 转体的钩子；独立于 v2，定位"产品体验赋能"。

---

## 一、本次方案的定位（最容易被误解，先对齐）

- 本次产出物是 **「思路稿 + 可能性分析」**，不是 PRD
- 解决的是"用户付费后到开始学之间的目标感空白"
- 真正的档案页面（视觉/交互/形态）由 **体验设计**，本方案只给框架（模块清单 + 模块关系 + 数据来源 + 更新触发条件）
- 之前看过的两张 demo 图（问题选择 + 同类孩子方案）**不是档案本身**，是档案前的信息收集

产出物结构（5 块）：

1. 「档案」这个包装能解决什么 + 不解决什么
2. 不同来源路径下档案怎么插入（含对销售/体验的影响）
3. 档案需要的最小数据集 + 和体验/数据侧的对齐项（到模块级）
4. MVP 验证目标 + 验证后判断"是否继续"的指标线
5. 风险与待对齐项清单

---

## 二、已达成的共识（无需组长拍板，仅 sanity check）

### 2.1 用户路径

- **MVP 仅锁定新用户付费路径**
- 历史已购、AI 销售析出、未填首诊补建等场景延后处理
- 电商 / 直投 两条来源路径：**在 app 内的档案首诊插入点收口到同一个位置**——前测之后 + 计划页首次进入之间
- 共用一套首诊 UI，**入口文案做 2 个变体**（电商用户需要补"欢迎"层叙述，直投用户不需要）

### 2.2 档案要解决的问题边界

- **解决**：付费后到开始学之间的目标感空白
- **不解决**：电商用户的产品认知建立（这部分该靠新人引导，不靠档案兜底）

### 2.3 解释性的最低成本做法（MVP 用）

- MVP 阶段用 **"问题标签 → 课程证据" 映射表**（手动维护，类似销售提下限的做法）
- 关键：不同输入要产生**有差异化**的解释方案，避免家长 3 秒识破模板
- 完整方案再做对话式 / 个性化诊断

### 2.4 销售如何使用档案

- 销售只需要 **知道"档案是什么"**，作为加微/首通的破冰物料
- 档案内容本质是"学习数据的套壳变形"，销售在工作台已能看到原始数据
- → **不需要做"销售后台版 vs 家长版"的双视图**

### 2.5 MVP 指标分层

| 层级 | 指标 | 在 MVP 的角色 |
|:-|:-|:-|
| 近端（档案自身） | 档案完成率、二次打开率、深度浏览时长 | 过关线、不进业务汇报 |
| **中间层（主指标）** | **完习率 + 销售反馈率**（工作台现成指标） | **MVP 主盯** |
| 远端 | 正价转化率 | 仅观测、不背指标 |

- 不看 ARPU，因为当前每月 sku 定价固定，ARPU 不是变量
- 不直接看正价转化率作为 MVP 主指标——中间人（销售）扰动太大
- 待审视：完习率 vs 销售反馈率（首通反馈率）**两个指标背后是两套不同形态的档案 + 两套不同的用户动机叙事**，并列写在主指标里其实掩盖了一个未对齐项 → 详见 **决策点 D**（特别是 D.3）

### 2.6 档案框架草稿（5 模块，L2 颗粒度）

| 模块 | 内容 | 数据来源 | 更新触发 |
|:-|:-|:-|:-|
| 1. 孩子画像（静态层） | 年级、教材、成绩、习惯标签 | 前测 + 档案首诊 | 家长主动编辑 |
| 2. 问题清单（家长视角） | 家长选的问题 + 海豚的人话翻译 | 档案首诊 | 家长可追加 |
| 3. 解决方案（**解释性核心**） | 问题 → 课程证据映射 | 静态映射表 + 课程库 | 问题变化时重算 |
| 4. 学习进度（**档案性核心**） | 已学课节、解决了哪些问题、剩余问题 | 学习行为数据 + 课-问题映射 | 每节课完成后自动 |
| 5. 下一步建议 | 给家长 1 句、给孩子 1 句 | 进度状态 + 简单规则 | 进度变化时自动 |

- demo 那两张图覆盖的是模块 1-3
- 模块 4-5 才是"档案性"的体现，也是 MVP 真正难的部分
- MVP 建议至少做出 1-4；模块 5 用静态模板顶

## 三、待和组长对齐的关键决策点

### 决策点 A | 档案的"档案性"做到什么程度

| 选项 | 形态 | MVP 难度 | 真正价值 |
|:-|:-|:-|:-|
| **X：一次性卡** | 看完就完 | 低 | 弱，等于活动 banner |
| **Y：可成长档案** | 随学习数据持续更新 | 高 | 强，长期目标感的真正载体 |
| **Z：可成长 + 可交互** | 家长可追加问题、跟 AI 对话 | 最高 | 强，但 AI 瞎承诺风险高 |

**AI 倾向 Y**：本次方案给的是 Y 的框架，MVP 落地的"动态更新"颗粒度待定。
**待组长拍板**：方向认不认？MVP 阶段是否允许只跑 X，把 Y/Z 留到完整方案？

---

### 决策点 B | 档案首诊的"卡点策略"

| 选项 | 含义 |
|:-|:-|
| (a) 强卡点 | 不填首诊就进不去计划页 |
| **(b) 软引导 + 强提醒** | 可跳过，但计划页顶部一直挂入口 |
| (c) 顺手收 | 付费后直接进计划页，档案首诊作为计划页内引导卡 |

**AI 倾向 (b)**，**但**这不是结论，是**和业务方的讨论项**——需要平衡"档案渗透率"和"MVP 开发难度"。
**待组长拍板**：是不是把 (b) 作为方案默认推荐，把 (a)(c) 列为对照备选？

---

### 决策点 C | 销售首通 / 加微页面 / 档案首诊 的时序（**最复杂的一项**）

**现状回顾**：
- 用户购买 9 元课后，**会紧接着跳一个加销售微信的页面**
- 销售首通电话发生在购买之后，但**时间相对档案首诊 / 用户开学的顺序不确定**

**核心判断**：
- 档案如果想做销售的破冰抓手 → **必须在销售首通之前完成**
- 加微页 vs 档案首诊 谁先 → 影响用户疲劳度（连续填两步）vs 影响档案完成率

**可能的顺序组合**（不完整列举）：

```
购买 → 档案首诊 → 加微页 → 销售首通 → 学
购买 → 加微页 → 档案首诊 → 销售首通 → 学
购买 → 加微页 → 销售首通 → 档案首诊 → 学
购买 → 加微页 → 档案首诊 → 学 → 销售首通
......
```

---

### 决策点 D | MVP 主指标的取舍：完习率 vs 首通反馈率

**为什么把这件事单拎出来讨论**：2.5 节写的"完习率 + 销售反馈率"看似是一个共识，但**这两个指标背后是两套不同形态的档案产品**。如果不在 MVP 启动前定清楚谁主谁辅，最后会被指标反向拉着走，把档案做成另一个东西。

#### D.1 两个指标的本质区别

| 维度 | 完习率 | 首通反馈率 |
|:-|:-|:-|
| 服务对象 | 家长 + 孩子（产品端） | 家长 + 销售（销售端） |
| 衡量行为 | 体验课是否被学完 | 首通是否聊得起来、有没有正向回馈 |
| 和档案定位（"产品体验赋能"）的对齐度 | **强对齐** | 弱对齐，偏"销售析出工具"方向 |
| 因果链 | 档案 → 目标感 → 学习坚持 → 完习（中长） | 档案 → 破冰物料 → 接通质量（短） |
| 中间人扰动 | 小（孩子学不学不太受销售影响） | **大**（销售话术 / 拨打时机 / 个体差异都会污染数据） |
| 验证周期 | 长，需要等一个体验班跑完（7~14 天） | 短，购买后 24~72h 就出结果 |
| 归因风险 | 完习涨了说不清是档案功劳还是课程功劳 | 首通涨了说不清是档案功劳还是销售个体差异 |

> 注意：按 2.5 节"中间人扰动太大所以不直接看正价转化率"的同样逻辑，**首通反馈率本质上也是中间人扰动严重的指标**，只是离档案近一档。

#### D.2 反向约束：档案会被设计成什么样

**以「完习率」为目标 →**
- 决策点 A 必须选 **Y（可成长档案）**：档案不持续更新，就推不动持续学习
- 模块 4（学习进度）+ 模块 5（下一步建议）**必须做**，且必须真的随每节课更新
- 时序约束弱：档案首诊插哪儿都行，甚至允许"先学几节课再补建档案"
- 决策点 B 大概率落到 **(c) 顺手收**
- 决策点 C 大幅简化：首通时档案完不完成不那么重要
- → 档案 = **家长自用的学习进度看板**（长期、可成长）

**以「首通反馈率」为目标 →**
- 决策点 A 选 **X（一次性卡）** 就够用：首通只看首诊那一刻的档案
- 模块 1-3（画像 + 问题 + 解决方案）**必须做**，模块 4-5 在首通前还没数据，可以延后甚至砍掉
- 时序强约束：档案首诊**必须**在首通前完成 → 决策点 C 直接被锁死成"购买 → 档案首诊 → 加微 → 首通"
- 决策点 B 可能要选 **(a) 强卡点**，否则渗透率不够、首通时档案缺席就白做了
- → 档案 = **首诊报告**（一次性、给销售当破冰物料）

#### D.3 用户动机视角：两个指标背后是两套不同的"用户动机叙事"

**这次讨论后达成的方法论**：

> 选指标 → 拆解"为什么这个指标低" → 用户为什么没配合 → 提升用户完成动作需要什么因素 → 反推档案应该怎么做

按这条路径走，两个候选主指标对应的"用户动机缺口"完全不同——这是比 D.2「产品形态约束」更上位的差异：D.2 是"档案长什么样"，D.3 是"档案要让用户因为什么而动起来"。

**数据依据**：`Day1 到习与首触反馈率分析.md`

##### Day1 到习低 → 用户动机缺口

> **口径说明**（看下面表格前先对一遍分母）：
> - **春10 全量**：7,082 人
> - **无反馈用户**：春10 全量中**系统没有反馈关单记录**的 4,678 人（占全量 66.05%）
> - **未到习用户**：无反馈用户中学习状态停留在未到习的 1,782 人（占无反馈 38.09%、占全量 25.16%）
> - 因此下面"占未到习"和"占无反馈"是两层分母

D1 未到习 / 未完习的根因，从两个互补视角看（量级见 `Day1 到习与首触反馈率分析.md` 第二章 + `反馈环节分析.md` 第二章下钻表）：

**视角一：上游结构性维度（决定有多少用户能进 D1）**

- 开课就绪三件套缺一（加微 / 首触 / 入门测）→ 用户"不知道有这件事"
  量级：**春10 直投 ~54% 用户**卡在此层（"仅加微" + "其他用户" 合计），对应 D1 到习率 `11%~64%`，而三件套齐备组到习率 `94%`

**视角二：未到习用户内部分桶（1,782 人，三条加起来正好 = 全部未到习）**

| 细分原因 | 用户动机翻译 | 人数 | **占未到习** | 占无反馈 |
|:-|:-|-:|-:|-:|
| 有产品/任务触达但未启动 | "不知道做什么" | 1,221 | **68.52%** | 26.10% |
| 无原始触达 / 低线索 | "根本没建联" | 470 | **26.38%** | 10.05% |
| 有触达但没有任务引导 | "触达了但没给具体动作" | 91 | **5.11%** | 1.95% |
| **合计** | | **1,782** | **100%** | **38.09%** |

**视角三：已到习但卡在入口**（这部分不在"未到习"分母里，属于「到习-未完习」下钻，但失败发生在"开始学"那一刻，性质和未到习同质）

- 下载 / 登录 / 入口障碍 → 用户"不知道从哪开始"
  量级：**559 人 / 占到习-未完习 50.9% / 占无反馈 11.95%**

→ 本质：**用户对产品没认知、没目标感**——视角二里 `68.52%` 的"有触达未启动" + 视角三的入口障碍，都指向"用户被触达过但没能形成动作"
→ 档案要给的动机：**让用户理解产品 + 建立目标感**，把更多用户推到 D1 到习

##### 首触反馈率低 → 用户动机缺口

无反馈用户根因四层叠加（春10 全量 7,082 人 / 无反馈 4,678 人为基准）：

- 没素材（**2,880 人 / 占无反馈 61.6%**）→ 上游 D1 到习路径没跑通，回流到上一条
- 没互动（**1,885 人 / 占全量 26.6%** 全程 0 条有效回复）→ 用户"不觉得老师懂我家孩子"
- 没沉淀（**466 人 / 占 2 阶段以上完习无反馈用户 41.9%** 已有反馈雏形但未关单）→ 服务发生过但没归集
- 没认知（**1,265 人 / 占匹配反馈电话用户 ~76%** 微信无产品表达）→ 用户"对销售触达没预期、没准备"

→ 本质：**用户对学习结果没期待、对销售触达没预期**
→ 档案要给的动机：**让用户对学习结果和老师解读有期待 + 提前建立对销售触达的预期**，让更多用户愿意接电话、接得起对话

##### 两条动机路径对应的档案差异化呈现

| 维度 | Day1 到习路径 | 首触反馈率路径 |
|:-|:-|:-|
| 用户动机缺口 | 不理解产品 + 没目标感 | 对学习结果没期待 + 不愿接销售电话 |
| 档案的"价值主张" | "你家孩子要解决什么问题、用什么解决、看得见的路径" | "孩子学完会有一份初步学情，老师将基于这份给你完整解读" |
| 档案核心模块（参 2.6） | **模块 1-2-3** 为重，模块 5 顺手收 | **模块 1-2-4** 为重，需预埋"反馈触点"指向老师 |
| 档案的 CTA 落点 | "开始学第一节" | "等老师电话给你解读" |
| 用户应建立的预期 | "我知道孩子要学什么、为什么学" | "我等着老师给我解读" |

##### 这一节的关键含义

1. **底层 5 个模块可以共用，但对外的叙事重心 / CTA / 留白点必须二选一**——MVP 阶段同时打两个动机，两边都讲不清
2. **这给"选主指标"补了一个用户视角的支撑**：不是"哪个指标更好测"，而是"档案先打哪个动机缺口"——而这个动机缺口又决定了档案的对外呈现重心

---

#### D.4 最关键的潜在冲突

纪要一开头已经写："档案**不是**销售析出工具，**不是** v2 的钩子，定位'产品体验赋能'"——这句话本身就是在防止首通反馈率把档案拽偏。

如果现在选首通反馈率作主指标，相当于在指标设计层面**把档案的定位拉回了"销售工具"**——前面的定位共识就会被悄悄推翻。

#### D.5 AI 的建议（待组长拍板）

**不二选一，分主次：**

| 角色 | 指标 | 用途 |
|:-|:-|:-|
| **主指标** | **完习率** | 和定位对齐 + 中间人扰动小 + 归因相对干净 + 对应用户动机缺口"理解产品 + 目标感"和档案定位同向（见 D.3） |
| **辅指标** | **首通反馈率** | 仅观测，验证档案的破冰副价值，**不背指标** |
| 近端 | 档案完成率、二次打开率 | 过关线 |

两个一起看的好处是**互相校验**：

| 完习率 | 首通反馈率 | 含义 |
|:-:|:-:|:-|
| ↑ | — | 档案对家长有用，但销售没接住 → 销售侧问题 |
| — | ↑ | 档案被销售当物料用了，家长没真用起来 → 产品侧问题 |
| ↑ | ↑ | 两条链路都跑通 |
| — | — | 档案这个包装可能就不成立 |

**如果非要二选一**：
- 选完习率 → 同步在方案里**明确放弃**"档案做销售破冰抓手"这条线，决策点 C 简化、加微页顺序就不再是档案的事
- 选首通反馈率 → MVP 实质退化为"首诊报告 + 销售话术"，**这时候要重新审视'档案'这个包装是否还成立**

**待组长拍板**：
1. 同意"完习率为主、首通反馈率为辅观测"的分工吗？
2. 如果同意，2.5 节的"完习率 + 销售反馈率"主指标表述需要改写为分主辅的版本

## 四、待和其他业务方对齐的项目（组长可能需要协调）

### 4.1 跟体验设计
- 真正的档案页面（视觉/交互/形态）由体验设计
- 本方案只给框架颗粒度（模块清单 + 模块关系 + 数据来源 + 更新触发条件）
- **【新增·高】前测 vs 档案首诊的去重和衔接**：前测已收年级/教材，档案首诊不应重复打扰
- **【新增·中】计划页首次进入 vs 后续进入的入口呈现差异**：首次=档案首诊入口；后续=档案入口
- **【新增·高】电商欢迎层的归属**：纪要 2.2 说"靠新人引导补"，但落到具体页面是哪一页、由体验还是电商主导，未定

### 4.2 跟销售业务方
- 卡点策略 (b) 的渗透率取舍
- **加微页面 vs 档案首诊的顺序**（决策点 C 的子项）
- 销售首通拨打前是否检查档案状态
- 销售拿档案当破冰抓手的具体玩法
- **【新增·中】工作台是否展示档案状态**（家长是否填了档案、停在哪一步），决定销售首通前的话术分支
- **【新增·低，依赖决策点 D】销售首通后是否回写信息到档案**（如更新模块 5"下一步建议"），形成档案↔销售反馈回流闭环

### 4.3 跟电商业务方 / 增长
- 电商用户进 app 前的产品认知建立（新人引导该补什么）
- 电商用户档案首诊入口文案差异化
- **【新增·高，卡 MVP 范围】H5 / 小程序占比核对**：电商各渠道里 H5/小程序占比是多少？>10% 的话 MVP 就要适配，否则电商档案渗透率会有缺口
- **【新增·中】电商支付完成页 → 加微页之间是否插"档案前预热"**（"3 分钟问诊待你完成"）
- **【新增·高】全链路漏斗埋点**（购买→加微→启动→前测→档案首诊→计划页→首学→首通），MVP 必须，否则验证不了
- **【新增·高】档案有 vs 无的 A/B 对照设计**，MVP 必须
- **【新增·中】电商 vs 直投 分桶看指标**：直投目标感天然强一档，混在一起会污染数据
