## 一、背景与目标

### 1.1 背景

大促期间（6月6日），公司在 App 内进行直播抽奖活动，但部分用户无法实时在 App 内参加直播。需要一个站外 H5 页面，让已下单/续费的用户在微信场景下也能参与抽奖、感受活动氛围，同时引导未下单用户完成转化。

### 1.2 目标

| 目标 | 说明 |
|------|------|
| 双端联动 | H5 与直播间共用同一套后台配置、同一奖池、同一开奖结果，用户在任一端体验一致 |
| 氛围拉齐 | H5 展示直播间在线人数、同步标识等信息，让用户感知到与直播是同一场活动 |
| 转化抓手 | 未下单用户通过 CTA 引导下单，下单后自动获得全部剩余轮次的抽奖资格 |

### 1.3 入口 `✅ 已确认`

销售在**微信群/私聊**中群发 H5 页面链接，用户点击直接打开。

### 1.4 活动节奏 `✅ 已确认`

- 活动日期：6月6日
- 活动时段：12:00 - 22:00（一天一场直播）
- 抽奖轮次：由运营在 Gaffey 后台逐轮配置

## 二、用户角色与资格

### 2.1 用户身份判断 `✅ 已确认`

```
进入 H5 → 是否登录？
              ├─ 否 → 手机号 + 验证码登录
              └─ 是 → 是否为大促目标池用户？
                        ├─ 否 → Toast "您不符合抽奖资格"（不展示页面内容）
                        └─ 是 → 是否已下单/续费？
                                  ├─ 否 → 展示抽奖页面 + 吸底「下单获资格」CTA
                                  └─ 是 → 展示抽奖页面 + 吸底「已获资格」状态
```

### 2.2 资格定义 `✅ 已确认`

| 条件 | 说明 | 标注 |
|------|------|------|
| 大促池用户 | 用户在本次大促的目标人群池内（由后端标记） | |
| 已下单/续费 | 大促期间产生过有效订单，截止到用户当前的实时状态 | |
| 抽奖资格 | 已下单 = 有资格，自动参与所有「抽奖渠道 = 直播间和H5」的轮次 | `📌 关键决策` 自动参与，无需手动报名 |
| 中奖限制 | 整场活动每人**最多中奖 1 次**（该规则不外显给用户） | `📌 关键决策` 不外显 |

## 三、页面结构与交互

H5 抽奖页面为**单页面**，自上而下包含以下模块：

### 3.1 活动头部 `✅ 已确认`

| 元素 | 内容 | 说明 |
|------|------|------|
| 活动标题 | 海豚夏日福利嘉年华 | 固定文案 |
| 活动时间 | 6月6日 12:00 - 22:00 | 固定文案 |

### 3.2 状态栏 `✅ 已确认`

| 元素 | 数据来源 | 说明 | 标注 |
|------|----------|------|------|
| 当前轮次信息 | 后台配置 | 格式：「🔥 第X轮抽奖中」+「还有N轮 · 共N个奖品」 | |

| 在线人数 | 直播间接口 | 展示 **H5 + 直播间**去重在线人数 | `🔧 需开发` 需对接直播间在线人数接口 |

### 3.3 抽奖卡片区 `✅ 已确认`

**展示规则：**
- 仅展示「正在抽奖」+「未抽奖」的轮次
- 仅展示后台配置中「抽奖渠道」为「**直播间和H5**」的轮次 `📌 关键决策` 过滤条件
- 已开奖轮次自动移入下方「历史开奖记录」
- 卡片横向滚动排列，最后一张卡片为「已展示全部抽奖 · 共N轮」提示

**单张卡片内容：**

| 元素 | 数据来源 | 说明 | 标注 |
|------|----------|------|------|
| 轮次状态标签 | 后台 | 正在进行的轮次显示「🔥 正在进行」标签 | |
| 奖品示意图 | 后台（新增字段） | 支持动图/静态图，详见后台改动 §5.1 | `🔧 需开发` 后台新增字段 |
| 奖品名称 | 后台 | | |
| 轮次 + 中奖名额 | 后台 | 格式：「第X轮 · N个名额」，每轮 1-2 人 | |
| 开奖倒计时 | 后台 | 正在进行的轮次：「⏰ 距离开奖 MM:SS」（实时递减）| `⚠️ 边界case` 倒计时与服务端时间同步，避免客户端本地时间偏差 |
| 开奖时间 | 后台 | 未到轮次：显示具体开奖时间「⏱️ 开奖时间 HH:MM」| |

### 3.4 自动开奖 & 结果弹窗 `✅ 已确认`

倒计时归零后，**自动弹出**中奖/未中奖结果弹窗。 `📌 关键决策` 后台自动开奖，非人工触发

**中奖弹窗：**
| 元素 | 内容 |
|------|------|
| 图标 | 🎉 |
| 标题 | 恭喜您中奖了！ |
| 奖品图片 | 从后台配置读取 |
| 奖品名称 | 从后台配置读取 |
| 说明文字 | 「第X轮 · 奖品将在活动结束后发放」 |
| 按钮 | 「太棒了」→ 关闭弹窗 |

**未中奖弹窗：**
| 元素 | 内容 |
|------|------|
| 图标 | 😢 |
| 标题 | 很遗憾，您未中奖 |
| 说明文字 | 「继续参与后续轮次，好运就在前方！」 |
| 按钮 | 「继续等待好运」→ 关闭弹窗 |

**异步回看场景：** 用户不在页面时开奖的轮次，回来后仅**弹窗展示中奖**结果；未中奖不弹窗，结果直接展示在历史记录中。 `⚠️ 边界case` 前端需记录哪些轮次结果尚未展示，回来后仅对中奖轮次弹窗

### 3.5 历史开奖记录 `✅ 已确认`

| 元素 | 说明 | 标注 |
|------|------|------|

| 中奖名单 | 每条可点击「中奖名单 ›」→ 弹出底部卡片，展示中奖人手机号（脱敏：138\*\*\*\*1234） | |
| 数据口径 | 与直播间完全一致 | `📌 关键决策` 双端同一数据源 |

### 3.6 九重福利 `⏳ 待确认`

| 元素 | 说明 | 标注 |
|------|------|------|
| 展示形式 | 运营提供的一张图片，展示九重福利内容 | |
| 解锁规则 | 下单后解锁全部福利 | |
| 当前状态 | **内容占位中**，待业务方确认后补充 | `⏳ 待确认` 文悦与业务方对齐中 |

### 3.7 活动规则 `⏳ 待确认`

固定文案展示活动规则（以下为初稿，需运营确认最终文案）：
1. 下单/续费后自动获得全部共有轮次抽奖资格
2. 每轮自动参与，中奖名单实时公布
3. 每轮抽取一种奖品，与大促直播间同步开奖
4. 下单用户可同时获得九重专属福利
5. 本活动最终解释权归海豚所有

| 用户状态 | CTA 内容 | 点击行为 | 标注 |
|----------|----------|----------|------|

| 未下单（无资格） | 「🎁 立即下单，获得抽奖资格」<br>副文案：「下单即可参与剩余 N 轮抽奖 + 九重福利」 | 跳转下单页面 | `⚠️ 边界case` 下单成功后需实时回写资格，CTA 即时切换状态 |
| 活动已结束 | 「活动已结束，感谢参与」 | 置灰不可点击 | |

## 五、后台改动（Gaffey 系统）

### 5.1 奖品池增加图片配置 `🔧 需开发`

| 维度 | 说明 |
|------|------|
| 改动位置 | 奖品池配置表单，每个奖品新增「奖品图片」字段 |
| 字段类型 | 图片上传（支持 JPG/PNG/GIF） |
| 用途 | H5 和直播间卡片展示奖品示意图 |
| 是否必填 | 是 |

### 5.2 参与条件增加「仅下单」 `🔧 需开发`

| 维度 | 说明 |
|------|------|
| 改动位置 | 抽奖配置表单 →「参与条件」下拉 |
| 现有选项 | 仅评论 / 评论且下单 |
| 新增选项 | **仅下单** |
| 用途 | H5 场景下用户无法发评论，需要一个仅基于下单状态的参与条件 |

### 5.3 新增「抽奖渠道」字段 `🔧 需开发`

| 维度 | 说明 |
|------|------|
| 改动位置 | 抽奖配置表单，新增字段 |
| 字段类型 | 单选 |
| 选项 | **仅直播间**（默认）/ **直播间和H5** |
| 逻辑 | 选「仅直播间」→ 该轮次仅在直播间展示和开奖<br>选「直播间和H5」→ 该轮次同时在 H5 页面展示，H5 用户可参与 |
| 说明 | 不自动生成 H5 页面，H5 页面由前端独立开发，仅读取后台数据 |

> `📌 关键决策` 默认值为「仅直播间」，运营需主动选「直播间和H5」才会同步到 H5，避免存量配置受影响

### 5.4 售卖活动列表增加「H5链接」操作 `🔧 需开发`

| 维度 | 说明 |
|------|------|
| 改动位置 | 直播售卖管理 → 活动列表 → 操作列 |
| 现有操作 | 复制 |
| 新增操作 | **H5链接**（与「复制」并列） |
| 点击行为 | 拼接 `https://h5.xxx.com/lottery/{售卖活动id}`，复制到剪贴板，Toast「H5链接已复制」 |
| 置灰条件 | 该活动下没有任何「抽奖渠道 = 直播间和H5」的轮次时，按钮置灰，hover 提示「该活动暂无H5抽奖轮次」 |
| 用途 | 运营获取 H5 页面链接，发给销售在微信群/私聊中分发 |

> `📌 关键决策` 链接获取入口放在售卖活动列表页，运营配完轮次后直接复制，无需找研发要链接

> 后台改动 Demo 见 [admin-lottery-form.html](./admin-lottery-form.html)

## 六、数据接口需求

以下为 H5 前端所需的数据接口，具体字段和格式由前后端协商确定。

### 6.1 用户鉴权 `🔧 需开发`

| 接口 | 说明 | 标注 |
|------|------|------|
| 登录 | 手机号 + 验证码，返回 token | `⚠️ 边界case` 验证码发送频率限制、过期时间 |
| 用户身份校验 | 入参：token；返回：是否在大促池、是否已下单 | |

### 6.2 抽奖数据 `🔧 需开发`

| 接口 | 说明 | 标注 |
|------|------|------|
| 获取轮次列表 | 返回所有「抽奖渠道 = 直播间和H5」的轮次信息（轮次号、奖品名称、奖品图片、中奖人数、开奖时间、当前状态） | `📌 关键决策` 后端过滤渠道，前端不做二次过滤 |

| 获取活动状态 | 返回：活动状态（未开始/进行中/已结束）、距离开始的倒计时 | `⚠️ 边界case` 返回服务端时间戳，前端用于校准本地倒计时 |

| 接口 | 说明 | 标注 |
|------|------|------|

## 十、埋点方案

### 10.1 页面级埋点

| 事件名 | 触发时机 | 参数 | 说明 |
|--------|----------|------|------|

| `h5_lottery_leave` | 页面离开（visibilitychange） | `user_id`, `stay_duration`, `rounds_seen`, `rounds_revealed` | 停留时长、看了几轮、揭晓了几轮结果 |

### 10.2 用户身份流程

| 事件名 | 触发时机 | 参数 | 说明 |
|--------|----------|------|------|
| `h5_login_show` | 登录页展示 | | |
| `h5_login_sms_send` | 点击发送验证码 | `phone_masked` | 手机号脱敏 |
| `h5_login_success` | 登录成功 | `user_id` | |
| `h5_login_fail` | 登录失败 | `error_type` | 验证码错误/过期/频率限制 |
| `h5_pool_check_fail` | 非池用户 Toast 展示 | `user_id` | 统计非目标用户访问量 |

### 10.3 抽奖核心交互

| 事件名 | 触发时机 | 参数 | 说明 |
|--------|----------|------|------|

### 10.5 转化链路（核心）

| 事件名 | 触发时机 | 参数 | 说明 |
|--------|----------|------|------|

|--------|----------|------|------|
| `h5_activity_not_started` | 展示「活动未开始」蒙层 | `countdown_seconds` | 距离开始还有多久 |
| `h5_activity_ended` | 展示「活动已结束」状态 | `total_rounds`, `user_win_count` | |

### 10.7 埋点要求

| 维度 | 要求 |
|------|------|
| 上报方式 | 与现有 H5 埋点 SDK 一致（待前端确认） `⏳ 待确认` |
| 公共参数 | 所有事件携带：`user_id`, `timestamp`, `activity_id`, `platform`(h5), `channel`(wechat/browser) |
| 实时性 | 转化链路事件（`cta_click`, `order_success`）需实时上报；其他事件可批量上报 |
| 数据看板 | 活动期间需关注的核心指标见下方 |

### 10.8 核心数据看板指标

| 指标 | 口径 | 用途 |
|------|------|------|
| H5 UV / PV | `h5_lottery_pv` 去重 | 渠道触达效果 |
| 登录转化率 | `login_success` / `login_show` | 登录流程漏损 |
| 池外用户占比 | `pool_check_fail` / 总 UV | 链接分发精准度 |
| CTA 点击率 | `cta_click` / `cta_expose`(unqualified) | 下单引导效果 |
| 下单转化率 | `order_success` / `cta_click` | **核心指标**，H5 渠道转化能力 |
| 人均停留时长 | `stay_duration` 均值 | 活动氛围感知 |
| 异步回看率 | `trigger=async` 的弹窗 / 总弹窗 | 用户是否会主动回来看结果 |

## 十一、验收标准

### 11.1 核心流程

- [ ] 非大促池用户进入页面，展示 Toast 提示后无法查看内容
- [ ] 未登录用户进入页面，展示手机号验证码登录页
- [ ] 登录后正确识别用户下单状态，展示对应 CTA
- [ ] 未下单用户点击 CTA 可跳转下单页面
- [ ] 下单后资格自动回写，CTA 切换为「已获资格」状态

### 11.2 抽奖展示

- [ ] 正确展示所有「抽奖渠道 = 直播间和H5」的轮次卡片
- [ ] 不展示「仅直播间」渠道的轮次
- [ ] 不展示「仅评论」参与条件的轮次
- [ ] 正在进行的轮次有实时倒计时
- [ ] 卡片横滑正常，末尾展示「已展示全部抽奖」

### 11.3 开奖

- [ ] 倒计时归零后自动弹出中奖/未中奖弹窗
- [ ] 用户离开后再进入，仅中奖轮次弹窗展示，未中奖轮次直接进历史记录
- [ ] 整场活动同一用户最多中奖 1 次
- [ ] 中奖结果与直播间一致

### 11.4 历史记录

- [ ] 默认展示最近 3 条，可展开查看全部
- [ ] 每条可查看中奖名单（手机号脱敏）
- [ ] 数据与直播间口径一致

### 11.5 页面状态

- [ ] 活动未开始：蒙层 + 倒计时
- [ ] 活动已结束：CTA 置灰
- [ ] 无更多轮次：正确展示提示

### 11.6 后台配置

- [ ] 奖品池可上传图片（动图 + 静态图）
- [ ] 参与条件可选「仅下单」
- [ ] 抽奖渠道可选「仅直播间」/「直播间和H5」
- [ ] H5 页面正确读取后台配置数据

### 11.7 埋点

- [ ] 所有事件携带公共参数（user_id, timestamp, activity_id, platform, channel）
- [ ] `h5_lottery_pv` 正确上报用户身份状态
- [ ] `h5_cta_click` 和 `h5_order_success` 实时上报
- [ ] `h5_result_popup_show` 正确区分 realtime / async 触发方式
- [ ] 活动期间核心看板数据可查
