# 业务支持杂项汇总

> 状态：13 个独立小项目集合（已上线/方案完成）
> 时间：2025.06 - 2025.12
> 角色：产品需求承接 + 跨团队推动落地
> 用途：在简历/面试中作为「项目数量 × 业务覆盖广度」的支撑材料

---

## 一句话定位

> 同时承接 13+ 个业务支持类小项目（跨增长策略 / 转介绍 / 大促 / 销售工具 / 数据打点 / 合规等多个领域），体现「多线程项目管理 × 跨团队协作 × 业务覆盖广度」的综合产品能力。

---

## S · 背景（Situation）

**业务背景**：海豚 AI 学增长产品角色除了主线项目（AI 销售战略主线 / 大促增长支持等），还需要承接大量业务支持类小需求——这些需求**单个看不大，但合起来构成业务正常运转的基础设施**。

**核心特点**：
- **多线程**：同时在跑 5-10 个不同优先级的小项目
- **跨团队**：每个项目对接的团队都不同（运营 / 销售 / CC / 研发 / 数据 / 合规）
- **快进快出**：大部分项目从需求到上线在 1-3 周内完成
- **不可见但必要**：这些项目不会出现在主线汇报里，但它们决定了业务的流畅度

---

## T · 目标（Task）

整体目标：**保证业务侧需求按时按质交付**，不阻塞主线项目的推进。

每个子项目有独立的小目标，详见下方「项目清单」。

## A · 行动（Action） · 13 个子项目清单

### 增长策略类

#### 1. 转介绍关系建立逻辑优化（已上线 9.22）

- **背景**：转介绍是核心增长渠道之一，但关系建立逻辑（"谁邀请谁"的归因规则）有边界 case 处理不一致
- **行动**：梳理边界 case + 优化归因规则 + 推动技术上线
- **结果**：9.22 上线，转介绍归因数据准确性提升

#### 2. 转介绍 H5 页面新增前置弹窗

- **背景**：转介绍 H5 页面用户跳出率较高，缺少价值传达
- **行动**：设计前置弹窗承接落地流量，提升 H5 留存
- **结果**：方案完成，已上线

#### 3. 市场分销链路搭建（已上线 9.8）

- **背景**：市场分销渠道是新探索的增长方向，没有现成链路
- **行动**：从 0 设计分销链路（投放 → 分销页 → 转化跟踪），跨产品/技术/数据团队推动
- **结果**：9.8 上线，市场分销链路从 0 到 1 跑通

#### 4. 通用售卖页增加表单组件（已上线 9.4）

- **背景**：售卖页缺少标准化表单组件，业务方每次都要定制开发
- **行动**：抽象通用表单组件，支持多场景复用
- **结果**：9.4 上线，后续多个业务复用，节省研发资源

#### 5. MVP 课程售卖

- **背景**：MVP 阶段需要快速试水新课程的售卖模式
- **行动**：设计最小可行版本的售卖流程，快速上线验证
- **结果**：方案完成，根据数据决定是否扩大投入

### 大促 / 活动类

#### 6. 提高抽奖机会发放人数上限 + 回执（已上线 10.13）

- **背景**：抽奖活动机会发放人数上限不够，且发放后没有回执确认
- **行动**：调整人数上限规则 + 增加发放回执确认机制
- **结果**：10.13 上线，活动支持能力提升

- **背景**：大促期间需要为特定用户开放支付白名单（绕过常规限制）
- **行动**：和支付/合规/产品团队对齐流程，建立白名单申请通道
- **结果**：流程跑通，大促期间正常使用

#### 8. 8 年级家长会模块排序前置实验

- **背景**：家长会落地页有多个模块，排序对转化的影响未知
- **行动**：设计 AB 实验测试模块排序 → 8 年级排在前/后位置对比
- **结果**：方案完成，根据数据调整排序策略

### 数据 / 打点 / 工具类

## 🎤 面试常见追问 + 标准答案

### Q1：你同时跑这么多项目，怎么管理优先级？

**追问意图**：考察多线程能力
**标准答案**：
- 我用了「**两个维度 × 四个象限**」的简化框架：
  - 维度 1：业务紧急程度（卡上线 / 不卡上线）
  - 维度 2：自己投入度（深度推动 / 轻度承接）
- 四个象限：
  - **卡上线 + 深度推动** = 主线（如大促支付白名单 → 全力推）
  - **卡上线 + 轻度承接** = 标准化承接（如打点需求 → 给标准模板让研发自助）
  - **不卡上线 + 深度推动** = 战略储备（如 keyfrom 规范化 → 投入但有节奏）
  - **不卡上线 + 轻度承接** = 拒绝或延期（避免精力分散）
- 每周复盘一次：哪些项目滑到了"卡上线"象限，提前预警

### Q2：13 个项目里挑 1 个你最自豪的，为什么？

**追问意图**：考察从小项目中提取价值的能力
**标准答案**：
- 我会选 **"市场分销链路搭建"**——因为这是从 0 到 1 的设计
- 价值点：
  - **从无到有**：之前公司没有这个分销渠道，我从投放 → 分销页 → 转化跟踪整链路设计
  - **跨多个团队**：和产品、技术、数据、市场 4 个团队协作
  - **可复用**：设计的链路结构后续可以扩展到其他分销场景
- 它不是"最大"的项目，但是**最能体现"产品 0-1 设计能力"的样本**——这是我作为 PM 的核心能力之一

### Q3：这些小项目的"业务影响"怎么衡量？

**追问意图**：考察价值量化能力
**标准答案**：
- 我承认：单个看，**很多小项目的业务影响很难量化**——比如"短信合规报备"对转化没直接影响
- 但合起来看：
  - **无形价值**：保障了业务流畅运转，避免"大项目卡在小问题上"
  - **风控价值**：合规类项目避免了潜在的法律风险（不可见但价值巨大）
  - **复用价值**：通用表单组件、keyfrom 规范等沉淀为基础设施，长期省研发资源
- 更诚实的回答：**这些项目的核心价值是"基础设施级别的稳定性"**——没人感谢，但出问题时人人都会怪你
