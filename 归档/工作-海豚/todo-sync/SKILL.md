# Todo 同步归纳

接收用户口语化的 todo 状态汇报，解析后更新 `work/todos.md`，保持格式规范、序号连续、优先级有序。

## 输入

用户的输入通常是以下几种形式（可混合）：

1. **状态变更**："XX 需求已上线"、"XX 方案中"
2. **新增任务**："又有个 todo：大促需求，下周开始搞"
3. **批量汇报**：一次列出多条 todo 的当前状态
4. **聊天记录/截图**：让你从中提取 todo

用户不会用精确字段描述，需要你**匹配已有条目**或**判断为新增**。

## 处理规则

### 匹配与更新

1. **模糊匹配**：用户说的名称可能和 todos.md 中的标题不完全一致，按语义匹配
2. **状态映射**：
   - "已上线"、"已完成"、"搞定了" → 移到「已完成」区
   - "方案中"、"在写方案" → `🔥 方案中`
   - "进行中"、"在搞" → `🔥 进行中`
   - "下周开始"、"待启动" → `⏳ 待启动`
   - "等XX提供"、"待对齐" → `⏳` + 具体等待内容
3. **信息精简**：条目移到「已完成」时，精简背景描述，只保留核心信息和完成时间
4. **增量更新**：只改变用户提到的条目，未提及的保持不动

### 新增条目

- 判断为新增时，根据用户描述填写：标题、背景（如有）、TODO、状态
- 如果用户给了详情但没给标题，自己起一个简短的

### 排版规则

每次更新后必须重新排版：

1. **三个区域**：`紧急重要` → `重要不紧急` → `已完成`
2. **排序逻辑**（紧急重要区内）：
   - `🔥` 进行中/方案中 → 排在前面
   - `⏳` 待启动/待提供 → 排在后面
3. **序号连续**：从 1 开始，不跳号，每个条目用 `### N. 标题` 格式
4. **已完成区**：用删除线格式 `~~标题~~ — 完成时间/说明 ✅`，不编号

### 条目格式

```markdown
### N. 标题
- **背景**：（简要背景，可选）
- **需求**：（需求描述，可选）
- **TODO**：当前要做的事
- **状态**：🔥/⏳ + 状态描述
- **详情**：（关联文件路径，可选）
- **对接人**：（可选）
```

字段不是必填的，有什么写什么，不要补空字段。

### 格式兼容

`todos.md` 会被 `scripts/daily-work-reminder.sh` 解析弹窗提醒，格式需保持兼容：
- 区域标题用 `## 紧急重要` / `## 重要不紧急` / `## 已完成`
- 条目标题用 `### N. 标题`
- 状态行以 `- **状态**：` 开头

## 工作流

1. **读取** `work/todos.md` 当前内容
2. **解析**用户输入，逐条判断：匹配已有条目（更新） or 新增条目
3. **执行更新**：用 StrReplace 精准修改，或在大批量变更时用 Write 整体重写
4. **重新排版**：按排序逻辑调整顺序，重编序号
5. **输出摘要**：告诉用户做了哪些变更（状态变更/新增/移到已完成），不需要贴全文

## 边界

- 不主动删除条目（除非用户明确说"这个不要了"）
- 不自行判断优先级调整区域（紧急 vs 不紧急），除非用户明确说
- 不修改「重要不紧急」区域的非编号条目（如 Prompt 学习、能力建设的 checklist）
- 聊天记录提取 todo 时，如果信息不够明确，先输出理解让用户确认
